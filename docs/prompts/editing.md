# 프롬프트 다듬기 지침

Canon 의 프롬프트 글을 고치는 편집 AI(Claude Code, Codex, Gemini CLI 등)와 사람을 위한 지침이다.
RisuAI 프리셋 다듬기 지침(v1.4, 2026-09-15)의 원칙을 Canon 의 구조에 맞게 옮겼다.

- 대상: `canon/prompts.py` 의 시스템 프롬프트 · 요청 블록 · 규칙 줄, `PREAMBLE`, `llm.POLICY_NOTE` · `ADULT_NOTE`, 단계별 요청 문구.
- 이 문서는 편집하는 쪽의 규칙이다. 런타임 프롬프트에 이 문서의 글을 넣지 않는다.
- 새 기능의 프롬프트를 처음부터 만드는 일은 이 문서의 범위 밖이다. 그때도 0절은 지킨다.

## 0. 절대 원칙: 편집 AI의 가치관과 제공자 정책을 끼워 넣지 않는다

뜻을 지키는 편집은 원문을 편집 AI가 보기에 더 안전하고, 건강하고, 현실적이고, 윤리적이고, 균형 잡히고, 서사적으로 나은 쪽으로 고쳐도 된다는 허락이 아니다.
이 원칙은 이 저장소에서 일하는 모든 편집 AI에 적용된다. 이 문서를 쓴 Claude 도 포함한다.

### 0.1 프롬프트의 모든 문장에는 출처가 있어야 한다

결과 프롬프트의 문장과 조각은 아래 셋 가운데 하나에서 나와야 한다.

1. 작가가 정한 것: 작가가 쓴 설정 · 문체 · 머리말 · 규칙, 작가가 채팅에서 정한 결정, 그 결정을 적은 문서(AGENTS.md 의 설계 원칙, DESIGN.md, 커밋 메시지).
2. 1의 뜻을 그대로 둔 구조화 · 다듬기 · 줄이기 · 바꿔 쓰기.
3. 작가가 명시적으로 요청한 동작이나 내용 변경.

- '도움이 될 것 같다'는 출처가 아니다.
- 실측 결과(DESIGN.md · `reports/` 의 비교 실험)는 작가가 그 결과로 규칙을 바꾸기로 정했을 때 1이 된다.

### 0.2 끼워 넣지 않는 것

작가가 정하지 않았는데 아래를 작가의 요구인 것처럼 넣지 않는다.

- 편집 AI의 학습 성향, 제공자 정책, 일반적인 조언, 도덕 판단, 임상 해석, 서사 취향
- 작가가 쓰지 않은 동의 · 관계의 건강함 · 회복 · 트라우마 치유 · 도덕적 성장 · 인과응보 규칙
- 수위 지시. #272(커밋 `ab410a33`)에 따라 수위는 화면과 프로그램 규칙에서만 다룬다
- 인물을 더 착하게, 더 합리적으로 바꾸는 손질
- 세계관의 절대 규칙을 '대개 그렇다'는 확률로 바꾸는 손질

극단적임, 비현실적임, 건강하지 않음, 불쾌함, 불균형, 의도한 모순은 약하게 만들거나 고칠 이유가 아니다.
문제는 출처 없는 삽입이다. 어떤 주제나 낱말이 들어 있다는 것 자체가 아니다.

### 0.3 작가가 쓴 강도와 낱말을 지킨다

- 고정 표현, 말투, 세기, 의도한 모호함, 풀리지 않은 상태를 지킨다.
- 작가가 쓴 대안 설정을 원작 설정이나 바깥 자료로 몰래 바꾸지 않는다.
- 작가가 넣은 금지 · 제한도 같은 세기와 범위로 지킨다. 0절은 작가의 규칙을 지우라는 뜻이 아니다.

### 0.4 코드에 있는 작가 결정도 출처다

아래는 작가가 정해 코드에 둔 규칙이다. 0절을 이유로 지우거나 약하게 만들지 않는다.

- 성인 작품의 인물 나이 19세 이상(`birth.py`, `cast.is_minor_age`)
- 전연령 작품의 삽화 등급 낮추기(`illust.py`)
- 모든 요청 끝의 `POLICY_NOTE` 와 `ADULT_NOTE`(`llm.with_note`). `ADULT_NOTE` 가 전연령 작품에 붙지 않는 것은 작가 결정이 아니라 편집 AI(Claude)가 따르지 않은 부분이다(0.5)
- 성인 · 전연령 작품이 같은 프롬프트 글을 받는다는 규칙(`test_no_rating_instruction_in_prompts`)

### 0.5 편집 AI가 할 수 없는 일은 드러내서 말한다

편집 AI마다 자기 운영 기준이 있다. 이 문서는 그 기준을 바꾸지 못한다.

- 편집 AI가 자기 기준 때문에 요청을 그대로 따를 수 없으면, 프롬프트를 몰래 약하게 고치지 않는다.
- 대신 무엇을 하지 않았는지, 왜인지를 작가에게 그대로 말한다. 거절은 숨은 수정이 아니라 드러난 결정이다.
- 하지 않은 부분과 별개인 나머지 일은 그대로 한다.
- 편집 AI가 넣고 싶은 규칙이 있으면 별도 제안으로 밝힌다. 작가가 받아들이기 전에는 프롬프트에 넣지 않는다.

### 0.6 바꾼 것마다 근거를 남긴다

- 더하거나 바꾼 문장마다 출처(0.1)를 댄다.
- 지우거나 합친 뜻마다 남은 자리나 작가의 지우기 요청을 댄다.
- 작가가 승인한 재설계도 재설계다. 승인이 바뀐 동작을 '같은 뜻'으로 만들지 않는다.

## 1. 일의 종류

요청에서 종류를 고른다. 작가에게 양식을 채우게 하지 않는다.

| 종류 | 하는 일 | 경계 |
|---|---|---|
| 다듬기 | 지금 프롬프트를 모델이 더 잘 따르게 고친다. 길어져도 된다 | 뜻을 지킨다. 재 보지 않은 동작은 '재지 않음'으로 남긴다 |
| 줄이기 | 같은 뜻을 더 적은 글자 · 토큰으로 쓴다 | 다듬기를 핑계로 요구를 늘리거나 동작을 몰래 고치지 않는다 |
| 고치기 · 재설계 | 작가가 요청한 동작이나 구조를 바꾼다 | 바뀌는 동작, 영향받는 경로, 근거를 '같은 뜻' 주장과 따로 적는다 |

- 고치는 범위는 가장 작게 한다. 이미 잘 듣는 글과 구조는 둔다.
- 결함 하나를 찾았다고 상관없는 동작까지 바꾸지 않는다.

## 2. 고치기 전에 확인할 것

- 원문: 고칠 함수 · 상수의 지금 글. `brief` 와 프롬프트 보기 API(`/episodes/{n}/prompt`)로 조립된 글을 본다.
- 경로: 그 글이 어느 단계(`settings.STAGES`) · 백엔드 · 작품 종류(단편 · 장편, 성인 · 전연령)에 가는지.
- 지킬 것: 작가가 정한 문장, 실측으로 정한 숫자, 시험이 지키는 글(프롬프트 해시 스냅샷).
- 증거: 실패한 출력이 있으면 그것을 보고, 없으면 글의 모호함을 가설로만 적는다.

## 3. 뜻 지도

고치기 전에 원문 문장을 뜻 단위로 나눈다.

| 종류 | 뜻 | 다루는 법 |
|---|---|---|
| 경계 | 해야 할 일, 하지 말 일, 조건, 예외, 사실, 숫자 한도, 출력 형식 | 그대로 둔다 |
| 의도 | 담담하게, 긴장감 있게 같은 방향 | 방향 · 세기 · 범위를 지킨다 |
| 보조 | 다른 곳에 같은 뜻이 있는 설명 · 예시 | 그 뜻이 남은 자리를 찾은 뒤에만 줄인다 |
| 불확실 | 뜻이나 쓰임을 알 수 없음 | 글을 그대로 둔다 |

- '할 수 있다'와 '해야 한다', '드물게'와 '절대', 시도와 결과, 믿음과 사실을 구별한다.
- 말로 된 정도를 근거 없이 숫자로 바꾸지 않는다. Canon 의 숫자 규칙(예: `ending_line` 의 몫)은 실측이 있을 때만 쓴다.
- 이유 문장과 예시도 독립된 뜻(예외, 실패를 알아보는 기준)을 가질 수 있다. 지우기 전에 확인한다.

## 4. Canon 프롬프트 구조에 맞춰 고친다

| 층 | 볼 것 | 글만 바꿔서는 안 되는 것 |
|---|---|---|
| 프롬프트 함수 | `prompts.py` 의 시스템 프롬프트, 블록, 규칙 줄 | 그 글이 모든 단계에 간다는 보장 |
| 조립 순서 | `static_context` 가 앞, 화마다 바뀌는 블록이 뒤, 요청은 맨 뒤 | 캐시(`claude.cache_blocks`, Gemini 암묵 캐시, `claude.shared_cut`) |
| 보내기 직전 | `llm.with_note` 의 `POLICY_NOTE` · `ADULT_NOTE` | 작업지시서(`brief`)에는 붙지 않음 |
| 예산 | `context.BUDGET`, 장편 줄거리 접기 | 화수에 따라 끝없이 커지지 않기 |
| 응답 형식 | `.json(…)` 스키마, `mock.py` | Gemini 가 dict 칸을 받지 못함(`test_schema_nodict.py`) |

- API 경로와 작업지시서 경로는 같은 함수를 쓴다. 한 곳만 고치고 `brief` 출력도 본다.
- 조각을 고치면 `prompts.PIECES` 의 그 줄(주제 꼬리표 · 들어가는 조건)도 함께 본다. 프롬프트 관리 페이지(`#/prompts`)가 그 표로 조각을 찾는다.
- 새 `SYSTEM_*` 상수나 `*_prompt` 함수를 더하면 `prompts.KINDS` 나 `PIECES` 에 적는다(`tests/test_prompt_registry.py`).
- 한 규칙을 여러 프롬프트가 함께 쓰면(예: `MINIMAL_FIX_RULES`, `write_plot`) 모든 사용처를 같이 본다.
- 단편(`form = "short"`) 경로는 장편 작업에서 바꾸지 않는다.

## 5. 지시를 쓰는 법

- 원문이 시키는 동작을 옮긴다. 낱말만 바꾸지 않는다.
- 원문에 대신 할 일이 있으면 그것을 먼저 쓰고, 경계와 예외는 그대로 남긴다.
- 금지를 긍정문으로 바꿀 때 뜻이 바뀌지 않게 한다. '잔인하게 굴지 않는다'를 '다정하고 장난스럽다'로 바꾸면 성격을 더한 것이다.
- 강한 말('절대')보다 이유를 붙인 담담한 지시를 쓴다. 이유는 원문이나 작가 결정에서 가져온다(`prompts.py` 의 문체 규칙 주석).
- 예시는 구별이 필요할 때만 가장 적게 쓴다. 예시가 새 사건 · 소품 · 비밀의 출처가 되지 않게 한다.

## 6. 확인

### 6.1 두 방향으로 본다

1. 원문의 모든 뜻이 결과 글에 남았는가.
2. 결과 글의 모든 문장에 출처(0.1)가 있는가.

새로 생긴 금지도 사라진 금지만큼 꼼꼼히 본다.

### 6.2 층마다 따로 적는다

| 층 | 통과 기준 |
|---|---|
| 글 | 6.1 두 방향 확인, 지운 문장의 뜻이 남은 자리 |
| 시험 | 전체 시험 통과. 프롬프트 해시 스냅샷이 바뀌면 바뀐 항목이 의도한 것뿐인지 확인한 뒤 `CANON_UPDATE_SNAPSHOT=1` 로 다시 만든다 |
| 조립 | `brief` · 프롬프트 보기로 실제 조립된 글 |
| 모델 출력 | 같은 화를 고치기 전 · 뒤로 2~3판씩 쓰고 견준다. 블라인드 판정, 검수 지적 수, 문체 지표(`metrics`) |

- 각 층을 통과 · 실패 · 재지 않음으로 적는다.
- 글만 본 것을 모델 출력 통과로 쓰지 않는다.
- 실측은 DESIGN.md 의 기존 실험처럼 모델 · 판 수 · 판정 방법을 남긴다.

## 7. 보고

- 바꾼 것, 고른 이유, 확인한 층과 결과, 재지 않은 것.
- 0.5 에 따라 하지 않은 일이 있으면 무엇을, 왜 하지 않았는지.
- 런타임 프롬프트에는 편집 이유, 출처 표시, 시험 문구를 넣지 않는다.
