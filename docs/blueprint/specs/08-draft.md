# 08. AI 로 설계도 짜기

상태: 끝 ([#483](https://github.com/c10dev/canon/pull/483)) · 계획: [plan.md](../plan.md) 의 8번 · 먼저: 5번

## 목표

플롯이 없는 새 작품에서도 AI 가 설계도를 제안한다.
재료는 작품 설정 · 로그라인, 두 인물, 관계(지금 사이 · 가 닿을 곳), 부 구성, 이미 적은 설계도 줄, 작가 메모다.
제안은 거꾸로 뽑기와 같은 카드로 오고, 작가가 고른 줄만 더한다.

## 정할 것

1. 이 일감을 할까 — 정함(2026-11-10 사용자 '진행'): 'AI로 설계도 짜기'를 한다. 부 구성이 설계도를 읽게 하기 · 대화로 다듬기는 따로 둔다.
2. 범위 — 정함: 장편은 부 하나(부가 없으면 작품 전체), 단편은 작품 전체. 615화를 한 번에 받으면 칸이 거칠고 출력이 길어진다.

## 바꿀 곳

| `canon/static/blueprint.js` | 쌍 쪽 'AI로 설계도 받기' 카드(짜기 메모 · 부 고르기 · 'AI로 짜기', 플롯이 있으면 뽑기 줄), 제안 카드 제목 'AI가 짠 설계도', 개요의 '여정 짜기' 버튼 |
| `canon/static/app.js` | `PENDING_KINDS` · `pendingShown` · `applyJobResult` 에 `blueprint_draft` |

## 데이터 · 스키마

- 바꾸지 않는다. 응답 형식은 `BlueprintProposal` 그대로, 근거 칸에는 '그 자리에 둔 까닭'이 온다.

## 규칙

- 정리와 더하기는 거꾸로 뽑기와 같다(`blueprint.clean_proposal` · `apply_picks`).
- 프롬프트 요구: 작품 설정 · 로그라인 · 부 구성 · 가 닿을 곳 · 작가 요청에 있는 방향만 따르고 사건을 지어내지 않는다. 관계 단계는 한 화에 한 칸, 사다리 칸은 처음 닿는 화가 줄지 않게, 범위 안에서 부 목표에 맞는 자리. 수위 지시는 넣지 않는다(`docs/prompts/editing.md` 0.2).
- 출력 한도 16,384토큰(생각 토큰 포함). 넘으면 형식 고치기 재시도로 넘어간다.
- 대화 에이전트 · 자동 집필은 이 작업을 부르지 않는다.

## 화면 · 명령줄 · 프롬프트

- 쌍 쪽 맨 아래 'AI로 설계도 받기': 메모 칸, 장편은 부 고르기, 'AI로 짜기'. 플롯이 있으면 아래에 '지금 플롯에서 뽑기' 줄.
- 제안 카드 제목은 짜기면 'AI가 짠 설계도', 뽑기면 'AI가 뽑은 설계도'.
- 개요의 관계 목록 줄마다 '여정 짜기' 버튼(개요에서 쌍을 눌러야 한다는 것이 보이지 않던 문제).
- 명령줄은 바꾸지 않는다.

## 실호출 확인 (2026-11-10)

- 지하철 작품 사본(임시 `CANON_HOME`)의 2부(80~203화), 조아영 ↔ 김지훈, 작가 메모 '2부에서 공범으로, 접촉은 한 아크에 한 칸쯤'. gemini-3.8-flash, 추론 강도 low.
- 한도 없이 보낸 첫 호출: 첫 시도가 65,521토큰까지 되풀이해 형식 불일치로 실패했고(285초, 약 $0.25), 재시도가 10초 만에 받았다. 재시도 응답은 동작 id · 근거가 비었다.
- 거꾸로 뽑기 실측(05)에서도 같은 폭주가 있었다. 그래서 두 작업에 출력 한도를 걸었다.
- 한도를 걸고 다시 보낸 호출: 첫 시도에 성공(87초, 출력 7,549토큰, 약 $0.03). 사다리 9칸이 80 · 86 · 96 · 108 · 124 · 140 · 158 · 174 · 198화로 고르게 놓였고, 칸마다 부위 · 동작 id 와 까닭이 왔다. 이정표에는 까닭이 붙지 않았다.
- 비용 합계: 호출 3번(실패 1), 가격표 어림 약 $0.30.
- 남은 일: 이미 적은 칸을 이어받는 줄(80화 '이미 적은 4번째 칸을 계승')이 한 번 나왔다. 작가가 제안 카드에서 빼면 된다.

## 확인하지 못할 것

- 제안의 질은 작가가 판단한다.
