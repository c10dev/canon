# 06. 스토리보드 · 쓰기 · 검수에 설계도 잇기 (6a)

상태: 진행 (claude/blueprint-board) · 계획: [plan.md](../plan.md) 의 6a · 먼저: 4번

## 목표

화 하나를 만드는 요청이 설계도를 본다.
스토리보드는 이번 화의 상한과 처음 닿는 칸을 받는다. 쓰기는 처음 닿는 칸이 있는 화에만 한 줄을 받는다. 검수는 다음 칸을 앞당겼는지 짚는다.
실제로 닿은 칸의 기록은 6b 다.

## 정할 것

1. 6을 나눌까 — 정함(2026-11-10 사용자): 6a(이 명세)를 먼저, 6b(상태 변경안의 실제 닿은 칸)를 따로 한다.
2. 6b 에서 자동 집필 · `-y` 는 — 정함(2026-11-10 사용자): 반영하지 않고 남겨 둔다. 인물 설정 바꾸기(`charlog.hold`)와 같다.

## 바꿀 곳

| 파일 | 바꿀 것 |

| `canon/prompts.py` | `blueprint_board_rule`(스토리보드 요청 맨 끝), `blueprint_write_line`(쓰기 지시문, 중심 장면 줄 뒤), `blueprint_check_rule`(검수 요구사항, 관계 단계 확인 뒤) |
| `canon/prompts.py` 의 레지스트리 | 조각 `blueprint_board` · `blueprint_write` · `blueprint_check`, 견본 글, 스토리보드 · 쓰기 · 검수 갈래의 조각 목록 |

- LLM 호출 경로는 늘지 않는다.

## 데이터 · 스키마

- 바꾸지 않는다.

## 규칙

- 세 줄 모두 n 화 플롯 인물(`EpisodePlot.characters`)에 두 인물이 함께 있는 사다리 · 이정표만 본다.
- 스토리보드: 이 화까지 닿을 수 있는 칸(`planned_rung(n)`, 이 화가 그 칸의 범위 안이면 '처음 닿는 범위인 칸'으로만 적음), 이 화가 처음 닿는 범위인 칸, 다음 칸(넣지 않음), 이 화가 든 관계 이정표. 끝에 '위 칸을 넘는 접촉을 넣지 않고, 플롯이 더 요구하면 플롯을 따르고 warnings 에 적는다' 한 줄.
- 쓰기: 이 화가 어떤 칸의 처음 닿는 범위일 때만 한 줄. 상한 · 다음 칸은 넣지 않는다(README 2026-11-10, 앞당김 방지).
- 검수: 다음 칸이 있을 때 '이 화까지 닿기로 한 칸'과 '다음 칸'을 적고, 본문이 다음 칸의 접촉을 쓰면 짚게 한다. 지적 type 은 플롯이다.
- 줄이 없으면 빈 글이다. 설계도가 없는 작품의 요청은 바뀌지 않는다(`tests/test_prompt_registry.py` 의 요청 스냅샷).
- 단편과 장편이 같다.
- 문구는 수위 지시가 아니라 이야기 사실(이 쌍이 어디까지 왔나)이다(`docs/prompts/editing.md` 0.2).

## 화면 · 명령줄 · 프롬프트

- 자리: 셋 다 요청 끝쪽이라 쓰기 가족 앞부분 캐시(`write_head`)를 깨지 않는다.
- 작업지시서(`brief`)의 스토리보드 · 본문 · 검수 갈래도 같은 함수를 써서 같은 줄이 들어간다.
- 화면 · 명령줄은 바꾸지 않는다.
