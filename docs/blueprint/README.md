# 설계도 작업 문서

Canon 의 작품 설계를 위에서 아래로(탑다운) 내리는 일의 설계 자산이다.
지금 Canon 은 아래에서 위로 쌓는다. 부 · 아크 목표는 줄글이고, 실제 진도는 화별 플롯이 정하고, 관계는 상태 변경안의 사건으로 뒤에 계산한다.
설계도는 그 위에 작가가 먼저 정하는 계획 층을 하나 둔다: 인물 사이 관계가 몇 화쯤 어디에 닿는지(관계 이정표), 두 인물의 신체 접촉이 몇 화쯤 어디까지 가는지(접촉 사다리), 나중에 인물의 능력을 몇 화쯤 얻는지(능력 일정).
부 · 아크 · 플롯 기획은 그 계획을 재료로 받고, 검수와 플롯 점검은 계획과 실제를 견준다.
기능이 들어가면 동작 설명은 [DESIGN.md](../../DESIGN.md) 에 쓰고 이 폴더를 가리킨다. 이 폴더는 일을 나누고 이어 가는 데 쓴다.

| README.md (이 문서) | 목적, 정한 규칙, 원칙과의 경계, 용어, 넣지 않는 것 | 이 폴더의 일을 시작하기 전 |
| [plan.md](plan.md) | 일감 차례, 먼저 끝날 것, 미룬 것 | 다음 일을 고를 때 |
| [specs/](specs/) | 일감마다 작업 명세서. 틀은 [docs/context/specs/TEMPLATE.md](../context/specs/TEMPLATE.md) | 일감을 시작할 때 |

## 정한 규칙

2026-11-10 에 사용자와 정한 것이다. 바꾸려면 사용자와 다시 정한다.
처음 추천안을 '설계' 세션이 평가했고, 사용자가 고친 안으로 진행하기로 했다.

| 날짜 | 규칙 |
|---|---|
| 2026-11-10 | 설계도는 작품 하나에 하나(`Project.blueprint`)다. 장편과 단편이 같은 칸을 쓴다. |
| 2026-11-10 | 첫 판의 축은 둘이다: 관계 이정표, 접촉 사다리. 능력 일정은 두 번째 묶음으로 미룬다. |
| 2026-11-10 | 관계 이정표는 방향마다 둔다(`source` → `target`). 관계 단계(`Tie.stage`)가 방향마다 있고 두 방향이 다를 수 있어서다. |
| 2026-11-10 | 이정표 한 줄은 [화 범위, 관계 단계(비워도 됨), 작가 라벨, 계기]다. 관계 단계는 `dynamics` 의 일곱 말만 받는다. 연인 같은 진도는 라벨에 쓴다. |
| 2026-11-10 | 설계도의 화 번호는 점이 아니라 범위(`from_ep` ~ `to_ep`)다. 장편에서 화 끼워 넣기와 아크 길이 변화가 점을 쉽게 깨서다. |
| 2026-11-10 | 이정표는 계획값이다. 관계 수치(`Tie`)를 이정표에 맞춰 고치지 않는다. 계획과 실제의 차이는 경고로만 보인다. |
| 2026-11-10 | 접촉 사다리는 두 인물 쌍마다 하나다. 칸의 차례가 곧 단계의 차례다. |
| 2026-11-10 | 사다리 칸의 부위 · 동작은 장면 연출의 id(`stage.PARTS` · `stage.ACTS`)를 쓴다. 겹(옷 위 · 옷 안 · 맨살)은 새 칸이다. 장소는 인과율 '장소' 요소 id 다. |
| 2026-11-10 | 사다리 칸은 수위 지시가 아니라 이야기 사실(이 쌍이 어디까지 왔나)로 적는다. 프롬프트에 넣을 때도 그렇게 적는다. |
| 2026-11-10 | 계획에 어긋나면 경고만 한다. 막지 않는다(완급 계획 · 관계 속도 점검과 같은 방식). |
| 2026-11-10 | 쓰기 요청에는 상한 줄을 넣지 않는다. 상한과 '이번 화에 처음 닿는 칸'은 스토리보드가 받는다. 쓰기는 '처음 닿는 칸'이 있는 화에만 그 한 줄을 받는다. |
| 2026-11-10 | 실제로 닿은 사다리 칸은 상태 변경안이 칸 id 목록에서 골라 제안하고 작가가 승인한다. 지금 칸은 승인한 기록에서 계산한다. |
| 2026-11-10 | 일감 6 은 6a(스토리보드 · 쓰기 · 검수 프롬프트 줄)와 6b(실제 접촉 기록)로 나눠 6a 를 먼저 한다. |
| 2026-11-10 | 실제 접촉 기록은 자동 집필 · `-y` 가 반영하지 않고 남겨 둔다(인물 설정 바꾸기 `charlog.hold` 와 같음). |
| 2026-11-10 | 플롯이 없어도 AI 가 설계도를 짠다(설정 · 부 구성 · 작가 메모, 장편은 부 하나씩). 제안은 거꾸로 뽑기와 같은 카드로 오고 고른 줄만 더한다. 부 구성이 설계도를 읽게 하기 · 대화로 다듬기는 따로 둔다. |
| 2026-11-10 | 화면은 새 단계를 만들지 않는다. 편집은 사이드바 도구 '설계도' 쪽(스킬 도감과 같은 틀)이고, 기획서 관계 카드에는 '여정' 줄과 링크만 둔다(일감 3 에서 사용자가 고름). 굵은 판은 `series` 뒤에, 화 범위는 아크 기획 때 내린다. |
| 2026-11-10 | 이미 플롯이 있는 작품(지하철 작품 1~119화)은 AI 가 지금 플롯에서 설계도를 아크 단위로 거꾸로 뽑고 작가가 고쳐 확정한다. 맞지 않는 확정 플롯은 표시만 하고 고치지 않는다. |
| 2026-11-10 | 인물 신체 프로필은 평소 프롬프트에 넣지 않고, 이야기가 몸을 쓰는 화에만 골라 넣는다(사용자 결정). 설계도에 적은 신체 특징이 앞 화 본문과 어긋나지 않게 하려는 것이다([specs/09-body.md](specs/09-body.md)). |
| 2026-11-10 | 넣는 조건은 둘이다: 그 화 플롯 인물끼리 그 화까지 닿기로 한 사다리 칸 가운데 옷 안 · 맨살 겹이 있음(한 번 닿으면 그 뒤 화도), 신체 특징 낱말이 그 화 플롯 · 연출 지시에 그대로 나옴. 넣는 칸은 체형 · 특징이고, 키 · 몸무게 · 쓰리사이즈는 넣지 않는다. |
| 2026-11-10 | 신체 특징은 스토리보드 · 쓰기 · 검수 요청 끝에 들어간다. 미성년 인물(`cast.is_minor_age`)은 넣지 않는다. |
| 2026-11-10 | 능력 일정(두 번째 묶음)을 만든다. 한 줄은 [인물, 화 범위, 능력, 등급(비워도 됨), 얻는 조건]이고 인물이 단위다([specs/10-ability.md](specs/10-ability.md)). |
| 2026-11-10 | 능력은 스킬 도감 항목의 이름으로 가리킨다. 도감에 없는 이름은 저장을 막지 않고 경고한다. |
| 2026-11-10 | 능력의 실제 쪽 값은 저장하지 않는다. 얻은 화는 상태창 기록(`Project.stat_log`)에서 계산한다. |
| 2026-11-10 | 능력 일정도 쓰기 요청에는 이 화가 얻는 범위인 줄만 넣는다. 다음 줄은 스토리보드 · 검수가 받는다. |
| 2026-11-10 | 능력 일정의 쓰기 줄은 그 화 플롯 · 연출 지시에 능력 이름이 나올 때만 넣는다(검토 뒤 사용자 요청). 범위는 스토리보드가 받는다. |
| 2026-11-10 | 상태창이 없는 인물의 능력 일정 줄은 범위 끝 화까지 반영하면 얻은 것으로 보고 경고 · 프롬프트에서 뺀다(검토 뒤 사용자 요청). |
| 2026-11-11 | 능력 일정 화면은 설계도 도구 안의 쪽 하나다(인물마다 나누지 않음). 상태 변경안 요청에는 얻을 때가 된 능력의 이름 줄을 넣는다. 같은 날 '거꾸로 뽑기 · AI 로 짜기와는 잇지 않는다'도 정했으나 아래 줄에서 다시 정했다. |
| 2026-11-11 | 능력 일정도 AI 로 짜고 지금 플롯에서 거꾸로 뽑는다(사용자가 다시 정함, [specs/12-ability-ai.md](specs/12-ability-ai.md)). 인물 하나씩 받고, 제안 카드에서 고른 줄만 더한다. 계획만 더하고 상태창 기록은 건드리지 않는다. |
| 2026-11-11 | 능력 일정 제안은 도감에 없는 능력의 스킬 도감 초안도 함께 낸다. 작가가 고른 초안만 도감에 만든다. 능력 일정 줄에서 도감 항목을 바로 만들 수도 있다(사용자 결정, [specs/13-ability-codex.md](specs/13-ability-codex.md)). |
| 2026-11-11 | 접촉 사다리의 쓰기 줄도 그 화가 처음 닿는 범위이고 그 칸이 그 화 플롯 · 연출 지시에 나올 때만 넣는다(작가 결정). 범위 안 모든 화에 넣지 않는다. 범위는 스토리보드와 검수가 받는다. |
| 2026-11-11 | '칸이 나왔다'는 칸 이름이 그대로 나오거나, 칸 이름의 낱말(두 글자 이상, 인물 이름 뺌) 가운데 절반 넘게 나오는 것이다. 부위 · 동작 이름은 보지 않는다([specs/06-episode.md](specs/06-episode.md) 의 실측). |
| 2026-11-10 | 미성년 인물 판정은 이 일에 넣지 않는다. 사용자가 다른 과정과 함께 뒤에 하기로 했다([plan.md](plan.md) 의 미룬 것). |

## 원칙과의 경계

- 관계 수치는 AI 가 적지 않는다: 설계도는 계획이고, `Tie` 는 지금처럼 사건에서 계산한다.
- 확정된 것은 덮어쓰지 않는다: 설계도를 고쳐도 확정 플롯 · 본문은 그대로다. 어긋남은 경고로만 보인다.
- 사용자가 입력한 설정은 AI 제안이 덮지 않는다: 설계도는 작가 입력이다. 저장할 때 모르는 id 를 말없이 지우지 않고 저장을 거절한다.
- 컨텍스트는 일정한 크기로: 기획 프롬프트에는 지금 범위와 다음 이정표만 접어서 넣는다. 화수에 따라 커지지 않는다.
- 바뀌지 않는 블록이 앞: 화마다 바뀌는 설계도 줄은 `heat_step_line` 과 같은 뒤쪽 자리에 둔다.
- LLM 이 채우는 스키마에는 dict 를 쓰지 않는다: 쌍은 `list` 의 항목으로 둔다.

## 용어

| 말 | 뜻 | 코드 |
|---|---|---|
| 설계도 | 작품의 계획 층 | `Project.blueprint`, `Blueprint` |
| 관계 이정표 | 한 방향 관계가 어느 화 범위에 어디에 닿는지 | `Milestone` |
| 접촉 사다리 | 두 인물 쌍의 신체 접촉 단계 목록 | `ContactLadder` |
| 사다리 칸 | 사다리의 한 단계와 그 칸에 처음 닿는 화 범위 | `ContactRung` |
| 겹 | 닿는 곳이 옷 위 · 옷 안 · 맨살 가운데 어디인지 | `ContactRung.layer` |
| 계획 칸 | n 화에 계획상 닿아 있는 가장 높은 칸 | `blueprint.planned_rung` |
| 능력 일정 | 인물이 어느 능력을 어느 화 범위에 어느 등급까지 얻는지 | `AbilityPlan`, `Blueprint.ability_plans` |
| 얻은 화 | 상태창 기록에서 그 능력 조각이 계획 등급에 처음 닿은 화 | `blueprint.got_ep` |
| 몸이 드러나는 화 | 그 화 플롯 인물끼리 그 화까지 닿기로 한 칸에 옷 안 · 맨살 겹이 있는 화 | `blueprint.exposed` |

## 넣지 않는 것

- 새 사이드바 단계 '설계'. 사이드바 도구 '설계도'로 둔다(2026-11-10).
- 관계 축과 접촉 축을 서로 묶는 경고. 관계가 적대인 채 접촉이 깊어지는 작품이 있다(지하철 작품).
- 이정표에 맞춰 관계 수치를 고치는 기능.
