### `canon/claude.py`

- Claude 백엔드
- `ClaudeAPILLM` 은 Anthropic 키가 없으면 `MissingKey` 를 낸다(웹은 설정 안내 code `no_key`)
- 구독 로그인(`claude`, 설치된 Claude Code 를 `claude -p` 로 부름, 로그인 상태 `status`)과 API 키(`claude-api`, Anthropic SDK)
- Canon 은 Claude 계정 로그인을 직접 받거나 토큰을 저장하지 않는다(Anthropic 정책)
- Canon 전용 로그인: `settings.claude_config_dir`(설정 `claude_separate` 면 설정 파일 옆 `claude-code` 폴더, `CANON_CLAUDE_CONFIG_DIR` 가 우선)를 `child_env` 가 `CLAUDE_CONFIG_DIR` 로 넘긴다
- `start_login` 은 그 폴더로 `claude auth login --claudeai` 를 띄우기만 한다(입출력을 잇지 않음, 10분 뒤 끝냄). 웹 `POST /api/claude/login` 은 Canon 을 실행하는 컴퓨터에서 온 요청만 받는다
- `logout` 은 전용 폴더를 쓸 때만 `claude auth logout` 을 부른다(평소 Claude Code 로그인은 건드리지 않음)
- 단계별 추론 강도(`settings.stage_effort`)를 구독은 `--effort`(모르는 버전이면 뺌), API 는 `output_config.effort` 로 넘긴다. 비우면 모델 기본값. 사용량 기록 줄의 `effort`
- 구독 호출은 `--settings` 로 사용자 설정의 advisor 를 끈다(`NO_ADVISOR`, 모르는 버전이면 뺌). `--safe-mode` 는 advisor 를 끄지 않는다
- advisor 가 붙으면 긴 호출마다 다른 모델 요청이 하나 늘고 본 모델 요청이 두 번 나갔다(2026-11-09, Claude 호출 544번 중 84번)
- 프롬프트 캐시는 두 백엔드가 같은 `shared_cut`(같은 모델 · 시스템 · 스키마의 직전 요청과 겹치는 앞부분, 단락 경계, 2,000자 이상)으로 자른다
- 부른 쪽이 공통 앞부분의 끝을 알면 `hint[llm.PREFIX_HINT]`(`prefix_chars`, 글자 수)로 넘긴다. 읽는 함수는 `llm.prefix_of`
- 경계를 받으면 `shared_cut` 은 직전 요청과 견주지 않고 그 자리(뒤따르는 단락 구분까지 보고 단락 경계로 맞춤)에서 자른다. 같은 앞부분의 첫 호출부터 캐시에 넣는다
- 경계는 Claude 두 백엔드만 쓴다. Gemini · 로컬 · mock 은 hint 의 이 키를 쓰지 않는다
- 캐시는 다음 요청이 읽을 때만 쓴다(`worth_caching`). 캐시 쓰기는 입력 값의 1.25배(1시간 캐시는 2배)다
- 나눌 앞부분이 없으면(cut 0) 쓰지 않는다. 다음 요청은 다른 자리에서 나눠 이 요청의 캐시를 읽지 못한다
- 경계(`PREFIX_HINT`)를 받았으면 쓴다
- 경계 없이 직전 요청과 견줘 나눴으면 직전 같은 종류 요청을 캐시 유지 시간 안에 봤을 때만 쓴다(`cut_and_recent`, `_SEEN_AT`)
- 화마다 한 번 부르는 단계(plot_one 등)는 다음 요청이 15~17분 뒤라 5분 캐시를 읽지 못했다(2026-11-07 서버 실측: plot_one 쓰기 1,044k, 읽기 3k)
- `worth_caching` 은 (쓸지, 까닭 낱말)을 돌려준다. 까닭은 short(cut 0) · prefix(경계를 받음) · recent(직전 요청을 방금 봄) · not_worth(직전 요청이 오래됨)
- 까닭 낱말은 사용량 칸 `cache_note` 로 넘긴다. API 는 `cache_blocks_note` 가, 구독은 `_split` 이 `last_cache_note` 에 정한다
- 구독이 `--system-prompt-file` 을 모르는 버전이면 `cache_note` 는 unsupported 다(캐시는 Claude Code 에 맡김)
- 구독의 형식 고치기 재시도는 `cache_note` 도 첫 시도 값을 쓴다
- API 는 쓰지 않을 요청에 캐시 표시를 달지 않는다(`cache_blocks`)
- 구독은 쓰지 않을 요청에 `DISABLE_PROMPT_CACHING=1` 을 넣는다(`last_keep`). Claude Code 는 표시를 고를 수 없어 사용자 메시지까지 통째로 캐시에 쓴다
- 구독의 쓰지 않는 호출은 캐시 게이트(`_claim`)를 거치지 않는다
- 대가: Claude Code 가 한 호출 안에서 같은 요청을 다시 보내면(`resent`) 그 요청도 캐시를 읽지 못한다
- API 는 그 끝에 `cache_control` 을 단다(`cache_blocks`)
- 구독은 캐시 표시를 고를 수 없어 그 앞부분을 시스템 프롬프트 뒤로 옮겨 `--system-prompt-file` 로 넘긴다(`ClaudeCodeLLM._split`)
- 캐시 가족: 경계(`PREFIX_HINT`)를 받은 호출은 시스템 프롬프트를 가족 공통 글 `llm.FAMILY_SYSTEM` 으로 둔다. 원래 시스템 프롬프트는 사용자 메시지 맨 앞(`llm.role_block`)으로 옮긴다
- 시스템 프롬프트가 다르면 캐시가 맞지 않아서다. 그래서 검수 · 고침안 · 다시 검수가 한 앞부분을, 스토리보드 · 큐 시트 · 본문 쓰기가 다른 한 앞부분을 함께 쓴다
- 구독의 가족 호출은 `--json-schema` 를 쓰지 않는다. 스키마마다 다른 도구가 붙고 도구는 시스템 프롬프트보다 앞이라 캐시가 갈린다
- 구독의 가족 호출은 요청 끝에 `json_instruction`(스키마 JSON 과 'JSON 객체 하나만' 지시)을 붙이고 받은 글을 `_parse` 로 검증한다. 형식이 틀리면 다른 호출처럼 한 번 고쳐 묻는다
- 구독의 가족 호출은 캐시 게이트(`_claim`) 열쇠에서 스키마를 뺀다. 같은 앞부분이면 스키마가 달라도 기다린다
- API 의 가족 호출도 시스템 프롬프트를 `FAMILY_SYSTEM` 으로 두고 역할을 뒤 블록 앞에 둔다. 구조화 출력(`output_config.format`)은 그대로 쓴다
- 두 백엔드는 `family_cache = True` 다. `text(system, prompt, hint=)` 도 경계를 받는다(`llm.family_text`)
- Claude Code 는 시스템 프롬프트 끝에 캐시 표시를 단다
- 형식 고치기 재시도는 첫 시도와 같은 자리에서 자른다(`last_cut`). 처음 요청 뒤에 덧붙이므로 첫 시도의 캐시를 읽는다
- 형식 고치기 재시도는 캐시에 쓸지도 첫 시도를 따른다(`last_keep`)
- `--system-prompt-file` 은 2.1.x `--help` 에 `--system-prompt[-file]` 로만 나온다. 모르는 버전이면 예전처럼 사용자 메시지에 둔다
- 같은 시스템 프롬프트를 동시에 보내면 먼저 보낸 호출이 끝나거나 보낸 지 `CACHE_PREFILL_SECONDS`(30초)가 지날 때까지 뒤 호출이 기다린다(`_claim` · `_release`). 고침안 받기(`FIX_WORKERS` 3)가 모두 캐시를 새로 쓰지 않게 하려는 것
- 모델까지 간 호출은 보낸 시각부터 `CACHE_WARM_SECONDS`(300초) 동안 캐시에 있다고 보고 기다리지 않는다
- `CANON_CLAUDE_CACHE_1H` 를 켜면(`cache_1h`) 이 시간이 `CACHE_WARM_SECONDS_1H`(3600초)다
- `CANON_CLAUDE_CACHE_1H` 를 켜면 `child_env` 가 `ENABLE_PROMPT_CACHING_1H=1` 을 넣는다. Claude Code 가 구독 초과 사용 중에도 1시간 캐시를 쓴다
- `CANON_CLAUDE_CACHE_1H` 가 꺼져 있으면 `child_env` 가 `FORCE_PROMPT_CACHING_5M=1` 을 넣는다. 구독 로그인에서 Claude Code 는 스스로 1시간 캐시를 쓴다(2026-11-05 서버 실측: 쓰기 26건 모두 1시간)
- 같은 실측에서 캐시 읽기는 모두 쓰고 2~4분 뒤에 왔다. 1시간 캐시로는 총비용이 캐시 없을 때의 약 1.08배였다
- `CANON_CLAUDE_CACHE_1H` 를 켜면 API 경로의 캐시 표시(`cache_blocks`)에 `ttl: "1h"` 를 단다
- 기다린 시간은 사용량 기록의 `seconds` 에 넣지 않는다
- 사용량 기록의 글자 수 · 블록 크기는 옮기기 전 원래 프롬프트 기준이다
- `_cli_usage` 는 JSON 결과의 `num_turns` · `stop_reason` · `duration_api_ms` · `modelUsage` 를 사용량 칸 `turns` · `stop` · `api_seconds` · `models` 로 넘긴다
- 구독은 받은 응답 글자 수(`last_raw`)를 사용량 칸 `out_chars` 로 넘긴다
- API 는 `stop_reason` 과 응답 글자 수를 사용량 칸 `stop` · `out_chars` 로 넘긴다. `max_tokens` 로 끊긴 응답(실패 줄)도 받은 글자 수를 남긴다
- 다시 보낸 입력 어림값 `resent`(`_resent`)는 요청 수로 `in × (요청 수-1)/요청 수` 다. 요청 수는 구조화 출력이면 `turns-1`(답을 도구로 내 한 번이어도 2턴), 아니면 `turns`
- `modelUsage` 에 모델이 둘 이상이면(거절 뒤 대체 모델) 가장 작은 모델 입력을 한 번 크기로 보고 넘친 몫도 `resent` 로 본다. 두 값 가운데 큰 쪽
- 캐시에 새로 쓴 입력은 `written`, 그 가운데 1시간 캐시 몫은 `written_1h` 다(`_written`, 응답의 `cache_creation_input_tokens` · `cache_creation.ephemeral_1h_input_tokens`). 구독과 API 경로가 같다
- 두 백엔드도 `llm.wait_cap` · `llm.out_cap` 을 따른다(`llm.caps` 로 읽음)
- 구독은 제한 시간을 `min(CANON_CLAUDE_TIMEOUT, wait_cap)` 으로 둔다. 넘기면 `ClaudeTimedOut`(`ClaudeCodeError` 의 갈래)
- 구독이 `wait_cap` 으로 줄인 한도를 넘기면 `llm.TIMEOUT_RETRIES`(1)번 다시 부른다(`_slow_retry`, 작업 진행 줄에 '다시 불러요')
- 줄이지 않은 한도(`CANON_CLAUDE_TIMEOUT`)를 넘기면 다시 부르지 않는다. 900초를 두 번 기다리지 않게 하려는 것이다
- API 는 `max_tokens` 를 `min(MAX_TOKENS, out_cap)` 으로, SDK 요청 옵션 `timeout` 을 `wait_cap` 으로 보낸다
- API 응답이 `max_tokens` 로 끝나면 `llm.OutputCut` 을 낸다. 본문 쓰기(`pipeline._write`)는 끊긴 본문으로 세어 다시 부른다
- 구독은 `out_cap` 이 있을 때만 그 호출의 하위 환경에 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` 를 넣는다(`child_env(extra)`). 없으면 넣지 않는다
- 두 백엔드는 호출마다(형식 고치기 재시도도) 보내기 전에 `cancel.check()` 를 부른다
- 구독은 `_run` 이 `Popen` 으로 띄우고 `STOP_POLL`(0.25초)마다 멈추기 신호를 보다가 서면 하위 프로세스를 끝내고 `cancel.Cancelled`
- API 는 스트림 조각마다 `cancel.check()` 를 불러 멈추면 스트림을 닫는다
- API 는 흘려 받기(`text_stream(system, prompt, on_chunk, hint=)`)를 둔다. 같은 스트림의 `text` 이벤트마다 지금까지 받은 글 전체로 `on_chunk` 를 부르고 사용량은 다 받은 뒤 한 번 기록한다
- 구독(`ClaudeCodeLLM`)은 `text_stream` 이 없다. 본문 쓰기도 다 끝난 뒤 한 번에 받는다
- 화면은 `static/claude.js`

### `canon/judge.py`

- 판단기
- 글을 쓰지 않고 선택지 확률만 낸다(Jev 의 System One 방식)
- `LocalJudge`(OpenAI 호환 서버 logprobs, 출력 1토큰)
- `LocalJudge.decide` 는 질문 하나가 실패하거나 작업을 멈추면 바로 끝낸다. 남은 질문은 보내지 않고, 보낸 질문의 응답은 기다리지 않는다
- `MockJudge`
- `make_judge` / `get_judge`(`CANON_JUDGE`)
- 환경 변수 값은 `env_choice` 로 읽는다. 연구 화면 검수 시험도 판단기를 고르지 않았거나 모델 · 주소가 비면 이 값을 쓴다(`research.judge_backend`)
- 호출마다 `usage.record`(단계 `judge`)
- 두 걸음 검수 `pipeline.check_two_step`(진술 `prompts.claims_prompt` → 근거 `claim_evidence` → 의심 `verdict_prompt`)가 쓴다
- 두 걸음 검수는 아직 연구 화면에서만 쓴다
- 판단기 평가 세트 `scripts/judge_eval.py`(시험 `tests/test_judge_eval.py`)
- `judge_eval.py build` 는 작품 사본에 모순을 심고(`plant_prompt`) 심은 문장 · 원래 문장 · 고친 지적 · 심지 않은 문장마다 근거 묶음(`claim_evidence`)을 붙여 JSONL 로 쓴다
- `judge_eval.py build` 는 모순을 심은 화마다 심기 전 · 뒤 본문으로 진술 뽑기(`claims_prompt`)를 한 번씩 불러, 그 문장에서 뽑은 진술로 근거를 찾는다(`--no-claims` 면 문장 그대로)
- 평가 줄의 `has_source` 는 심을 때 고른 어긋나는 원문이 근거 묶음에 들었는지다
- `has_source` 가 거짓이어도 다른 단락 · 확정 사실이 같은 모순의 근거가 될 수 있다
- `judge_eval.py run` 은 판단기(local | mock)로 판정해 묶음별 문턱 재현율 · 헛지적률과 AUC 를 낸다. `--blind` 는 근거를 빼고 판정한다
- `judge_eval.py run --shuffle SEED` 는 다른 화의 근거 묶음을 붙여 판정한다. 엉뚱한 근거로도 심은 문장을 짚으면 판단기가 문장의 티를 보는 것이다

### `canon/llm.py`

- LLM 프로바이더 인터페이스(`json`, `text`)와 Gemini(API 키 또는 Vertex AI 서비스 계정 `_vertex_client`)
- 흘려 받을 수 있는 백엔드(Gemini, Claude API, 로컬, mock)만 `text_stream(system, prompt, on_chunk) -> str` 을 둔다. `LLM` Protocol 에는 넣지 않고 부르는 쪽이 `getattr` 로 찾는다
- `on_chunk` 는 조각마다 지금까지 받은 글 전체를 받는다. 다시 부르는 호출(시간 초과 · 서버 오류)은 빈 글부터 다시 보내 화면의 부분 글이 겹치지 않는다
- `text_stream` 은 조각 사이에서 `cancel.check()` 를 부르고 사용량(`usage.record`)은 다 받은 뒤 한 번 기록한다
- Gemini `text_stream` 은 `generate_content_stream` 으로 받는다. 조각을 모은 `_Streamed` 의 마지막 조각 값으로 끝난 이유(`last_finish`) · 사용량을 읽는다
- 로컬 `text_stream` 은 `stream=True` 와 `stream_options.include_usage` 로 SSE 를 받는다(`LocalLLM._stream`). 서버가 400 을 내면 `stream_options` 만 빼고 한 번 더 부른다
- 로컬 흘려 받기는 생각 블록(`<think>`, 아직 닫히지 않은 것까지)을 뺀 글로 `on_chunk` 를 부른다
- 배치(`BatchLLM`)는 `text_stream` 이 없다
- 키 · 권한 오류(401, 403, 400 API_KEY_INVALID, `is_bad_key`)는 다시 부르지 않고 `BadKey`(`KEY_HINT`, Vertex 는 `VERTEX_HINT`)를 낸다. 웹은 code `bad_key` 로 답한다
- 요청 한도로 기다리거나 응답 지연으로 다시 부를 때 `cancel.say` 로 작업 진행 줄에 알리고, 그 호출이 끝나면 비운다
- 로컬(OpenAI 호환) 구현
- 로컬 `json` 은 다른 백엔드처럼 `_validate` 로 읽는다. 앞뒤에 말이 붙은 JSON 도 받는다
- 로컬 시간 초과와 JSON 이 아닌 응답은 주소를 담은 해요체 `RuntimeError` 로 낸다(`LocalLLM._request`)
- 로컬 모델 목록은 `LOCAL_LIST_TIMEOUT`(30초)까지만 기다린다. 멈춘 서버에서 모델 이름을 찾느라 본 호출만큼 더 기다리지 않게
- 단계별 선택(`get_llm(stage)`)
- 단계 이름은 `settings.STAGES` 다
- 캐시 가족 공통 시스템 프롬프트 `FAMILY_SYSTEM` · 역할 블록 `role_block`. 이 글을 바꾸면 쌓인 캐시를 모두 새로 쓴다
- `family_text(llm, system, prompt, head, on_chunk=None)` 는 요청이 head 로 시작하고 백엔드가 `family_cache` 면 `text` 에 경계 hint 를 넘긴다. 아니면 `text(system, prompt)` 만 부른다(다른 백엔드 · 시험용 가짜 LLM)
- `family_text` 는 `on_chunk` 를 받고 백엔드에 `text_stream` 이 있으면 `text` 대신 그것을 부른다. 없으면 지금처럼 `text` 를 부르고 `on_chunk` 는 부르지 않는다
- Gemini 429 요청 한도는 `GeminiLLM._call` 이 `RATE_WAITS`(30 · 60 · 120초)만큼 기다려 다시 부른다(기다리기 전 `cancel.check`, 실패한 시도는 하나씩 사용량에 실패로)
- 429 오류에 서버가 `RetryInfo.retryDelay` 를 주면 `rate_pause` 가 그 값(올림, `RATE_WAITS` 의 가장 긴 값까지)을 기다린다(`retry_delay`)
- 끝내 막히면 해요체 안내 `RateLimited`(`RATE_HINT`)
- 하루 한도 · 선불 크레딧 소진 429(`is_hard_quota`)는 기다리지 않고 `QuotaSpent`(`QUOTA_HINT` 와 `usage.BILLING_URL`)를 낸다
- `is_hard_quota` 는 `QuotaFailure` 위반의 `quotaId` 에 `PerDay` 가 있거나 메시지에 `CREDIT_SPENT` 문구가 있으면 참이다
- `_call` 은 `is_hard_quota` 를 `is_rate_limit` 보다 먼저 본다. 분당 한도와 Vertex 'Resource exhausted' 는 들지 않아 `RATE_WAITS` 만큼 기다린다
- 'exceeded your current quota' 는 분당 한도 429 에도 오는 문구라 `is_hard_quota` 가 보지 않는다
- `retry_delay` 와 `is_hard_quota` 는 같은 details 읽기(`_details`)를 쓴다
- 500 · 502 · 503(`is_transient`: 과부하 UNAVAILABLE · INTERNAL)은 `SERVER_WAITS`(5 · 15 · 45초)만큼 기다려 다시 부른다
- 끝내 풀리지 않으면 해요체 안내 `ServerBusy`(`SERVER_HINT`)
- 429 · 서버 오류 · 시간 초과는 따로 센다
- 응답 시간 한도는 요청마다 SDK `HttpOptions(timeout)` 로 준다(`GEMINI_TIMEOUT` 600초, `CANON_GEMINI_TIMEOUT` 초로 바꿈, `gemini_timeout`)
- 시간 한도를 넘기면(`is_timeout`) `cancel.check` 뒤 한 번 더 부른다
- 또 넘기면 해요체 안내 `TimedOut`(`TIMEOUT_HINT`)
- 넘긴 시도도 사용량에 실패로
- Gemini 가 글 없이 끝나면 `EmptyResponse`(RuntimeError)를 낸다: '끝난 이유'(`finish`) · '막은 이유'(`prompt_feedback.block_reason`, `block`) · 생각 토큰 수(`thought`)를 싣는다
- `EmptyResponse` 문구는 'Gemini 응답이 비었어요' 로 시작한다. code · status 칸이 없어 `is_transient` 가 다시 부르지 않는다
- 화면 오류 문구는 `explain_error(e)` 가 고른다. `ERROR_TABLE` 의 줄을 위에서부터 보고 처음 맞는 줄의 원인과 할 일을 쓴다
- `ERROR_TABLE` 줄 차례: 하루 한도 · 안전 필터(`SAFETY_STOPS`) · RECITATION · 생각만 쓰고 끊김(MAX_TOKENS 와 생각 토큰) · 입력 길이 초과 · 지역 제한
- `ERROR_TABLE` 에는 'blocked' · '400' 같은 넓은 패턴을 두지 않는다. API 키 제한 403 도 'are blocked.' 로 온다(`tests/test_explain_error.py`)
- 맞는 줄이 없으면 한국어 오류는 그대로 둔다. 한글이 없는 오류는 앞 `FOREIGN_CUT`(140)자만 싣고, `PROVIDER_MODULES` 의 오류면 'AI 서비스가 오류를 돌려줬어요' 를 앞에 붙인다
- `explain_error` 를 쓰는 곳: `jobs` 작업 오류 · `autorun` 오류 멈춤 · `web` 의 서버 오류 응답 · 고침안 실패 · 쓴 뒤 검수 실패 · `pending.json` 실패 기록. 전체 예외는 각 곳이 서버 로그에 남긴다
- 배치는 429 · 서버 오류 · 시간 한도 경로 밖
- `BatchLLM` 은 slot 마다 보낸 프롬프트 지문(`keys`, `BatchLLM.key`)을 남긴다. 다시 붙을 때 지문이 다르면 기다리던 작업을 취소하고 새로 보낸다
- `GeminiLLM.batch_poll` 은 배치 응답의 `finish_reason` 을 `last_finish` 에 남기고, `BatchLLM` 이 그것을 자기 `last_finish` 로 옮긴다(끊긴 배치 본문 거부)
- 형식 고치기 slot(`<slot>:fix`)도 처음 프롬프트의 지문으로 맞춰 본다. 지문이 없는 예전 기록은 그대로 다시 붙는다
- 모든 요청 맨 끝(사용자 메시지)에 `POLICY_NOTE` 한 줄(`with_note`, Gemini · 배치 · 로컬 · `claude.py` 두 백엔드가 보내기 직전에). 수위 지시는 프롬프트에 두지 않는다
- 성인 독자 대상 작품의 요청이면 `with_note` 가 `POLICY_NOTE` 앞에 `ADULT_NOTE`(작가가 정한 RP/ERP 줄)를 둔다. 작품은 `usage.adult()` 로 안다. 프롬프트 글은 성인 · 전연령 작품이 같다
- 응답 읽기 `_validate`: 통째로 읽히지 않으면 글 속 최상위 JSON 객체(`_json_objects`)를 뒤에서부터 읽는다(생각 글이 앞에 새는 응답, Gemini · 배치 · Claude 공통)
- 형식 고치기 `repair_prompt`: 응답에 JSON 객체가 없으면 처음 요청을 그대로 다시 보낸다
- Gemini 응답이 끝난 이유는 `last_finish`(두 번째도 실패하고 `MAX_TOKENS` 면 `SchemaMismatch` 글에 길이 한도를 적는다)
- 로컬도 응답의 `finish_reason` 을 `last_finish` 에 남긴다(`length` 는 출력 한도에 걸려 끊김)
- Gemini · 로컬 · 배치는 끝난 이유와 응답 전체 글자 수를 사용량 칸 `stop` · `out_chars` 로 넘긴다(`usage.with_extra`, `last_usage` 는 토큰 수만 둔다)
- 로컬의 `out_chars` 는 생각 태그(`<think>`)를 떼기 전 응답 글자 수다
- `was_cut(llm)` 은 `last_finish` 가 `CUT_FINISH`(`MAX_TOKENS` · `length`)면 참이다
- `knows_cut` 이 참인 백엔드(Gemini · 로컬 · Claude API · mock)만 끊김을 알린다. `pipeline._write` 가 이 백엔드에만 출력 한도를 건다
- 로컬은 `caps_write = False` 라 본문 쓰기 출력 한도를 받지 않는다. vLLM 은 프롬프트 + `max_tokens` 가 컨텍스트를 넘으면 요청을 400 으로 거절한다
- `OutputCut`(RuntimeError): 끝난 이유 대신 오류로 끊김을 알리는 백엔드가 낸다(Claude API `max_tokens`)
- Gemini 추론 강도(`GeminiLLM.effort`, `settings.GEMINI_EFFORTS`)는 `thinking_config.thinking_level` 로 넘긴다(일반 호출과 배치)
- Gemini 온도(`GeminiLLM.temperature`)는 정했을 때만 `temperature` 로 넘긴다. 연구 화면 샘플 생성과 프롬프트 놀이터가 쓴다(`research.make_backend`)
- 프롬프트 놀이터는 `research.make_backend` 에 단계를 넘겨 그 단계의 모델 · 추론 강도로 Gemini · 로컬을 만든다
- 강도를 비우면 `thinking_config` 를 보내지 않는다(모델 기본값)
- Gemini 명시 캐시(`GeminiLLM._cached`)는 플롯 대화 단계(`stage == "chat"`)에서 `settings.gemini_cache` 가 켜져 있을 때만 쓴다
- 같은 종류 직전 요청과 겹치는 앞부분은 `claude.shared_cut` 으로 찾는다(열쇠 `("gemini", vertex, 모델, 시스템, 작품)`, 단락 경계)
- 열쇠에 작품(`usage.context()` 의 project)을 넣는다. 두 작품의 대화가 번갈아 와도 서로의 겹침을 지우지 않는다
- 겹치는 앞부분이 `GEMINI_CACHE_MIN_CHARS`(16,000자) 이상이고 덮는 캐시가 없으면 `client.caches.create`(시스템 프롬프트 + 앞부분, `GEMINI_CACHE_TTL` 600초)로 만든다
- 캐시 만들기는 `GEMINI_CACHE_CREATE_TIMEOUT`(120초)까지만 기다린다. 늦으면 일반 호출로 넘어가고, 그 전에 작업 멈추기(`cancel.check`)를 본다
- 캐시 만들기도 사용량에 따로 기록한다(작업 이름 뒤에 '캐시 만들기', 입력은 응답의 `total_token_count`). 보통 입력 요금으로 매긴다(가정)
- 만든 캐시는 `(vertex, 모델, 시스템 해시, 계정)` 별로 앞부분 길이 · 해시 · 이름 · 만료 시각으로 기억한다(`_GEM_CACHES`, `_cache_find`)
- 계정(`GeminiLLM.cache_owner`)은 API 키나 Vertex 서비스 계정 · 프로젝트 · 위치의 해시다. 키를 바꾸면 앞 키로 만든 캐시를 보내지 않는다
- 살아 있는 캐시가 겹치는 앞부분의 절반 이상을 덮으면 그것을 다시 쓴다. 만료 `GEMINI_CACHE_MARGIN`(60초) 전부터는 쓰지 않는다
- 캐시를 쓰는 요청은 `GenerateContentConfig(cached_content=이름)` 과 나머지 글만 보낸다. 시스템 프롬프트는 넣지 않는다(API 가 거절한다)
- 캐시를 만들거나 쓰다 난 오류는 모두 일반 호출로 넘어간다(`_cache_failed`). 넘어간 호출 하나만 사용량에 기록한다
- `_cached` 는 (캐시 이름과 나머지 글 또는 None, 까닭 낱말)을 돌려준다. 까닭은 사용량 칸 `cache_note` 가 된다(`llm.CACHE_NOTES`)
- 까닭 낱말은 분기마다 하나다: stage_off · setting_off · model_off(오류로 잠시 끔) · unsupported(받지 않는 모델) · hit · short · made · failed
- 캐시를 만들다 실패했거나 살아 있는 캐시를 쓰다 실패해 일반 호출로 넘어간 호출은 failed 다
- 만료된 캐시는 `_cache_find` 가 조용히 지우기만 해 따로 낱말을 두지 않는다(새로 만들면 made, 앞부분이 짧으면 short)
- 429 · 시간 초과 · 서버 오류가 아닌 캐시 오류는 그 모델의 캐시를 `GEMINI_CACHE_BACKOFF`(1시간) 동안 끈다
- 모델이 명시 캐시를 받지 않는다는 오류(`is_cache_unsupported`, 문구 'does not support explicit context caching')는 그 모델을 바로 끈다(`_GEM_CACHE_OFF` 값 inf)
- 그 모델은 `settings.mark_gemini_cache_unsupported` 로 설정 파일 `gemini_cache_unsupported` 에 남기고, `_cached` 가 읽어 서버를 다시 시작해도 캐시 만들기를 보내지 않는다
- 기록의 열쇠는 `key:모델` · `vertex:모델`(`settings.gemini_cache_model_key`)이다. 모델이 나중에 받게 되면 설정 파일에서 그 줄을 지운다
- 실측(2026-11-07): gemini-4-argon(API 키)은 명시 캐시를 받지 않는다. 캐시 만들기 5번이 모두 이 오류였고 성공은 0번이다
- 캐시를 쓰다 난 403 · 404(만료되거나 다른 키로 만든 캐시)는 그 캐시만 잊는다
- 캐시 만들기의 400(앞부분이 최소 캐시 크기보다 작을 수 있다)은 그 길이 이하만 피한다(`_GEM_CACHE_FLOOR`). `GEMINI_CACHE_BAD_SIZE`(3)번 잇따르면 모델을 끈다
- 명시 캐시를 받지 않는다는 400 은 이 길이 셈을 거치지 않는다
- 캐시를 쓰는 요청이 429 · 시간 초과 · 서버 오류면 일반 호출로 넘어가지 않고 `_call` 의 다시 부르기에 맡긴다
- Vertex AI 도 같은 경로다. SDK 가 Vertex 캐시를 지원하지만 실제 Vertex(`global` 위치)에서 되는지는 재지 않았다. 안 되면 첫 오류 뒤 1시간씩 꺼진다
- 캐시 저장 요금은 사용량 비용 추정에 넣지 않는다. 기본값 근거(저장 · 만들기 요금 가정)는 `llm.py` 의 `GEMINI_CACHE_TTL` 위 주석

### `canon/usage.py`

- AI 사용량과 비용
- LLM 구현이 실제 호출마다 `record` 로 `projects/.usage/usage.jsonl` 에 남긴다
- `adult()` 는 scope 의 `project` 가 성인 독자 대상 작품인지 돌려준다(`adult_of` 는 store 가 채움, 모르면 False)
- `read` 는 읽은 끝 위치를 기억하고 다음에는 늘어난 줄만 읽는다(`_read_cache`)
- 작품 · 화 · 작업은 `scope(...)` 로 붙인다(웹 미들웨어, `jobs.start`, 자동 집필, CLI)
- `collect()` 는 안에서 `record` 한 줄을 목록에 모은다(`_acc`). `copy_context` 로 넘긴 스레드의 호출도 같은 목록에 모인다
- `totals(rows)` 는 모은 줄의 입력 · 출력(생각 포함) 토큰과 `row_cost` 비용 합이다. 가격을 모르는 줄이 있으면 비용은 None
- 가격표(`DEFAULT_PRICES` + 설정의 `prices`, 날짜별 `since`)로 볼 때 비용을 계산한다
- 기본 가격표는 `PRICES_CHECKED` 에 Google 가격표(`PRICES_URL`)와 Anthropic 가격표(`CLAUDE_PRICES_URL`)에서 옮겼다
- `Price.cache_write` · `cache_write_1h` 는 5분 · 1시간 캐시에 새로 쓴 입력의 값이다
- 캐시 쓰기 칸이 비면 입력의 1.25배 · 2배로 친다(Anthropic 가격표의 배율)
- `cost` 는 `written` 을 캐시 쓰기 값으로, 그 가운데 `written_1h` 를 1시간 캐시 쓰기 값으로 센다
- 기록 줄에 `written` 칸이 없으면(옛 줄 · Gemini) 캐시 쓰기는 0이다
- `cost` 는 캐시 읽기와 쓰기의 합이 입력을 넘으면 입력 안으로 자르고, 음수는 0으로 둔다
- 프롬프트 놀이터의 `promptlab.run_cost` 도 `written` · `written_1h` 를 넘겨 같은 값을 낸다
- 배치는 캐시 읽기 · 쓰기 값에도 입력과 같은 할인 비율을 곱한다(Anthropic 가격표: 배율은 배치 할인과 겹친다)
- `row_cache` 는 줄마다 (캐시 읽기로 아낀 비용, 캐시 쓰기 할증)이다. 둘 다 0 이상이다
- 아낌은 `cached` 를 입력 값으로 친 비용에서 실제 비용을 뺀 값이다
- 할증은 실제 비용에서 `written` 을 입력 값으로 친 비용을 뺀 값이다
- 로컬 · Claude 구독(0원) · 가격을 모르는 모델은 아낌과 할증이 0이다
- `summary` 는 날짜 · 작품 · 화 · 단계 · 모델 · 용도 · 작업(`by_task`) · 추론 강도(`by_effort`)로 묶는다
- 추론 강도를 정하지 않은 호출은 `EFFORT_DEFAULT`('기본') 묶음에 든다
- 묶음과 합계마다 `cache_rate`(캐시 / 입력, 입력이 없으면 0)와 `seconds_avg`(호출당 평균 초)를 붙인다(`_rates`)
- 묶음과 합계는 `discarded`(버린 응답 수)와 `cut`(끊긴 호출 수, `is_cut`: `stop` 이 `CUT_STOPS` 이거나 `discarded` cut)를 센다
- 분량 달성률 `len_ratio` 는 목표 분량이 있는 줄의 `out_chars` 합 / `target` 합이다(`len_pair`). 그런 줄이 없으면 None, 센 줄 수는 `len_calls`
- `len_ratio` 에는 실패 · 버린 줄과 칸이 없는 옛 줄을 넣지 않는다
- 낭비(`wasted`)와 실패 목록(`trouble`)은 실패 · `attempt` 2 이상 · `discarded` 줄이다
- 묶음 · 합계 · 호출 줄마다 `cache_saved` · `cache_premium` 을 붙인다(`row_cache`, 묶음은 `_cache` 로 반올림)
- 자동 집필 추정도 같은 가격표를 쓴다
- 입력 토큰 추정 `token_rate(백엔드, 모델)` 은 '기울기 × 요청 글자 수 + 호출마다 붙는 토큰' 직선(`TokenRate`)이다
- 기본값 `TOKEN_RATES` 는 2026-11 서버 기록의 최소제곱 직선이다(Opus Claude Code 1.035/3805, Sonnet 0.995/5793, argon 0.568/1579, flash 0.599/2508)
- `claude-api` 는 기록이 없어 같은 기울기에 붙는 토큰 0을 쓴다
- 기본값이 없는 백엔드(로컬, mock)는 1.7자당 1토큰이다(`FALLBACK_CHARS_PER_TOKEN`)
- 같은 백엔드 · 모델의 최근 성공 기록(글자 수 있음) `REFINE_MIN` 줄 이상이면 최근 `REFINE_ROWS` 줄로 다시 잰다
- 다시 잴 때 Claude Code 가 캐시 읽기를 입력에 두 번 센 예전 줄(cached × 2 ≥ 0.9 × in 이고 in 이 기본 직선의 1.5배 초과)은 뺀다
- 캐시가 입력 대부분이어도 입력이 직선 근처인 줄(앞부분을 시스템 프롬프트로 옮겨 캐시가 맞은 호출)은 남긴다
- Claude Code 기록의 모델은 실제로 답한 이름이라 설정의 별칭(`opus` 등)은 그 낱말이 든 기록과 맞춘다(`_same_model`)
- Claude Code 기본 모델(설정이 빔)은 최근 성공 기록에 가장 많은 모델로 본다(`_default_model`)
- 기록의 글자 수는 시스템 프롬프트를 뺀 요청이라 붙는 토큰에 시스템 프롬프트가 들어 있다
- `est_input(글자, 직선, 시스템 글자, 호출 수)` 는 붙는 토큰과 '기울기 × 시스템 글자' 가운데 큰 쪽을 호출마다 더한다
- 단계의 백엔드 · 모델은 `stage_llm`, 그 직선은 `stage_rate` 다
- 자동 집필 · 큐 시트 · 블록 시험 · 상태창 시험 · 역설계 실험의 비용 추정이 이 직선을 쓴다
- 장편 블록 예산(`context.BUDGET`)과 `context.est_tokens` 는 이 직선을 쓰지 않는다
- 백엔드가 더 준 칸(`EXTRA`: turns · stop · api_seconds · models · resent · written · written_1h · out_chars · cache_note)은 있을 때만 줄에 남는다. 옛 줄에는 없다
- `cache_note` 는 캐시를 쓰거나 못 쓴 까닭 낱말이다(`llm.CACHE_NOTES`). Gemini 는 `_cached`, Claude 는 `worth_caching` 이 정한다
- `stop` 은 모든 백엔드의 끝난 이유다(Gemini `STOP` · `MAX_TOKENS`, Claude `end_turn` · `max_tokens`, 로컬 `stop` · `length`). 새 칸을 두지 않고 Claude Code 의 칸을 함께 쓴다
- `out_chars` 는 응답 전체 글자 수다(본문에서 뗀 작업 설명도 든다)
- `with_extra(tokens, **칸)` 은 백엔드가 토큰 dict 에 칸을 더한 새 dict 를 만든다. 값이 None · 빈 글이면 넣지 않는다
- scope 의 정해진 키(project · episode · stage · task · source · attempt) 밖에서는 `SCOPED`(target)만 줄에 싣는다. 다른 키는 줄에 남지 않는다
- `record` 는 백엔드가 넘긴 `attempt` 를 scope 의 값보다 먼저 쓴다
- `hold()` 는 안에서 `record` 한 줄을 파일에 쓰지 않고 모았다가 끝날 때 쓴다. 겹쳐 열면 안쪽 줄은 바깥 목록으로 넘긴다
- `hold()` 안의 줄도 `collect()` 에는 바로 더한다. 같은 dict 라 나중에 단 `discarded` 도 보인다
- `discard(rows, 까닭)` 은 모은 줄 가운데 마지막 줄(응답을 낸 호출)에 `discarded` 를 단다. 이미 까닭이 있으면 두고 바꾸지 않는다
- 기록 파일은 덧붙이기만 하므로 응답을 받은 뒤 버릴지 정하는 쪽(`pipeline._write`)이 `hold` 로 쓰기를 미룬다
- `cache_rate(rows)` 는 캐시 비율이다. `resent` 를 입력과 캐시 양쪽에서 뺀다. 비용 계산은 `resent` 를 보지 않는다
- `summary` 의 합계는 `resent` 합과 `cache_rate` 를 준다. 화면 토큰 타일이 다시 보낸 입력이 있을 때 뺀 캐시 비율을 보인다
- 화면은 `static/usage.js`
- `usage.js` 는 손가락 기기에서 차트 안내를 '막대를 누르면 날짜별 값을 봐요' 로 보인다(←/→ 키 안내는 aria-label 에만)
- 화면 차례: 기간 · 작품 거르기 → 비용 타일 → 날짜별 막대 → '어디에 썼나' 막대 목록 → 호출 목록 → 접힌 가격표
- 날짜별 막대는 비용 · 호출 수 중 하나(축 하나, 눈금 `usageTicks`)
- '어디에 썼나'는 단계 · 작업 · 모델 · 추론 강도 · 작품(작품 안에서는 화) · 어디서 중 하나(`usageBreakdown`)
- '어디에 썼나' 줄은 비용 · 호출 · 캐시 비율 · 평균 시간 · 토큰을 보인다
- 추론 강도로 나누면 끊김 · 버림 · 분량(달성률) 열을 더하고(`.usage-br.fx`), 표 아래에 '응답 전체 글자 수 기준'이라고 밝힌다. 칸 폭 900px 이하에서는 세 열과 그 안내를 숨긴다
- 호출 목록은 버린 줄에 '버림' 칩과 까닭(`USAGE_DISCARD`)을, 토큰 칸에 '응답 글자 수/목표 분량자'를 보인다
- 캐시 비율 글자는 `usagePct`(10% 밑은 소수 첫째 자리)
- 비용 타일의 토큰 칸은 캐시 비율과 캐시 토큰을 함께 보인다
- '아낀 · 버린 비용' 타일의 큰 숫자에서 아낀 쪽은 배치 할인과 캐시 읽기 아낌의 합이다
- 그 타일의 풀이(`usageSavedLine`)는 배치 · 캐시 읽기 · 캐시 쓰기 할증을 따로 보인다
- 할증이 캐시 읽기 아낌보다 크면 풀이에 '(아낀 것보다 커요)'를 덧붙인다
- 호출 목록의 비용 칸은 아낌(배치 + 캐시 읽기)과 쓰기 할증을 따로 보인다
- 가격표 카드는 읽는 모양이 기본이고 '고치기'로 편다(`S.priceOpen`)
- 가격표 칸은 `PRICE_COLS` 이고 캐시 쓰기 · 1시간 캐시 쓰기 칸이 있다
- 빈 가격 칸의 흐린 글자는 비웠을 때 쓰는 값이다(`PRICE_EMPTY`, `usage.cost` 와 같은 규칙)
- 가격표 저장 · 기본값으로 되돌리기는 `run()` 으로 보내 기다리는 동안 뒤 화면을 막고 포커스를 기다림 상자로 옮긴다(`priceSend`)
- 칸 폭 규칙은 `@container usage`
