# 12. 문체 규칙의 빈도 하한 막기

상태: 진행 (claude/style-rule-floor) · 계획: [plan.md](../plan.md) 의 12번 · 먼저: —

## 목표

문체 분석과 문체 대화가 지킬 것(`dos`)과 전개 속도(`pacing`)에 '화마다 한 번 이상' 같은 빈도 하한을 새로 적지 않는다.
이미 있는 그런 줄은 문체 화면에서 '빈도 규칙' 칩으로 보인다.
이 일감은 이야기 틀과 상관없다. [plan.md](../plan.md) 의 '기본값이면 프롬프트가 글자까지 같다'는 시험은 맞지 않아 두지 않았다. 두 프롬프트는 모든 작품에서 바뀐다.

## 정할 것

아직 사용자가 정하지 않았다. 이 일감은 답이 필요 없는 부분만 구현했다.

1. [plan.md](../plan.md) 정할 것 19: 장치 최소 간격(`StyleDevice.every`)을 분석이 원문 빈도로 채우지 않게 할까요? — 추천: 채우지 않게 한다. **구현하지 않음.** `style_prompt` 의 'every 는 … 짐작한 최소 간격' 문장과 스키마 설명은 그대로다.
2. [plan.md](../plan.md) 정할 것 20: 빈도 하한 줄을 저장 때 경고만 할까요, 막을까요? — 추천: 경고만. **임시로 경고만 구현.** 막기로 정하면 저장 경로에 검사를 더한다.

## 본 것 (2026-11-14, 읽기만)

- 작품과 문체 라이브러리의 `dos` · `pacing` 은 겹친 것을 빼고 105줄이다. 검사가 17줄을 짚는다.
- 꼴: '한 화에 한 번은 …', '장면마다 한 번 이상 …', '아크마다 한 번은 …', '매 대화마다 …', '매 장면 …', '장면 하나마다 … 하나를 묶는다', '각 화마다 A → B → C 구성을 취하며'.
- 지나가야 하는 꼴: '장면마다 쓰지 않는다', '화마다 되풀이하지 않는다', '한 장면에 한 번 넘게 쓰지 않는다', '화마다 순서와 비중이 달라진다', '아크마다 다르게', '닿을 때마다'.
- 작가가 `pacing` 의 '각 화마다 … 구성을 취하며'를 '화를 짜는 재료일 뿐 정해진 순서가 아니다'로 손본 작품이 있다. 프롬프트의 둘째 문장은 이 글에서 가져왔다.

## 규칙

- 문장(`.` `!` `?` 줄바꿈으로 나눔) 하나에 `FLOOR_HIT` 이 있고 `FLOOR_PASS` 가 없으면 빈도 하한이다.
- `FLOOR_HIT`: 매 + 단위, 단위 + 마다, '한 단위에 n번은 · 씩 · 이상', 'n번 이상', '최소 · 적어도 n'. 단위는 화 · 회 · 회차 · 장면 · 씬 · 문단 · 대화 · 아크다.
- `FLOOR_PASS`: 부정(않 · 말 것 · 마세요 · 금지), 횟수 뒤의 상한(까지 · 넘게 · 넘기 · 이하 · 이내), 달라짐(달라 · 다르게).
- 보는 칸은 `pacing` 과 `dos` 다. 피할 것은 보지 않는다. 효과음 칸은 화당 빈도를 묻는 칸이라 보지 않는다.
- 막지 않는다. 화면에 칩만 단다. 이미 저장된 줄은 그대로다.
- 문체 대화 프롬프트는 '새로 더하지 않는다'고만 적는다. 대화는 목록 칸의 모든 항목을 다시 보내므로, 금지로 적으면 작가가 쓴 줄을 지울 수 있다.

## 프롬프트 글의 출처 ([docs/prompts/editing.md](../../prompts/editing.md) 0.6)

일의 종류는 고치기다. 분석과 문체 대화의 동작이 바뀐다.

| 더한 문장 | 출처 |
|---|---|
| 'dos 와 pacing 에는 … 얼마나 자주 넣을지 정하는 규칙을 적지 않습니다' | [README.md](../README.md) 'AI 느낌을 만드는 프롬프트'의 방향(2026-11-10, 전한 세션에 따르면 사용자가 동의함)과 계획 12번 |
| '원문에서 화마다 되풀이되는 구성은 화를 짜는 재료로만 적고, 정해진 순서로 적지 않습니다' | 작가가 작품의 `pacing` 을 손본 글 |
| '… 새로 더하지 않습니다. 작가가 그렇게 적어 달라고 한 것과 지금 프로필에 이미 있는 줄은 그대로 둡니다' | 같은 방향. 뒤 문장은 '사용자가 입력한 설정은 AI 제안이 덮지 않는다'(AGENTS.md) |

## 확인한 층

| 층 | 결과 |
|---|---|
| 글 | 원문 문장은 지우지 않았다. 더한 문장 셋의 출처는 위 표 |
| 시험 | 전체 시험 통과. 스냅샷은 `style_chat` 둘만 바뀜 |
| 조립 | 재지 않음. 문체 대화는 `brief` 경로의 해시만 봤다 |
| 모델 출력 (분석) | 가르지 못함. gemini-3.8-flash, 표본 둘, 줄 없는 판 6회 · 있는 판 5회 모두 빈도 하한 줄 0개 |
| 모델 출력 (문체 대화) | 재지 않음 |

- 분석은 줄 없이도 빈도 하한을 내지 않았다. 작품에 있는 17줄은 문체 대화가 제안한 것으로 작가가 짐작한다(2026-11-14). 기록으로 확인하지는 않았다.
- 실측 기록: `reports/rate-floor-2026-11-14/`(커밋하지 않음).

## 한계

- 한 문장에 부정과 하한이 함께 있으면 지나간다('아크마다 하나씩 더하며, 같은 문구를 되풀이하지 않는다').
- '장면 하나마다 … 하나를 묶는다'처럼 조건에 가까운 줄도 걸린다. 경고만 하므로 그대로 뒀다.
- '매번', '항상', '반드시'는 보지 않는다. 빈 줄 넣기 같은 형식 규칙이 함께 걸린다.
