# 12. 문체 규칙의 빈도 하한 막기

상태: 끝 ([#526](https://github.com/c10dev/canon/pull/526), 장치 간격은 [#533](https://github.com/c10dev/canon/pull/533)) · 계획: [plan.md](../plan.md) 의 12번 · 먼저: —

## 목표

문체 분석이 지킬 것(`dos`)과 전개 속도(`pacing`)에 '화마다 한 번 이상' 같은 빈도 하한을 적지 않는다.
문체 분석이 장면 장치의 최소 간격(`StyleDevice.every`)을 원문 빈도로 짐작해 채우지 않는다.
문체 대화 프롬프트는 바꾸지 않는다(아래 실측).
이미 있는 그런 줄은 문체 화면에서 '빈도 규칙' 칩으로 보인다.
이 일감은 이야기 틀과 상관없다. [plan.md](../plan.md) 의 '기본값이면 프롬프트가 글자까지 같다'는 시험은 맞지 않아 두지 않았다. 분석 프롬프트는 모든 작품에서 바뀐다.

## 정할 것

1. [plan.md](../plan.md) 정할 것 19: 장치 최소 간격(`StyleDevice.every`)을 분석이 원문 빈도로 채우지 않게 할까요? — 추천: 채우지 않게 한다. **추천안으로 진행, 2026-11-14.** 아래 '장치 최소 간격' 절.
2. [plan.md](../plan.md) 정할 것 20: 빈도 하한 줄을 저장 때 경고만 할까요, 막을까요? — 추천: 경고만. **임시로 경고만 구현.** 막기로 정하면 저장 경로에 검사를 더한다.

## 본 것 (2026-11-14, 읽기만)

- 작품과 문체 라이브러리의 `dos` · `pacing` 은 겹친 것을 빼고 105줄이다. 검사가 17줄을 짚는다.
- 꼴: '한 화에 한 번은 …', '장면마다 한 번 이상 …', '아크마다 한 번은 …', '매 대화마다 …', '매 장면 …', '장면 하나마다 … 하나를 묶는다', '각 화마다 A → B → C 구성을 취하며'.
- 지나가야 하는 꼴: '장면마다 쓰지 않는다', '화마다 되풀이하지 않는다', '한 장면에 한 번 넘게 쓰지 않는다', '화마다 순서와 비중이 달라진다', '아크마다 다르게', '닿을 때마다'.
- 작가가 `pacing` 의 '각 화마다 … 구성을 취하며'를 '화를 짜는 재료일 뿐 정해진 순서가 아니다'로 손본 작품이 있다. 프롬프트의 둘째 문장은 이 글에서 가져왔다.

## 규칙

- 문장(`.` `!` `?` 줄바꿈으로 나눔) 하나에 `FLOOR_HIT` 이 있고 `FLOOR_PASS` 가 없으면 빈도 하한이다.
- `FLOOR_HIT`: 매 + 단위, 단위 + 마다, '한 단위에 n번은 · 씩 · 이상', 'n번 이상', '최소 · 적어도 n'. 단위는 화 · 회 · 회차 · 장면 · 씬 · 문단 · 대화 · 아크다.
- `FLOOR_PASS`: 부정(않 · 말 것 · 마세요 · 금지), 횟수 뒤의 상한(까지 · 넘게 · 넘기 · 이하 · 이내), 달라짐(달라 · 다르게).
- 보는 칸은 `pacing` 과 `dos` 다. 피할 것은 보지 않는다. 효과음 칸은 화당 빈도를 묻는 칸이라 보지 않는다.
- 막지 않는다. 화면에 칩만 단다. 이미 저장된 줄은 그대로다.

## 문체 대화 프롬프트 줄 실측 (2026-11-14, 넣지 않음)

요구사항에 "dos 와 pacing 에 … 규칙을 새로 더하지 않습니다. 작가가 그렇게 적어 달라고 한 것과 지금 프로필에 이미 있는 줄은 그대로 둡니다"를 넣은 판과 뺀 판을 견줬다.

- 방법: 대화 에이전트 세션에 남은 실제 문체 요청 둘을 그때의 적용 전 문체로 되돌려 다시 보냈다. gemini-3.8-flash, 판마다 10회(사례 가 3회, 사례 나 7회).
- 두 사례 모두 적용 전 문체에 빈도 줄이 5개 있었다.

| 판 | 성공 | 실패 | 지킬 것을 비운 변경안 | 결과의 빈도 줄 수 (성공한 실행) |
|---|---|---|---|---|
| 줄 없음 | 10 | 0 | 0 | 가: 0 · 1 · 0, 나: 5가 7번 |
| 줄 있음 | 6 | 4 (RECITATION 2, 끝없이 긴 응답 2) | 2 | 가: 0 · 0, 나: 5 · 0 · 5 · 5 |

- 빈도 줄 수는 두 판이 갈리지 않는다. 사례 가는 줄 없이도 0~1개로 줄었고, 사례 나는 두 판 모두 5개를 글자까지 그대로 뒀다.
- 줄 있는 판만 실패와 빈 지킬 것이 나왔다. 지킬 것을 비운 2회는 원래 응답을 남기지 않아 까닭을 가리지 못했고, 응답을 남긴 뒤 8회에서는 다시 나오지 않았다.
- 그래서 문체 대화 프롬프트에는 줄을 넣지 않는다. 모델은 flash 하나뿐이고 기본 기획 모델(gemini-4-argon)로는 재지 않았다.
- 문체 대화는 빈도 줄을 새로 만들기보다 이미 있는 줄을 새 작품에 맞게 고쳐 썼다. 기록에서 대화가 새로 만든 것은 전개 속도 칸의 '각 화마다 A → B → C 구성' 한 줄이다. 처음의 5줄이 어디서 왔는지는 기록에 없다.
- 쓴 비용: 문체 분석 11회와 문체 대화 20회(다시 요청 포함 호출 38회, 실패 11회)에 가격표로 약 $3.77. 실패한 호출이 출력 한도까지 써서 어림($1)보다 컸다.

## 장치 최소 간격 (정할 것 19, 2026-11-14)

- `style_prompt` 은 'every 는 원문에서 나온 빈도로 짐작한 최소 간격(화)' 대신 'every 는 0 으로 두세요. 최소 간격은 작가가 정합니다.'라고 적는다. `per_1k` 줄과 같은 꼴이다.
- `count_markers` 는 분석 결과의 `every` 를 모두 0 으로 맞춘다. 모델이 값을 적어도 버린다. 이 함수를 부르는 곳은 `analyze_style` 하나다.
- `analyze_style` 을 거치는 경로가 모두 바뀐다: 작품 문체 분석, 라이브러리 분석, 레퍼런스 원고 문체, 역설계(`revlab`), 연구 화면, 명령줄 `style`.
- 그래서 분석이 만든 장치는 `prompts.device_block` 에서 '이번 화에는 쓰지 않습니다'가 나오지 않는다. 상황이 올 때만 한 번까지 쓰라는 줄과 마지막으로 쓴 화만 나온다. `metrics.device_warnings` 도 간격 경고를 내지 않는다.
- `schema.StyleDevice.every` 의 설명은 그대로다. 칸은 남고 작가가 적은 값은 지금처럼 쓴다.
- 바꾸지 않은 경로:
  - 문체 대화(`style_chat_prompt` 의 'devices 에 적습니다 (when, cues 1~3개, every)')와 대화 에이전트의 문체 도구. 작가의 말로 값을 정하는 경로다.
  - 수정에서 배우기(`learn_prompt` 의 'every 는 몇 화에 한 번까지인지'). 작가가 줄인 기록에서 뽑는다.
  - 라이브러리 · 작품 가져오기. 이미 있는 값을 옮긴다.
- 이미 저장된 값은 바꾸지 않는다. 문체 화면의 장치 칩('n화에 한 번' · '상황이 올 때만')도 그대로다.
- 가짜 응답(`mock._r_style_profile`)은 every=3 을 그대로 적는다. 정리가 버리는지 시험하려는 것이다.

## 한계

- 한 문장에 부정과 하한이 함께 있으면 지나간다('아크마다 하나씩 더하며, 같은 문구를 되풀이하지 않는다').
- '장면 하나마다 … 하나를 묶는다'처럼 조건에 가까운 줄도 걸린다. 경고만 하므로 그대로 뒀다.
- '매번', '항상', '반드시'는 보지 않는다. 빈 줄 넣기 같은 형식 규칙이 함께 걸린다.
