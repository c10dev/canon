# 11. 인물 카드를 '표현'에서 '압력'으로

상태: 진행 (claude/cast-pressure-3db64b, [#535](https://github.com/c10dev/canon/pull/535)) · 계획: [plan.md](../plan.md) 의 11번 · 먼저: —

## 목표

설정 도우미가 인물마다 버릇 하나와 대사 예시 한 줄을 만들지 않는다.
대신 인물이 무엇을 지키려 하고, 흔들리면 어디로 가는지(압력)를 적는다.
쓰기 요청의 인물 블록에 압력이 들어가고, 모델이 같은 버릇 · 대사를 장면마다 되풀이할 재료가 줄어든다.
이 일감은 [README.md](../README.md) 정한 규칙의 2026-11-14 줄(정할 것 16 · 17 · 18)을 따른다.
이야기 틀과 상관없이 모든 작품에 닿는다.

일감을 셋으로 나눈다.

| 부분 | 하는 일 | 상태 |
|---|---|---|
| 11a | 새 칸, 설정 프롬프트, 인물 블록에 넣기, 화면 칸, 실측 묶음 준비 | 진행 |
| 11b | 인물 화면의 '압력으로 다시 쓰기' 제안 카드: 이미 있는 버릇 문장 · 대사 예시를 압력으로 옮기는 AI 제안, 작가가 고름 | 설계 |
| 11c | 쓰기 요청의 인물 블록(`cast_view`)에서 이미 있는 대사 예시 · 버릇을 뺄지 정하고 고침 | 실측 결과를 작가가 본 뒤 |

## 정할 것

정한 것: 셋 모두 추천안으로 진행(2026-11-14). 사용자가 '추천안대로 병행 진행'을 골랐다.

1. (정함, 정할 것 16) '압력'은 새 칸 `Character.pressure` 로 둔다. `personality` 설명에서 '버릇 하나'를 뺀다.
2. (정함, 정할 것 17) 기존 작품의 버릇 문장 · 대사 예시는 자동으로 옮기지 않는다. 인물 화면에 '압력으로 다시 쓰기' 제안 카드를 두고 작가가 고른다(11b). 작가가 이미 손본 작품 하나는 건드리지 않는다.
3. (정함, 정할 것 18) 대사 예시 한 줄은 새로 만드는 인물에는 요구하지 않는다. 이미 있는 예시는 남긴다. 인물 블록에서 뺄지는 실측으로 정한다(11c).

남은 질문(11c 를 시작하기 전):

1. 실측에서 판 B(버릇 · 대사 예시를 빼고 압력을 넣은 인물 블록)가 낫거나 같으면, 인물 블록에서 대사 예시만 뺄까요, 버릇 문장도 뺄까요? — 추천: 실측 결과를 보고 정한다. 대사 예시는 `speech_style` 안의 따옴표 글이라 프로그램이 뺄 수 있지만, 버릇은 `personality` 의 한 문장이라 프로그램이 가려낼 수 없다. 버릇은 11b 의 작가 다시 쓰기로 옮기는 쪽이 맞다.

## 데이터 · 스키마

- `Character.pressure: str = ""`. 자리는 `wound` 바로 뒤다. 옛 `project.json` 은 고치지 않고 읽힌다.
- 설명: '안에서 미는 압력 한두 문장: 무엇을 지키려 하는가, 흔들리면 어디로 가는가'.
- `Character` 를 담는 모든 응답 형식(설정 제안, 설정 대화의 새 인물, 플롯 · 아크 · 상태 변경안의 새 인물)에 칸이 생긴다. 글 칸이라 dict 가 아니다(`tests/test_schema_nodict.py`).
- `BirthSketch.pressure: str = ""`.
- 압력은 `SettingField`(상태 변경안의 설정 바꾸기)와 `charlog.FIELDS` 에 넣지 않는다. 상태 변경안 프롬프트가 바뀌는 일이라 11a 밖이다. 작가가 고친 압력은 `charlog.LOG_FIELDS` 로 설정 변경 기록에 남는다.

## 규칙

- 압력을 적지 않은 인물은 프롬프트에 `pressure` 칸이 생기지 않는다(`_prompt_view`, `cast_view`, `setup_chat_prompt`). 압력을 적지 않은 작품의 쓰기 요청은 칸을 더하기 전과 글자까지 같다.
- 압력을 적은 인물은 앞 블록 '# 인물 설정'에 `wound` 다음 칸으로 들어간다. 바뀌지 않는 블록이라 캐시 차례는 그대로다.
- 승인 흐름은 그대로다. 설정 제안 · 설정 대화 · 아이디어 후보는 작가가 골라 적용한다. 빈칸 제안은 비어 있는 압력만 채우고 작가가 적은 압력을 덮지 않는다.
- 대화 에이전트의 설정 쓰기는 지금 권한 모드를 그대로 따른다. 압력은 설정 대화의 다른 인물 칸과 같다.
- 단편 · 장편 모두 같은 규칙이다.

| `FIELD_IDEAS` 압력 | 새 칸 '무엇을 지키려 하는지, 흔들리면 어디로 가는지를 한두 문장으로' | 정할 것 16 |

- '대사 예시를 넣지 않는다' 같은 새 금지는 넣지 않았다. 정한 것은 '요구하지 않는다'이고 금지가 아니다(editing.md 0.1). 금지를 더할지는 작가가 정한다.
- 원형 굴리기의 말투 틀(`archetypes.speech_text`)에는 도감 예시 대사가 그대로 있다. 도감 글이라 이 일감에서 고치지 않는다.

## 화면 · 명령줄 · 프롬프트

- 설정 도우미 인물 줄의 '더 자세히'(기본 접힘)에 '압력' 칸을 둔다. 요약 줄은 '더 자세히: 성격, 압력, 배경, 외모, 아크'.
- 칸에는 도움말 문장을 달지 않고 칸 안 예시 글만 둔다: '지키려는 것, 흔들리면 가는 곳'. 늘 보이는 안내 문장 수는 그대로다(`docs/design/README.md` '덜기').
- 아이디어 버튼(`charIdeaInput`)이 붙는다. 인물 카드의 설정 칸 목록(`SHEET_SETTING`)과 명령줄 `cast` 출력에 압력이 보인다.
- 새 블록은 없다. 예산(`context.BUDGET`)은 바뀌지 않는다. 압력은 인물 블록 안의 한 칸이다.
- 작업지시서(`brief`)도 같은 함수를 쓴다. 응답 형식이 든 작업지시서는 `Character` 스키마의 새 칸만큼 바뀐다.

## 시험

- `tests/test_char_pressure.py`
  - 옛 작품이 압력 없이 읽히고 프롬프트 직렬화에 칸이 없다.
  - 모든 압력이 빈 작품의 앞 블록 · 쓰기 요청이 칸을 더하기 전 `cast_view` 로 만든 글과 같다.
  - 압력을 적은 인물만 앞 블록에 들어가고, 플롯보다 앞이다.
  - 설정 · 출생 · 설정 대화 프롬프트가 압력을 적게 하고 버릇 하나 · 대사 예시 한 줄을 요구하지 않는다.
  - 빈칸 제안이 작가가 적은 압력을 덮지 않는다. 설정 대화 변경안 · 무작위 출생이 압력을 옮긴다.
- 스냅샷(`prompt_registry`, `char_context_auto`)이 바뀐 까닭
  - 시험 작품을 만드는 가짜 설정 제안이 주인공 압력을 채운다. 그래서 인물 블록이 든 요청이 그 한 줄만큼 바뀐다.
  - 응답 형식이 든 작업지시서는 `Character` 스키마에 압력 칸이 생긴 만큼 바뀐다.
  - 설정 대화 요청은 칸 목록 줄이 바뀐다.
  - 가짜 설정 제안의 대사 예시는 남겼다. 옛 작품의 말투 예시 경고(`style_drift`)를 시험이 계속 지나게 하려는 것이다.

## 실측 (11c 의 근거, 작가 판정)

[plan.md](../plan.md) 실측 계획의 11 줄을 따른다.

- 같은 화를 두 판으로 2편씩 쓴다. 판 A 는 지금 인물 블록, 판 B 는 버릇 문장 · 대사 예시를 빼고 압력을 넣은 인물 블록이다.
- 판 B 의 인물 블록은 실험 스크립트 안에서만 바꾼다. 작품은 임시 `CANON_HOME` 사본을 쓰고 사용자 작품은 바꾸지 않는다.
- 판 B 의 압력 문장은 실험용 초안이다. 작가의 글이 아니다.
- AI 없이 세는 것: 버릇 · 대사 예시 문장이 본문에 나온 횟수.
- 글 4편과 같은 글 한 쌍을 가려 읽기 묶음으로 만든다. 묶음과 정답 열쇠는 `reports/` 아래 따로 둔다(커밋하지 않음).

## 확인하지 못할 것

- 실제 모델이 압력 칸을 어떻게 채우는지는 설정 제안을 실호출해야 안다. 이 일감은 쓰기 쪽 실측만 한다.
- 판 A · B 중 어느 쪽 글이 나은지는 작가의 가려 읽기로만 정한다.

사용자가 할 단계:

1. 실측 묶음을 블라인드 화면에 넣고 가려 읽기 점수를 준다.
2. 결과를 보고 남은 질문 1(11c)을 정한다.
3. 기존 작품의 압력을 직접 적거나, 11b 가 들어간 뒤 제안 카드로 옮긴다.
