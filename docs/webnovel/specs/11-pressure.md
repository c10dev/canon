# 11. 인물 카드를 '표현'에서 '압력'으로

상태: 진행 (11a [#535](https://github.com/c10dev/canon/pull/535) 머지, 11b claude/pressure-card-d19767, 11c 남음) · 계획: [plan.md](../plan.md) 의 11번 · 먼저: —

## 목표

설정 도우미가 인물마다 버릇 하나와 대사 예시 한 줄을 만들지 않는다.
대신 인물이 무엇을 지키려 하고, 흔들리면 어디로 가는지(압력)를 적는다.
쓰기 요청의 인물 블록에 압력이 들어가고, 모델이 같은 버릇 · 대사를 장면마다 되풀이할 재료가 줄어든다.
이 일감은 [README.md](../README.md) 정한 규칙의 2026-11-14 줄(정할 것 16 · 17 · 18)을 따른다.
이야기 틀과 상관없이 모든 작품에 닿는다.

일감을 셋으로 나눈다.

| 부분 | 하는 일 | 상태 |
|---|---|---|
| 11a | 새 칸, 설정 프롬프트, 인물 블록에 넣기, 화면 칸, 실측 묶음 준비 | 끝 ([#535](https://github.com/c10dev/canon/pull/535)) |
| 11b | 인물 화면의 '압력으로 다시 쓰기' 제안 카드: 이미 있는 버릇 문장 · 대사 예시를 압력으로 옮기는 AI 제안, 작가가 고름 | 끝 (claude/pressure-card-d19767) |
| 11c | 쓰기 요청의 인물 블록(`cast_view`)에서 이미 있는 대사 예시 · 버릇을 뺄지 정하고 고침 | 실측 결과를 작가가 본 뒤 |

## 정할 것

정한 것: 셋 모두 추천안으로 진행(2026-11-14). 사용자가 '추천안대로 병행 진행'을 골랐다.

1. (정함, 정할 것 16) '압력'은 새 칸 `Character.pressure` 로 둔다. `personality` 설명에서 '버릇 하나'를 뺀다.
2. (정함, 정할 것 17) 기존 작품의 버릇 문장 · 대사 예시는 자동으로 옮기지 않는다. 인물 화면에 '압력으로 다시 쓰기' 제안 카드를 두고 작가가 고른다(11b). 작가가 이미 손본 작품 하나는 건드리지 않는다.
3. (정함, 정할 것 18) 대사 예시 한 줄은 새로 만드는 인물에는 요구하지 않는다. 이미 있는 예시는 남긴다. 인물 블록에서 뺄지는 실측으로 정한다(11c).

남은 질문(11c 를 시작하기 전):

1. 실측에서 판 B(버릇 · 대사 예시를 빼고 압력을 넣은 인물 블록)가 낫거나 같으면, 인물 블록에서 대사 예시만 뺄까요, 버릇 문장도 뺄까요? — 추천: 실측 결과를 보고 정한다. 대사 예시는 `speech_style` 안의 따옴표 글이라 프로그램이 뺄 수 있지만, 버릇은 `personality` 의 한 문장이라 프로그램이 가려낼 수 없다. 버릇은 11b 의 작가 다시 쓰기로 옮기는 쪽이 맞다.

## 데이터 · 스키마

- `Character.pressure: str = ""`. 자리는 `wound` 바로 뒤다. 옛 `project.json` 은 고치지 않고 읽힌다.
- 설명: '안에서 미는 압력 한두 문장: 무엇을 지키려 하는가, 흔들리면 어디로 가는가'.
- `Character` 를 담는 모든 응답 형식(설정 제안, 설정 대화의 새 인물, 플롯 · 아크 · 상태 변경안의 새 인물)에 칸이 생긴다. 글 칸이라 dict 가 아니다(`tests/test_schema_nodict.py`).
- `BirthSketch.pressure: str = ""`.
- 압력은 `SettingField`(상태 변경안의 설정 바꾸기)와 `charlog.FIELDS` 에 넣지 않는다. 상태 변경안 프롬프트가 바뀌는 일이라 11a 밖이다. 작가가 고친 압력은 `charlog.LOG_FIELDS` 로 설정 변경 기록에 남는다.

## 규칙

- 압력을 적지 않은 인물은 프롬프트에 `pressure` 칸이 생기지 않는다(`_prompt_view`, `cast_view`, `setup_chat_prompt`). 압력을 적지 않은 작품의 쓰기 요청은 칸을 더하기 전과 글자까지 같다.
- 압력을 적은 인물은 앞 블록 '# 인물 설정'에 `wound` 다음 칸으로 들어간다. 바뀌지 않는 블록이라 캐시 차례는 그대로다.
- 승인 흐름은 그대로다. 설정 제안 · 설정 대화 · 아이디어 후보는 작가가 골라 적용한다. 빈칸 제안은 비어 있는 압력만 채우고 작가가 적은 압력을 덮지 않는다.
- 대화 에이전트의 설정 쓰기는 지금 권한 모드를 그대로 따른다. 압력은 설정 대화의 다른 인물 칸과 같다.
- 단편 · 장편 모두 같은 규칙이다.

## 화면 · 명령줄 · 프롬프트

- 설정 도우미 인물 줄의 '더 자세히'(기본 접힘)에 '압력' 칸을 둔다. 요약 줄은 '더 자세히: 성격, 압력, 배경, 외모, 아크'.
- 칸에는 도움말 문장을 달지 않고 칸 안 예시 글만 둔다: '지키려는 것, 흔들리면 가는 곳'. 늘 보이는 안내 문장 수는 그대로다(`docs/design/README.md` '덜기').
- 아이디어 버튼(`charIdeaInput`)이 붙는다. 인물 카드의 설정 칸 목록(`SHEET_SETTING`)과 명령줄 `cast` 출력에 압력이 보인다.
- 새 블록은 없다. 예산(`context.BUDGET`)은 바뀌지 않는다. 압력은 인물 블록 안의 한 칸이다.
- 작업지시서(`brief`)도 같은 함수를 쓴다. 응답 형식이 든 작업지시서는 `Character` 스키마의 새 칸만큼 바뀐다.

## 11b: '압력으로 다시 쓰기' 제안 카드

이미 있는 인물의 버릇 문장(`personality` 안)과 대사 예시(`speech_style` 안의 따옴표 글)를 압력(`pressure`)으로 옮기는 AI 제안이다.
정할 것 17 을 따른다: 자동으로 옮기지 않고, 작가가 인물 화면에서 칸마다 고른다.

### 정할 것 (추천안으로 진행, 2026-11-15)

이 세션을 시작한 세션이 '정할 것은 추천안으로 진행하고 그렇게 적는다'고 맡겼다. 아래 넷은 사용자와 정한 규칙이 아니다.

1. 지우는 글은 누가 고르나? — 추천: 대사 예시는 프로그램이, 버릇 문장은 AI 가 고른다. AI 는 고른 문장을 `personality` 에서 글자 그대로 옮기고, 프로그램이 원문에서 찾은 문장만 뺀다. 남은 글은 작가가 쓴 글 그대로다. AI 가 `personality` · `speech_style` 을 새로 쓰지 않는다.
2. 대사 예시의 기준은? — 추천: 말투 예시 경고(`metrics.speech_examples`)와 같은 따옴표 규칙을 쓴다. '말버릇 "…"' · '입버릇 "…"' 은 남긴다. 따옴표 뒤가 '라고' · '이라고' · '라 부' · '로 부' · '하고 부'로 이어지면 호칭이라 남긴다.
3. 설정 변경 기록은 어떻게 남기나? — 추천: 새 라우트 없이 화면 저장으로 남긴다. 적용은 화면 안 작품 값만 바꾸고, 작가가 저장하면 `charlog.record_author` 가 `LOG_FIELDS`(성격 · 말투 · 압력) 작가 기록으로 남긴다. 1화를 반영하기 전에는 다른 설정 고치기처럼 기록하지 않는다. `charlog.FIELDS`(AI 가 바꾸자고 할 수 있는 칸)는 그대로다.
4. 버튼은 어디에 두나? — 추천: 인물 쪽 '설정' 카드 머리. 마지막 시점이고, 성격이 있거나 말투에 대사 예시가 있을 때만 보인다. 제안 카드는 설정 카드 안 칸 목록 아래에 놓인다.

- `PressureRewrite`: `pressure: str`, `habits: list[str]`, `note: str`. dict 칸이 없다(`tests/test_schema_nodict.py`).
- `habits` 는 `personality` 에서 버릇을 적은 문장을 글자 그대로 옮긴 것이다. 없으면 빈 목록이다.

### 화면

- 설정 카드 머리에 작은 버튼 '압력으로 다시 쓰기'(작업 버튼, 도는 동안 잠김). 늘 보이는 안내 문장은 더하지 않는다.
- 제안 카드(`.proposal`)는 칸 셋을 줄마다 보인다: 압력(지금 → 제안), 성격(뺄 문장에 줄 긋기 → 남는 글), 말투(뺄 대사 예시에 줄 긋기 → 남는 글).
- 체크는 모두 기본으로 꺼져 있다. 신체 프로필 제안과 달리 빈 압력도 고르지 않은 채로 둔다.
- 바뀌는 것이 없는 칸(뺄 글이 없음, 제안이 지금과 같음)은 줄을 그리지 않는다.
- 작업이 도는 동안 작가가 그 칸을 고쳤으면(지금 값이 `*_before` 와 다름) 그 줄은 고를 수 없고 '그 뒤 고친 칸이라 적용하지 않아요'를 보인다.
- '고른 칸 적용'은 화면 안 인물 값을 바꾸고 저장하지 않은 상태로 둔다. 알림은 'n칸을 적용했어요. 저장하면 남아요'.

### 규칙

- 제안은 작업 `char_pressure` 로만 만든다. 자동 집필(`autorun.py`)과 명령줄(`cli.py`, `-y`)은 부르지 않는다.
- 작업은 저장하지 않는다(`test_character_jobs_return_drafts_without_saving` 와 같음).
- 사용자 작품 '비밀-계정이-나한테만-보인다'를 따로 다루는 코드는 없다. 작가가 버튼을 누르지 않으면 아무 작품도 바뀌지 않는다(정할 것 17).
- 단계는 `plan` 이다(`get_llm("plan")`, 신체 프로필 제안과 같다).

### 시험

- `tests/test_pressure_rewrite.py`
  - `lines` 가 대사 예시를 찾고 말버릇 · 호칭 따옴표는 남긴다.
  - `cut` 이 대사 예시 앞 '예:' 와 남는 빈칸 · 문장부호를 함께 지운다.
  - 원문에 없는 버릇 문장은 버리고 `dropped` 로 센다.
  - 응답 스키마에 dict 칸이 없고, 가짜 LLM 으로 만든 제안이 작품을 바꾸지 않는다.
  - 프롬프트가 압력 줄과 버릇 줄을 담고, 지금 압력을 보인다.
  - 1화를 반영한 작품에서 제안 값을 적용해 저장하면 설정 변경 기록에 성격 · 말투 · 압력 작가 기록이 남는다.
  - `autorun.py` · `cli.py` 가 `suggest_pressure` · `char_pressure` 를 부르지 않는다.
- `tests/test_ai_jobs.py` 의 작업 목록에 `char_pressure` · `pressureAI`.

## 실측 (11c 의 근거, 작가 판정)

[plan.md](../plan.md) 실측 계획의 11 줄을 따른다.

- 같은 화를 두 판으로 2편씩 쓴다. 판 A 는 지금 인물 블록, 판 B 는 버릇 문장 · 대사 예시를 빼고 압력을 넣은 인물 블록이다.
- 판 B 의 인물 블록은 실험 스크립트 안에서만 바꾼다. 작품은 임시 `CANON_HOME` 사본을 쓰고 사용자 작품은 바꾸지 않는다.
- 판 B 의 압력 문장은 실험용 초안이다. 작가의 글이 아니다.
- AI 없이 세는 것: 버릇 · 대사 예시 문장이 본문에 나온 횟수.
- 글 4편과 같은 글 한 쌍을 가려 읽기 묶음으로 만든다. 묶음과 정답 열쇠는 `reports/` 아래 따로 둔다(커밋하지 않음).
