# 03. 로그라인 웹소설 칸

상태: 진행 ([#537](https://github.com/c10dev/canon/pull/537)) · 계획: [plan.md](../plan.md) 의 3번 · 먼저: 1

## 목표

이야기 틀이 웹소설식(`Meta.frame = "webnovel"`)인 작품은 로그라인을 웹소설 칸으로 쓴다: 누가 · 무엇 때문에 · 무엇을 하려 하나 · 주인공만 가진 것 · 독자가 받는 재미.
막는 것 · 걸린 것은 접어 두고 적었을 때만 문장 뒤에 붙인다.
드라마식(기본) 작품은 화면, 합친 문장, 점검, 프롬프트 글이 지금과 글자까지 같다.
[README.md](../README.md) 의 2026-11-14 규칙(이야기 틀, 정할 것 4)을 따른다.

## 정할 것

1. 웹소설 로그라인 다섯 칸을 '누가 · 무엇 때문에 · 무엇을 하려 하나 · 주인공만 가진 것 · 독자가 받는 재미'로 할까요? 막는 것 · 걸린 것은 접어서 선택으로. — 정함(2026-11-14: 추천안대로).
2. `Meta.logline` 설명('누가, 무엇을 원하고, 무엇이 막는가')을 틀과 상관없는 글로 바꿀까요? — 정함(이 명세서): 바꾸지 않는다. `Meta` 는 LLM 응답 형식에 들어가지 않고 프롬프트에도 설명이 나오지 않는다(`meta_text` 는 값만 덤프한다). 바꿔도 얻는 것이 없고, 화면 · 프롬프트 어디에도 보이지 않는다.
3. 새 칸 설명을 설정 대화 · 아이디어 칸 프롬프트에 늘 넣을까요, 웹소설 틀에서만 넣을까요? — 정함(이 명세서): 웹소설 틀에서만. 아래 '프롬프트' 절의 근거.

## 데이터 · 스키마

- `LoglineParts.edge: str = ""` 주인공만 가진 것.
- `LoglineParts.appeal: str = ""` 독자가 받는 재미.
- 옛 `project.json` 은 고치지 않고 읽힌다.
- `Meta` 와 `LoglineParts` 는 LLM 응답 형식에 들어가지 않는다. `Genre.logline` 은 화면 예시라 프롬프트에 넣지 않는다.
- 설정 대화의 응답 형식 `SetupRevision` 은 칸 키를 `SetupEdit.key` 로 받는다.
  - 저장된 변경안(`ChatMessage.setup` · `AgentTurn.setup`)은 새 키도 읽혀야 한다. 저장 검사는 모든 키를 받는다.
  - 드라마 틀 응답 형식(JSON 스키마)은 지금 키 목록 그대로 보인다(`WithJsonSchema`). 작업지시서의 응답 형식 글과 스냅샷이 바뀌지 않는다.
  - 웹소설 틀은 새 키를 더한 `SetupRevisionWeb` 을 응답 형식으로 보낸다. 받은 답은 `SetupRevision` 으로 옮겨 저장한다.

## 규칙

### 칸

| 틀 | 보이는 칸(차례대로) | 접은 칸 |
|---|---|---|
| 드라마식 | 누가 · 무엇 때문에 · 무엇을 하려 하나 · 무엇이 막나 · 무엇이 걸렸나 | 없음 |
| 웹소설식 | 누가 · 무엇 때문에 · 무엇을 하려 하나 · 주인공만 가진 것 · 독자가 받는 재미 | 무엇이 막나 · 무엇이 걸렸나(선택) |

- 틀을 바꿔도 칸 값은 지우지 않는다. 드라마 틀에서는 새 칸 둘이 보이지 않을 뿐 값은 남고, 틀을 되돌리면 그대로 보인다.
- 비었는지(`is_empty`)는 그 틀이 쓰는 칸만 본다. 드라마 틀 작품에 새 칸 값만 남아 있으면 비었다고 본다.

### 합치기

- 드라마식: `{누가}이/가 {무엇 때문에} {목표}. 하지만 {막는 것}. {걸린 것}.` 지금과 같다.
- 웹소설식: `{누가}이/가 {무엇 때문에} {목표}. {주인공만 가진 것}. {독자가 받는 재미}. 하지만 {막는 것}. {걸린 것}.`
- 빈 칸은 건너뛴다. 새 칸 둘은 '~다'로 끝나는 한 문장으로 쓴다(아이디어 칸 쓰는 법).
- 새 칸 둘이 비면 웹소설식 문장은 드라마식 문장과 같다. 드라마 틀 작품을 웹소설 틀로 바꿔도 새 칸을 쓰기 전에는 문장이 그대로다.

예시(장르 예시의 다섯 칸, `compose(…, "webnovel")`):

1. 라이트노벨: 게임 폐인 대학생이 직접 만든 게임 속 엑스트라로 들어가 메인 히로인의 배드엔딩을 막는다. 게임을 만든 그만 모든 분기와 엔딩을 안다. 엔딩을 하나 바꿀 때마다 그만 아는 숨은 길이 열린다.
2. 회귀: 멸망한 세계의 마지막 생존자가 죽는 순간 10년 전으로 돌아가 멸망의 원인을 먼저 없앤다. 그는 앞으로 10년 동안 일어날 일을 모두 안다. 아는 미래로 앞질러 움직일 때마다 전생의 후회를 하나씩 바로잡는다.
3. 시스템: 은퇴를 앞둔 하급 마법사가 자신만 스킬 창을 볼 수 있다는 걸 알게 되자 버려진 스킬을 모아 탑의 꼭대기에 오른다. 스킬 창은 그의 눈에만 보인다. 스킬을 합칠 때마다 숨은 직업이 하나씩 열린다.
4. 막는 것을 적은 경우: 위 1 에 '게임은 원래 시나리오대로 흘러가려 한다'를 적으면 끝에 ' 하지만 게임은 원래 시나리오대로 흘러가려 한다.' 가 붙는다.

### 점검

| 드라마식(지금과 같음) | 웹소설식 |
|---|---|
| 주인공에게 이름 말고 특징이 있어요 | 같음 |
| 이야기를 시작하게 만드는 일이 있어요 | 같음 |
| 목표가 눈에 보이는 행동이에요 ('~한다'로 끝나요) | 같음 |
| 목표를 막는 사람이나 힘이 있어요 | 주인공만 가진 것이 있어요 |
| — | 독자가 받는 재미가 있어요 |
| 길이가 40~150자 사이예요 | 같음 |

- 점검은 참고용이고 다음 단계를 막지 않는다(지금과 같음).

### 틀을 바꿀 때 합친 문장

- 합친 문장이 바꾸기 전 틀로 칸을 합친 문장과 같으면 새 틀로 다시 합친다.
- 직접 고친 문장, 칸 없이 문장만 있는 옛 작품은 그대로 둔다(칸을 고칠 때와 같은 규칙).
- 다시 합친 결과가 빈 글이면 바꾸지 않는다.

### 설정 대화

- 적용할 때 다시 합치기(`_recompose`)는 바꾸기 전 문장을 바꾸기 전 틀로 견주고, 새 문장은 지금 틀로 합친다.
- 적용 취소는 지금 문장을 지금 틀로 견주고, 칸을 되돌린 뒤 지금 틀로 다시 합친다. 칸이 적용 전과 같아지면 적용 전 문장을 그대로 돌린다(지금 규칙).
- 대화 에이전트의 설정 카드는 같은 `setupchat` 을 쓴다. 권한 모드는 바뀌지 않는다.

### 장르 예시

- 웹소설 틀을 권하는 장르(`Genre.frame == "webnovel"`: 현대 판타지 · 판타지 · 무협 · 라이트노벨 · 회귀 · 빙의 · 하렘 · 시스템)의 예시 둘에 새 칸 둘을 채운다.
- 지금 다섯 칸은 바꾸지 않는다. 드라마 틀 화면의 예시 문장이 그대로다.
- 새 칸 글은 그 예시의 다른 칸과 그 장르의 `summary` · `reader_expects` 에서 가져온다. 라이트노벨 · 하렘 · 시스템은 걸린 것 칸에 이미 보상 글이 있어 그 글을 독자가 받는 재미로 옮겨 적는다.
- 그래서 몇 예시는 주인공만 가진 것이 무엇 때문에 · 목표 칸과 겹친다(라이트노벨 1, 시스템 1 · 2, 하렘 2). 다섯 칸을 바꾸면 드라마 틀 화면이 바뀌므로 두었다.
- 시스템 1 은 같은 창을 받은 사람이 여럿이라(막는 것 칸) 주인공에게만 있는 것이 예시 안에 없다. 목표 칸을 다시 적었다.
- 판타지 2 의 '옛 동료들을 가장 가까이서 본 사람'은 '용사 파티에서 쫓겨난 짐꾼'에서 미루어 적은 말이다.
- 웹소설 틀 화면의 예시 문장과 '이 예시로 채우기'는 그 틀의 보이는 다섯 칸만 쓴다. 드라마 틀은 지금처럼 다섯 칸만 쓴다. 다른 칸 값은 그대로 둔다.

## 화면 · 명령줄 · 프롬프트

### 화면

- 설정 화면과 마법사의 로그라인 칸이 틀을 따른다. 웹소설 틀은 새 칸 둘이 목표 칸 뒤에 서고, 막는 것 · 걸린 것은 `<details>` '더 쓰기: 무엇이 막나 · 무엇이 걸렸나 (선택)'에 접는다. 둘 중 하나라도 적었으면 펼쳐 둔다.
- 기본 정보의 이야기 틀 버튼을 누르면 로그라인 칸이 바로 다시 그려진다(`loglineFrameChanged`).
- 늘 보이는 안내 문장은 늘지 않는다. 칸 이름과 칸 힌트만 바뀐다(`tests/test_copy_count_js.py`).
- 찾기(`palette.js`)는 그 틀에 있는 칸만 보인다. 웹소설 틀에서 접힌 칸을 고르면 접힌 칸을 펼치고 간다.
- `docs/design/` 은 고치지 않는다. 새 컴포넌트 · 색 · 간격이 없다(이미 있는 `details`, `slot`).
- `home.js` 의 `FRAME_WHY` 는 '아크와 플롯 기획은 아직 이 값을 따르지 않아요'라고 말한다. 로그라인은 이제 따르지만 일감 4 세션이 같은 줄을 고치는 중이라 이 일감은 고치지 않는다(남은 일).

### 명령줄

- `new -i --frame webnovel` 은 웹소설 칸 다섯과 막는 것 · 걸린 것(선택)을 묻는다. 예시 · 합친 문장 · 점검도 웹소설 틀로 보인다.
- `--frame` 이 없으면 지금 물음 그대로다.

### 프롬프트

- 바뀌는 요청은 둘이다: 설정 대화(`setup_chat_prompt`)와 칸 하나 아이디어(`field_prompt`). 둘 다 웹소설 틀 작품에서만 글이 달라진다.
- 설정 대화 `edits` 키 줄: 웹소설 틀이면 `logline.goal` 뒤에 `logline.edge 주인공만 가진 것(…)` · `logline.appeal 독자가 받는 재미(…)` 를 넣고, `logline.block` · `logline.stake` 에 '(선택)'을 단다. 드라마 틀은 지금 줄 그대로다.
- 로그라인 덤프(`[로그라인 다섯 칸]`)는 그 틀이 쓰는 칸만 넣는다(`logline_view`). 드라마 틀은 지금처럼 다섯 칸이다. 드라마 틀 작품에 새 칸 값이 남아 있어도 덤프는 같다.
- `FIELD_IDEAS` 에 새 칸 둘의 쓰는 법을 더한다. 이 칸은 웹소설 틀 화면에만 있어 드라마 틀 작품의 요청이 되지 않는다.
- 늘 넣지 않는 근거: 설정 대화의 요청 글과 응답 형식은 작업지시서 갈래 `setup_chat` 로 프롬프트 해시 스냅샷에 들어 있다. 늘 넣으면 드라마 틀 작품의 글이 바뀐다(정할 것 3).
- 설정 대화의 응답 형식도 틀을 따른다: 드라마 틀은 지금 스키마, 웹소설 틀은 새 키를 더한 스키마.
- 그래서 `tests/test_frame.py` 의 `test_frame_stays_out_of_every_request` 에 틀이 바꾸는 요청 목록(`FRAME_CHANGES`)을 적는다: `brief:setup_chat`. 시험은 목록 밖 요청만 스냅샷과 같은지 보고, 목록 안 요청은 드라마 틀에서 스냅샷과 같고 웹소설 틀에서 다른지 본다.
- 문장 출처(`docs/prompts/editing.md` 0.1 · 0.6):
  - 칸 이름 '주인공만 가진 것' · '독자가 받는 재미': 사용자 결정(정할 것 4, 2026-11-14).
  - 괄호 안 예 '회귀 지식, 혼자만 보이는 상태창' · '사이다, 성장, 하렘': 일감을 맡긴 세션의 배경 글(사용자와 정한 웹소설 일감 묶음의 설명).
  - '(선택)': 사용자 결정 '막는 것 · 걸린 것은 접어서 선택으로'.
  - 아이디어 칸 쓰는 법의 '한 문장, '~다'로 끝냄'과 예: 지금 막는 것 · 걸린 것 칸의 쓰는 법과 같은 꼴, 예는 라이트노벨 장르 예시의 글.
