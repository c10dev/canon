# 13. 문체 다듬기 결과의 혼잣말 거르기

상태: 진행 (claude/style-revision-junk) · 계획: [plan.md](../plan.md) 의 13번 · 먼저: —

## 목표

대화로 문체를 다듬을 때 모델이 값 안에 남긴 혼잣말(`[Wait: …]`)과 버린 초안이 작품 문체 칸에 저장되지 않는다.
작가가 보는 변경안 카드에는 다시 쓴 글만 나온다.
LLM 을 부르지 않는 검사다. 프롬프트와 스키마는 바꾸지 않는다.

## 정할 것

없다. 이야기 틀과 상관없는 고침이고 [plan.md](../plan.md) 의 정할 것 1~20 에 걸리지 않는다.

## 본 것

- 문체 라이브러리 항목 하나(2026-11-10 에 작품 문체에서 올린 1번 버전)의 장치 '쓰는 상황' 칸에 두 번 남아 있다.
- 꼴은 둘이다: `버린 초안 [Wait: clean description below]다시 쓴 글`, `버린 초안][Wait - keep string clean]다시 쓴 글`.
- 두 번 모두 표시 뒤의 글이 온전한 값이었다.
- 같은 장치의 단서(`cues`)에는 `[` 로 시작하는 상태창 글이 있다. 대괄호를 모두 지우면 이 값이 깨진다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/pipeline.py` | `_META_NOTE` · `strip_meta` · `_strip_edit_meta` 를 더하고 `clean_style_revision` · `apply_style_edits` 가 부른다 |
| `tests/test_style_chat.py` | 표시 꼴, 지나가야 하는 대괄호, 칸별 거르기, 두 번 거르기, 옛 변경안 적용 · 취소 |
| `docs/modules/core.md` · `DESIGN.md` | `pipeline.py` 절과 '대화로 다듬기' 문단 |

## 규칙

- 표시는 대괄호 안이 영문 혼잣말 낱말(wait · note · hmm · actually · correction · self-correction · thinking · oops · retry · rewrite)로 시작하고 한글이 없는 것이다.
- 닫는 괄호가 없으면 그 줄 끝까지를 표시로 본다.
- 마지막 표시 뒤의 글을 남긴다. 그 글이 비면 가장 가까운 앞 글을 남긴다.
- 지우는 값은 모델이 지어 쓰는 것이다: 줄글 칸, 지킬 것 · 피할 것, 표지 쓰임, 장치 이름 · 상황, 까닭, 시험 문단.
- 두는 값은 원문을 그대로 옮기는 것이다: 금지 표현, 표지 글자, 장치 단서 · 예시, 시험 문단의 원래 대목.
- 지우고 나니 빈 줄글 칸은 변경안에서 뺀다. 빈 값으로 칸을 지우자는 제안이 되지 않게 한다.
- 적용할 때도 같은 거르기를 변경안에 바로 한다. 거르기 전에 대화에 남은 옛 변경안을 덮는다.
- 표시가 없는 글은 글자까지 그대로다. 두 번 걸러도 결과가 같다.
- 승인 흐름은 바뀌지 않는다. 변경안은 여전히 작가가 칸을 골라 적용한다.

## 하지 않는 것

- 이미 저장된 값은 고치지 않는다. 작가가 문체 화면에서 고친다.
- 문체 분석(`analyze_style`)과 수정에서 배우기(`learn_style`)의 결과에는 넣지 않는다. 그 경로에서 혼잣말이 나온 기록이 없다.
- 작가에게 '혼잣말을 지웠어요' 알림을 띄우지 않는다. `StyleRevision` 에 칸을 더해야 하는 일이다.
