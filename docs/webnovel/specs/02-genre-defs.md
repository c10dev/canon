# 02. 장르 정의: 라이트노벨 관습, 요소 장르 하렘 · 시스템

상태: 진행 (claude/genre-webnovel) · 계획: [plan.md](../plan.md) 의 2번 · 먼저: —

## 목표

라이트노벨을 고른 작품의 장르 안내에서 매 화 지시('캐릭터마다 말버릇', '화마다 웃음 포인트')가 빠진다.
그 자리에 성장과 짧은 막힘 · 시원한 해결을 독자가 따라 읽는 것으로 적는다.
하렘 · 시스템을 요소 장르로 고를 수 있다.
현대 판타지의 피할 것에서 웹소설식과 부딪치는 '갈등 없이 이기기만 하는 전개'를 지운다.
LLM 을 부르지 않는다.
이야기 틀(`Meta.frame`, 일감 1)과 상관없이 장르를 고른 작품에 바로 들어간다.

## 정할 것

- 하렘 · 시스템을 요소 장르로 더하는 것은 사용자가 2026-11-14 에 이 일감을 요청하며 정했다("요소 장르 harem · system 더하기").
- plan.md 의 정할 것 5(하렘을 틀이 아니라 요소로)는 이 요청과 같은 쪽이다. README 의 정한 규칙에는 아직 옮기지 않았다.
- 장르 계수(`Genre.dynamics`)는 비워 둔다(정할 것 13).
- `modern_fantasy.avoid` 의 그 줄은 대체 문장 없이 지운다. 작가가 2026-11-14 에 정했다(세션 안 '준비나 대가 없이 거저 얻는 승리'를 받지 않음).

## 규칙

- 새 줄에 '화마다' · 'N화마다' · '한 번 이상' 같은 빈도 지시를 쓰지 않는다. README 'AI 느낌을 만드는 프롬프트'의 방향이다.
- 화수로 세는 고구마 · 사이다 규칙(1~3화)은 장르 글에 넣지 않는다. 틀이 가르는 일감 4 · 6 의 몫이다.
- 축을 나눈다: 공략 한 바퀴 · 위로 오르는 관계 · 짧은 오해는 `harem` 에만, 상태창 · 레벨업 규칙은 `system` 에만 둔다. `light_novel` 은 하렘을 전제하지 않는다.
- 이름에 `·` 을 넣지 않는다. `genres.parse` 가 `·` 로 자른다.

### 문장마다 출처

출처 '요구'는 README 의 '웹소설식 요구'(2026-11-10, 사용자 지적)다.

| 곳 | 문장 | 출처 |
|---|---|---|
| `light_novel.reader_expects` | 주인공의 성장과 막힌 것을 시원하게 푸는 장면 | 요구: 사이다를 자주, 성장이 축 |
| `light_novel.conventions` | 주인공이 막히는 구간은 짧게, 푸는 장면은 확실하게 | 요구: 고구마는 짧게, 사이다는 자주 |
| `light_novel.conventions` | 아크 하나가 목표, 짧은 막힘, 시원한 해결, 성장으로 한 바퀴 돈다 | 요구: 아크 하나는 보상 루프 한 바퀴. README 용어 '보상 루프' |
| `light_novel.pacing` | 장면 단위로 빠르게. 막힘은 짧게 끊고 해결과 성장으로 넘어간다 | 앞 문장은 그대로. 뒤 문장은 요구 |
| `light_novel.avoid` | 주인공이 오래 막혀 답답하기만 한 전개 | 요구: 고구마는 짧게 |
| `light_novel` 에서 뺀 줄 | 캐릭터마다 말버릇이나 특징을 분명히 · 화마다 웃음 포인트와 작은 사건 | plan.md 일감 2. README 'AI 느낌' 표의 원인 줄 |
| `modern_fantasy.avoid` 에서 뺀 줄 | 갈등 없이 이기기만 하는 전개 | README 장르 정의 표의 '어긋남'. 작가의 지우기 결정(2026-11-14) |
| `harem.conventions` | 아크 하나가 한 인물과 가까워지는 한 바퀴인 경우가 흔하다 | 요구: 하렘물이면 히로인 하나를 공략하는 한 바퀴가 흔하다 |
| `harem.conventions` | 관계는 주로 위로 오른다 · 균열은 짧은 오해로 두고 길게 끌지 않는다 | 요구: 하렘물의 관계는 주로 위로만 오른다. 균열은 짧은 오해다 |
| `harem.avoid` | 오해와 냉전이 길게 이어짐 | 요구: 균열은 짧은 오해 |
| `system.conventions` | 규칙을 초반에 정하고 지킨다 · 보상과 대가가 눈에 보이게 한다 | `modern_fantasy.conventions` 의 같은 줄 |
| `system.reader_expects` | 레벨업과 스킬 해금의 쾌감 | 요구: 성장(레벨업 · 해금 · 자신감)이 축 |
| `system` 초반 2화 | 상태창은 최소로 | `_OPENINGS["modern_fantasy"]` 의 같은 말 |

- `harem.avoid` 의 '인물이 주인공을 띄우는 장식으로만 쓰임'은 BL · GL 의 피할 것 '한 인물이 소품처럼 쓰임'과 같은 뜻이다.
- 위 표에 없는 요약 · 독자 기대 · 관습 · 소재 · 로그라인 예시 · 초반 박자는 다른 장르 항목과 같은 갈래의 장르 일반 지식이다. 작가가 정한 규칙이 아니다.
- `system.avoid` 에 '보상이 노력 없이 쏟아짐'을 넣지 않았다. 이 일감이 고치는 '갈등 없이 이기기만 하는 전개'와 같은 꼴이고 출처가 없다.

## 화면 · 명령줄 · 프롬프트

- 장르 안내(`genres.guide`)는 `static_context` 에 들어간다. 라이트노벨 · 현대 판타지를 고른 작품(단편 포함)은 이 블록이 바뀐다. plan.md 의 '기본값이면 글자까지 같다'의 예외다.
- 라이트노벨 · 현대 판타지를 고른 작품은 다음 요청에서 앞부분 캐시가 한 번 맞지 않는다.
- 다른 장르를 고른 작품의 프롬프트는 글자까지 같다(`test_untouched_genre_guides_stay_the_same`).
- 설정 화면의 장르 목록은 `/api/genres`(`genres.CATALOG`)를 읽으므로 새 요소가 저절로 나온다.
- `setup.js` 의 세계 추천 표(`WORLD_REC`)에는 두 요소를 넣지 않았다. 세계를 정하지 않는 소재다.
- 시스템 요소를 고른 작품은 설정 도우미 · 상태창 화면에 처음 수치 안내가 뜬다(`swWanted`).
- 범위 밖으로 남은 매 화 지시: `romance_fantasy.pacing`('화마다 작은 반전이나 응징'), `modern_fantasy.pacing`('화마다 작은 목표 달성'), `healing.pacing`('화마다 하나의 작은 이야기'). 뺄지는 따로 정한다.
- 남는 어긋남: `plot_rules` 의 '갈등은 너무 깔끔하게 정리하지 않습니다'는 라이트노벨 관습과 부딪친다. 일감 6 까지 남는다.

- `tests/test_genres.py` 의 `test_webnovel_elements`: 두 요소가 '요소'이고, 이름으로 고를 수 있고, 고른 작품의 안내에만 나온다.
- `test_no_per_episode_lines_in_webnovel_genres`: 라이트노벨 · 하렘 · 시스템 안내에 '말버릇' · '웃음 포인트' · '화마다'가 없다.
- `test_untouched_genre_guides_stay_the_same`: 나머지 장르 안내의 해시가 고치기 전과 같다.
- `tests/test_logline.py` 의 `test_genre_examples_pass_checks` 가 새 로그라인 예시도 점검한다.
