# 06. 화별 플롯 규칙을 이야기 틀별로

상태: 끝 ([#543](https://github.com/c10dev/canon/pull/543) 머지) · 계획: [plan.md](../plan.md) 의 6번 · 먼저: 4

## 목표

웹소설 틀(`Meta.frame = "webnovel"`)을 고른 장편은 화별 플롯 요청이 사이다를 깔끔하게 풀고 자주 두게 한다.
화 플롯에 '이 화의 사이다'(`EpisodePlot.reward`) 칸이 생겨 그 화에서 독자가 받는 보상을 한 줄로 적는다.
하렘 요소(`harem`)를 고른 장편은 화별 플롯 요청이 관계를 주로 위로 올리고 균열을 1~3화 안에 풀리는 오해로 둔다.
드라마 틀(기본)이고 하렘 요소가 없는 작품, 그리고 모든 단편은 요청 글과 응답 형식이 지금과 글자까지 같다.
[README.md](../README.md) 의 2026-11-14 규칙(이야기 틀, 하렘 요소, 일감 4 의 정할 것)을 따른다.

## 정할 것

사용자가 2026-11-15 에 남은 웹소설 일감을 진행하라고 했다. 아래 1~8 은 이 일감을 맡은 세션이 추천안으로 진행한 것이다. 작가가 PR 에서 확인하기 전에는 정한 규칙이 아니다.
3 은 plan.md 6번 줄과 작업을 맡긴 세션의 글 '2~3화마다 작은 보상'과 다르다. 실측은 화수를 넣은 글을 재지 않았다.

1. 단편에서 웹소설 틀을 고르면 화별 플롯도 가를까요? — 추천안으로 진행: 가르지 않는다. 장편만 가른다(`prompts.arc_axes` 와 같은 조건). 단편 기승전결(`arc_prompt`)의 틀별 줄과 함께 따로 본다(plan.md 정할 것 3 의 뒤 문장). 작업을 맡긴 세션도 단편 경로의 글을 바꾸지 말라고 했다.
2. 하렘 줄을 드라마 틀 장편에도 넣을까요? — 추천안으로 진행: 넣는다. 일감 4 의 정할 것 4 와 같다(하렘은 요소가, 보상 박자는 틀이 가른다).
3. '2~3화마다 작은 보상'을 화수 규칙으로 적을까요? — 추천안으로 진행: 화수로 적지 않는다. 화마다 `reward` 를 채우거나 비우는 사실로 적는다. 간격은 지금 장편 줄 '주인공이 막히는 구간은 2~3화를 넘기지 않고, 막힌 만큼 시원하게 푸는 화를 뒤에 둡니다' 가 이미 묶는다. 근거: 작가는 '몇 화에 한 번' 같은 빈도 규칙을 싫어한다(README 'AI 느낌', 2026-11-10). 요구 2 '사이다는 자주 둔다' 에 숫자가 없다(일감 4 의 '넣지 않은 것'). 사이다 없는 화가 이어지는지는 일감 7 의 경고가 `reward` 로 센다. 넣으려면 `PLOT_REWARD` 한 줄 앞에 '2~3화마다' 를 더한다.
4. 웹소설 틀에서 '주인공의 잘못된 선택' 과 '갈등은 너무 깔끔하게 정리하지 않습니다' 를 어떻게 할까요? — 추천안으로 진행: 둘 다 빼고 '막힌 것을 푸는 사이다는 깔끔하게 풉니다' 를 넣는다. README 조사 표가 이 두 말을 '어긋남'으로 적었다. 회상 · 시간 건너뛰기 · 곁가지 사건은 남긴다.
5. 일감 4 의 정할 것 11: 아크의 `gain` · `focus` 를 화별 플롯 요청에 넣을까요? — 추천안으로 진행: 장편 화별 플롯 초안(`serial_plot_prompt`)의 `[지금 부와 아크]` 에 넣는다. 축이 켜진 칸만 넣는다(웹소설 틀이면 `gain`, 하렘 요소면 `focus`). 본문 쓰기 · 검수 · 스토리보드에는 넣지 않는다. 웹소설 틀이면 '아크의 gain 은 아크 안 어느 화의 사건으로 보입니다' 한 줄을 더한다.
6. 초반 규칙과 초반 흡입력 판정의 '걸린 것' 을 어떻게 할까요? — 추천안으로 진행: 웹소설 틀 장편은 '걸린 것' 자리에 로그라인 웹소설 칸 '주인공만 가진 것' 을 쓴다. 판정 항목 이름 '걸린 것'(`schema.HookAspect`)은 두고 설명만 바꾼다. 설명은 잃을 수 있는 것도 남긴다.
7. 막히는 구간 화수(지금 `plot_rules` 의 2~3화, 아크 규칙 `ARC_SHORT_BLOCK` 의 1~3화)를 맞출까요? — 추천안으로 진행: `plot_rules` 의 줄을 두 틀 모두 그대로 둔다. README 조사 표가 이 줄을 '이미 웹소설'(바꾸지 않고 바탕으로 씀)로 적었다. 두 줄 모두 3화를 넘기지 않는다는 뜻이 같다.
8. 값이 찬 `reward` 를 본문 쓰기 · 검수 · 상태 변경안 · 스토리보드 요청에도 넣을까요? — 추천안으로 진행: 넣는다. 화 플롯의 다른 칸(엔딩 훅 등)처럼 플롯을 덤프하는 모든 요청에 들어간다. 조율 메모를 켜도 쓰기 재료 플롯에 남는다(`coord.plot` 은 summary · events · ending_hook 만 바꾼다). 근거: 그 화의 사이다는 본문이 실제로 보여야 하는 사건이다. 일감 4 의 `gain` · `focus`(아크 칸, 쓰기에서 뺌), 일감 10 의 표지(넣으면 장면마다 되풀이해 넣지 않음)와는 다르게 정했다. 빼려면 쓰기 쪽 플롯 덤프에서 `reward` 를 뺀다.

아래는 이 일감에서 정하지 않고 남긴 것이다.

9. 검수 프롬프트가 웹소설 틀에서 '갈등 부족'을 흠으로 보지 않게 할까요? — plan.md 장기 후보 그대로 둔다.
10. 스토리보드 · 큐 시트의 긴장 기호와 정점 규칙 — plan.md 장기 후보 그대로 둔다.
11. 다음 화 계획 줄의 '목표 / 갈등 / 보상' — 이 일감은 두었다. 플롯 규칙이 아니라 다음 화 계획 요청이다.

## 데이터 · 스키마

- `EpisodePlot.reward: SkipJsonSchema[str] = ""` — 이 화에서 독자가 받는 사이다 한 줄.
- 옛 `project.json` 은 고치지 않고 읽힌다. 빈 값은 저장 파일 · API · 프롬프트 어디에도 키가 생기지 않는다(`EpisodePlot` 의 직렬화).
- dict 칸은 없다.

### 응답 형식

- 저장 모델은 `reward` 를 응답 형식에서 뺀다. 칸을 늘 넣으면 드라마 틀의 `brief:plot` · `brief:plots` · `brief:agent_plot` 스냅샷이 바뀐다.
- 웹소설 틀 장편은 `schema.framed(형식, gain=True, …)` 가 만든 판으로 받는다. 일감 4 의 gain 축(`arc_axes` 의 첫째)을 그대로 쓴다. 판은 화 플롯에 `reward` 칸을 넣는다.
- 화 플롯이 든 형식(`PlotBatch` · `EpisodeDraft` · `PlotRevision` · `PlotAgentStep` · `ImpactReport` · `OpeningPlots`)은 `prompts.arc_schema` 를 거쳐 받는다. 작업지시서와 API 경로가 같은 판을 쓴다.
- 드라마 틀 · 단편이면 `framed` 는 원래 형식을 그대로 돌려준다.

## 규칙

- 이 작품의 응답 형식이 `reward` 를 묻지 않으면(드라마 틀, 틀을 드라마식으로 되돌린 작품) AI 가 다시 낸 화 플롯이 지금 화의 `reward` 를 지우지 않는다(`keep_unasked_plot`). 플롯 초안 다시 받기 · 한 화 플롯 · 플롯 대화 · 대화 에이전트 · 영향 분석 · 여는 방식 안이 모두 지킨다.
- 플롯 대화 · 대화 에이전트 · 영향 분석은 정리 단계(`clean_revision`)에서 채운다. 그래서 변경안 카드에 `reward` 가 지운 것으로 보이지 않고, `reward` 만 빠진 화는 바뀌지 않은 화로 빠진다.
- `reward` 는 값이 있으면 화 플롯을 덤프하는 모든 요청에 플롯의 한 칸으로 들어간다(정할 것 8). 엔딩 훅 칸이 들어가는 요청과 같다.
- 조율 메모를 만드는 요청(`coord_prompt`)은 summary · events · ending_hook 만 받아 `reward` 가 없다. 쓰기 요청의 플롯(`coord.plot`)에는 남는다.
- 관계 수치(`dynamics.py`)와 관계 단계 말은 바꾸지 않는다. 하렘 줄은 프롬프트 줄일 뿐이다.
- 틀을 바꿔도 이미 적은 화 플롯 칸은 그대로다. 확정 플롯 · 본문도 그대로다.

## 화면 · 명령줄 · 프롬프트

- 화 플롯 페이지 '끝과 이음' 의 엔딩 훅 아래에 '이 화의 사이다' 칸.
- 덜기(`docs/design/README.md`): 웹소설 틀 장편이거나 값이 있을 때만 보인다. 설명은 늘 보이는 글(`hint`)이 아니라 풍선(`help`)이다. 드라마 틀 작품의 화면은 늘 보이는 칸 · 안내 문장이 늘지 않는다. 버튼은 더하지 않았다.
- 플롯 대화 · 대화 에이전트의 칸별 비교(`PLOT_FIELDS`)는 바뀐 칸만 보이므로 `reward` 를 늘 목록에 둔다.
- 설정 화면의 이야기 틀 설명 풍선: '로그라인 칸, 장편의 부와 아크 기획과 화별 플롯은 이 값을 따라요.'
- 명령줄: `plot` · `arc` 들의 화 플롯 출력에 값이 있을 때만 '사이다:' 줄.
- 블록 자리는 바뀌지 않는다. 틀별 줄은 지금 요구사항 줄 자리에서 갈린다. 새 블록 · 예산은 없다.

## 실측

gemini-3.8-flash(계획 단계), 사용자 장편 사본 둘(임시 `CANON_HOME`), 화별 플롯 초안 3화씩. 호출 상한 8회를 모두 썼다. 기록: `/home/c10/canon/reports/plot-frame-2026-11-15/`.

- 웹소설 틀에서 `reward` 는 판마다 모두 차거나 모두 비었다(15화 중 12화, 다섯 판 중 네 판이 모두 참). 같은 요청 네 판 가운데 첫 판만 0/3 이었다.
- 찬 판은 보상이 약한 화(대화의 물꼬를 틈)에도 적었다. '그런 보상이 없는 화는 비웁니다' 로 화를 가르지 못했다.
- 비운 웹소설 판에도 15화는 연료 위기를 푸는 뚜렷한 보상 화였다. 칸을 비운 것이 보상이 없어서는 아니다.
- 장편 A 의 드라마 두 판은 14 · 15화에 차 열쇠 · 징발을 두고 대치를 이어 갔다. 웹소설 첫 두 판은 14 · 15화에 거래로 협력을 시작했다. 뒤 두 판은 줄거리를 견주지 않았다. 판이 적어 우연과 가르지 못한다.
- 장편 B 의 두 판(하렘 요소)은 세 화 모두 관계가 한 방향(저항 → 순응)으로 움직였고 균열이 없었다. 균열이 나오지 않아 '1~3화 오해' 줄의 효과는 재지 못했다.
- 형식 오류 · 출력 한도 걸림은 없었다.

## 확인하지 못할 것

- 작가가 웹소설 틀 화별 플롯을 받아 본문까지 쓴 뒤의 느낌(작가 취향 판단).
- 사이다 간격이 실제로 짧아지는지는 여러 아크를 짠 뒤에야 보인다. 일감 7 의 경고가 생기면 `reward` 빈 화가 이어지는 수로 잰다.
- 첫 웹소설 판이 `reward` 를 모두 비운 까닭은 재지 못했다. 그 판은 칸이 응답에 있었는지 적지 않았다. 후보: 응답 형식에서 `reward` 가 선택 칸이라 모델이 칸을 통째로 건너뜀. 판의 칸을 필수로 바꾸면(`framed` 의 `Field(...)`) 다른 백엔드가 칸을 빠뜨릴 때 검증 오류가 나서 이 일감에서는 바꾸지 않았다.
- 하렘 '균열은 1~3화 오해' 줄은 균열이 생기는 구간을 골라 다시 재야 한다.
- 찬 판은 모든 화에 `reward` 를 적어, 일감 7 의 경고가 빈 `reward` 를 '사이다 없는 화'로 세려면 채움이 화를 가르는지 먼저 다시 재야 한다.
