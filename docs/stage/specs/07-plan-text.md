# 07. 계획 장면과 본문 장면

상태: 설계 · 계획: [plan.md](../plan.md) 의 7번 · 먼저: 1-1(PR #163)

## 목표

장면 연출의 두 역할(README '왜 만드나')을 데이터로 나눈다. 작가가 쓰기 전에 짠 **계획 장면**과 본문에서 뽑은 **본문 장면**을 같은 사건에 따로 두고, 화면에서 바꿔 보고 겹쳐 보며, 둘의 차이를 코드가 잰다. 추출(일감 03) · 검수 연결(04) · 쓰기 프롬프트(05)가 이 구분 위에서 일한다.

## 정한 것 (2026-10-29)

- `StageScene.role: Literal["plan", "text"] = "plan"`. 옛 장면은 plan 으로 읽힌다.
- 한 사건에 plan 하나, text 하나까지. text 는 plan 을 덮지 않는다.
- 계획 대비 차이는 plan 이 있을 때만 잰다. 결과는 '사소' 지적 재료이고 작가가 '그대로 둠'으로 닫을 수 있다(AI 가 더 나은 연출을 썼을 수 있다).

## 정할 것

1. 견주는 단위 — 추천: 박자 번호가 아니라 **박자 끝 상태의 차례**로 견준다. 본문 장면의 박자 수는 계획과 다를 수 있으므로, 계획의 각 박자 끝 상태가 본문 장면의 어느 박자에서 처음 이뤄지는지 순서대로 찾는다(같은 인물 · 같은 칸이 같으면 이뤄짐). 끝까지 이뤄지지 않은 계획 칸이 '계획과 다름'이다. 다른 안: 사건 끝 상태만 견준다(가볍지만 중간 동선을 놓친다).
2. 견주는 칸 — 추천: 자리(기준점 + 관계, 같은 기준점이면 관계 차이는 무시), 자세(`upright` 여부만), 접촉(누가 · 누구에게 · 부위 쌍, 동작 이름은 무시). 향함 · 손에 쥔 것은 견주지 않는다(본문이 자주 말하지 않는다).

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/schema.py` | `StageScene.role` |
| `canon/stage.py` | `scenes_of(ep, event) -> (plan, text)`, `diff(plan, text, room) -> list[Gap]`(`Gap`: 계획 박자, 인물, 칸, 계획 값, 본문 값, 해요체 설명), `new_scene` 은 role 인자, `save_scene` 은 같은 사건 · 같은 role 에 하나만, `view` 는 장면마다 role 과 짝의 diff. #162 의 `episode_lines` 가 있으면 plan 만 고르게 고친다 |
| `canon/web.py` | 응답 모양만 늘린다(role · gaps). 엔드포인트는 그대로 |
| `canon/static/stage.js` | 머리에 '계획 \| 본문' 전환(본문 장면이 없으면 '본문에서 뽑기 전이에요'), '겹쳐 보기'(본문 장면 위에 계획 인물을 흐린 원으로), 계획과 다른 박자 표시. 본문 장면은 고칠 수 있지만 '추출 결과'라고 머리에 적는다 |
| `docs/stage/model.md` | 저장 자리 · 장면 형식 · 견주기 절 |

## 시험

- 옛 장면이 plan 으로 읽힌다. 같은 사건에 plan · text 가 하나씩만 남는다.
- `diff`: 같은 장면이면 빈 목록, 박자 수가 달라도 끝 상태가 같으면 빈 목록, 자리 · 자세 · 접촉이 다르면 각각 하나씩.
- JS: '계획 \| 본문' 전환과 겹쳐 보기가 그려진다(`tests/test_stage_js.py`).
- 전체 시험.
