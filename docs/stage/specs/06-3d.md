# 06. 3D 보기 (2차 후보)

상태: 탐색 (시안만, 브랜치 `claude/stage-3d-69497c`) · 계획: [plan.md](../plan.md) 2차 후보 '3D 보기' · 먼저: 1번, 2번 · 시안: [mockup-3d.html](../mockup-3d.html)

> 2026-10-29 사용자 결정으로 3D 는 '보기'가 아니라 '판별'이고 일감 6 이 됐다. 모듈 지도 · 정할 것 · 작업 명세서는 [../3d/README.md](../3d/README.md) 로 옮겼다. 이 문서는 탐색 기록(시안에서 잰 숫자, #159 와 맞춰 본 결과)으로 남긴다. 아래 '정할 것' · '추천안' · '바꿀 곳'은 3d/ 의 것이 앞선다.

1차 규칙(그림은 2D SVG, 3D · 관절 편집은 하지 않음, [README.md](../README.md))을 바꾸지 않는다. 이 문서는 1차가 끝난 뒤 3D 를 더할지 사용자와 정할 재료였다.

## 목표

장면 연출 화면에 '3D' 보기 전환을 더한다. 작가는 같은 장면을 비스듬히 · 위에서 · 문에서 돌려 보고, 박자 사이 자세가 바뀌는 모습(앉았다 일어남 등)과 손이 부위에 닿는 모습을 본다. 고치기는 2D 평면도 · 인물 카드에서만 한다. 3D 는 읽기 전용이다.

## 정할 것

1. 3D 를 넣을지 — 추천: 1차를 끝내고 작가가 2D 로 몇 장면을 짠 뒤 정한다. 넣으면 읽기 전용 보기 전환으로만 넣는다(아래 '추천안').
2. 라이브러리를 어떻게 싣나 — 추천: three.js 한 판을 `canon/static/vendor/three/` 에 MIT 라이선스와 함께 넣고, '3D' 를 처음 누를 때만 `import()` 로 읽는다. 시안은 CDN(jsDelivr, `three@0.170.0` 고정)을 쓴다.
3. 3D 에서 고치기를 허락할지 — 추천: 하지 않는다. 끌어 놓기 · 관절 편집은 1차 결정('관절 편집은 하지 않는다')과 부딪히고, 저장 단위(기준점 + 관계 말)로 되돌릴 수 없는 값을 만든다.
4. 두 사람 접촉 자세(안기 · 업기)를 어디까지 맞출지 — 추천: 업기 · 안기만 '붙여 매달기' 규칙으로 맞추고, 몸이 겹치는 것은 받아들인다(아래 '규칙').

## 2D 와 견준 득실

| 기준 | 2D SVG (1차) | 3D 보기 (이 시안) |
|---|---|---|
| 자리 · 동선 | 평면도가 가장 잘 보인다 | '위에서' 카메라가 평면도와 같다. 비스듬히 보면 가구 높이 · 가림이 더 보인다 |
| 자세 | 막대 인형 카드 12개, 평면도 위에는 원 + 쐐기 | 마네킹이 자세를 그대로 보인다. 박자 사이에 앉았다 일어나는 움직임이 보간된다 |
| 접촉 | 두 인물 원 사이 선, 부위는 도식 카드에서 | 손 끝에서 부위 점으로 선을 긋는다. 팔이 모자라면 틈이 보인다 |
| 높이 | 없음 (침대 위 · 바닥은 글로만) | 앉을 기준점 윗면 높이로 골반이 올라간다 |
| 고치기 | 끌어 놓기 → `stageSnap` | 하지 않는다 (3번) |
| 무게 | 코드 몇백 줄, 라이브러리 없음 | three.js 약 690KB(gzip 약 170KB) + 화면 코드 약 300줄 |
| 접근성 | SVG 에 `role="img"` · 글 목록 | 캔버스는 화면 읽기가 읽지 못한다. 같은 글 요약이 필요하다 |
| 시험 | 위치 계산을 node 로 맞춰 본다 | 위치는 같은 함수를 쓴다. 그림은 눈으로만 본다 |
| 깨질 곳 | 거의 없음 | WebGL 없는 기기, CDN 막힘, 저사양 노트북 발열 |

결론: 3D 가 새로 주는 것은 '높이'와 '자세 보간' 두 가지다. 동선 검수와 고치기는 2D 가 낫다.

## 데이터

스키마를 바꾸지 않는다. 시안은 PR #159 의 `StageRoom` · `StageScene` 모양 그대로 적은 가짜 장면(mockup.html 과 같은 장면)만 읽는다. 방은 `stage.make_room('bedroom')` 결과이고, 어휘(`stage.vocab()`)와 판정(`stage.judge`) 결과는 같은 장면으로 #159 코드를 돌려 붙였다. 아래 'PR #159 와 맞춰 본 결과'.

3D 가 더 필요로 하는 것은 데이터가 아니라 코드 상수다.

| 상수 | 내용 | 둘 곳 |
|---|---|---|
| `POSE` | 자세 id 12개마다 관절 각도 표 (아래) | `static/stage3d.js`. 서버는 모른다 |
| 앉을 높이 | 앉거나 누울 수 있는(`sit` · `lie` 참) 기준점의 `kind` 마다 윗면 높이 m (침대 0.5, 의자 0.45, 소파 0.42, 좌석 0.45) | `stage.py` 의 기준점 종류 표에 `seat` 칸을 더하고 어휘와 함께 내려 준다. 틀마다 값을 고칠 일은 없다 |
| 가구 높이 | `kind` 마다 상자 높이 (책상 0.75, 탁자 0.72, `other` 0.8). 문 · 창 · 벽(`wall`)은 벽에 붙는 판 | 위와 같은 표에 `height` |
| 동작별 손 배치 | `ACTS` id 마다 3D 만의 손 배치: 안다 · 끌어안다는 두 손으로 등을 감고 두 사람을 0.34 · 0.30m 까지 붙인다 | `static/stage3d.js` |
| 부위 점 | `PARTS` id 마다 마네킹 뼈 위 점 | `static/stage3d.js` |

`StageAnchor` 에 높이 칸을 두지 않는다. 작가가 고칠 값이 아니고 종류로 정해지며, 2D 판정(`reach` 거리)은 평면 거리만 쓴다. 다만 `other`(텔레비전 · 책장 …)는 종류만으로 높이를 알 수 없다. 시안은 0.8m 로 둔다. 작가가 책장을 낮은 상자로 보고 불편해하면 그때 `StageAnchor.height: float = 0`(0 이면 종류 값) 선택 칸을 더한다.

## PR #159 와 맞춰 본 결과

2026-10-29 에 PR #159(일감 01, `canon/schema.py` 의 `Stage*` 스키마와 `canon/stage.py`)와 맞춰 봤다.

방법:
1. 시안 장면을 `StageScene` JSON 으로 다시 적었다(기준점 id `a1`~`a5`, 접촉은 `StageContact` 목록, 손은 쥔 물건 글).
2. #159 의 `state_at` · `place` 를 시안 JS 로 옮겼다. 같은 장면의 시작 상태와 박자 5개, 모두 여섯 상태에서 인물 좌표가 Python `place` 와 같다(가장 큰 차이 4e-16m).
3. 같은 장면으로 `stage.judge` 를 돌렸다. 4박자 `reach` 하나가 나온다. 시안은 이 결과를 그대로 읽어 빨강을 정한다.

맞는 것:
- 스키마를 바꾸지 않고 그릴 수 있다. 3D 가 읽는 칸: 방 크기, 기준점의 자리 · 종류 · `rot` · `sit` · `lie`, 인물의 `at` · `posture` · `facing` · `left` · `right` · `contacts` · `ends`, 접촉의 `by` · `to` · `part` · `act`.
- 자세 id 12개가 `POSE` 표 키와 같다.
- `PARTS` 45개 모두 마네킹 점이 있다(기본 29개, 쌍은 `_l` · `_r` 로 뒤집음).
- 향함은 8방향 · `@인물` · `#기준점` 을 모두 `facing_vec` 와 같은 규칙으로 읽는다. 모르면 `place` 처럼 아래(+y)를 본다.
- 접촉 `by` 가 `both` 이면 두 손, 부위 id 이면 손 없이 부위 점 사이 선을 긋는다.

3D 가 그림에서만 바꾸는 것 (데이터 · 판정은 그대로):
- 안기: `place` 는 '@인물 앞'을 0.55m(몸 반지름 둘 + 0.05) 떨어뜨린다. 안으려면 0.34m 여야 해서 두 사람이 반씩 다가간다. 판정은 0.55m 로 보므로 `reach` 와 어긋나지 않는다.
- 안기거나 업히기 + '@인물' 자리: `place` 는 그 인물 0.55m 뒤에 둔다. 3D 는 그 인물 골반에 매단다(뒤면 업힘, 앞이면 안겨 들림).

PR #159 에 알릴 것 (3D 와 상관없이 2D 에도 나타난다):
1. 인물 기준 자리의 순환. 5박자 '하린: 도윤 앞' 에서 도윤의 향함이 '@하린' 이다. `place` 는 하린 자리를 모르는 채 도윤의 향함을 구해 '아래를 본다'로 친다. 그래서 하린이 (2.0, 1.8), 도윤 남쪽에 놓인다. 책상 앞(3.3, 1.1)에서 1.47m 를 걸어 도윤 뒤로 돌아가는 셈이라 본문 "한 걸음 다가가"와 다르다. 제안: 기준 인물이 나를 향하면 앞 박자의 내 자리 쪽을 앞으로 친다.
2. `bedroom` 틀의 의자 `rot` 이 0(앞이 아래)인데 책상은 의자 오른쪽(동)에 있다. 책상에 앉은 하린의 등받이가 왼쪽에 온다. 책상을 보게 하려면 `rot` 270 이다.
3. `Violation` 에 접촉 id 가 없다. 화면은 '이 박자에 이 인물이 시작한 접촉'까지만 좁힐 수 있다. 같은 박자에 한 인물이 접촉 둘을 시작하고 하나만 멀면 둘 다 빨개진다. 제안: `Violation.contact: str = ""`.

세 가지는 #159 의 뒤 커밋 `5c0a90d` 에서도 그대로 나와서 #159 에 댓글로 남겼다(2026-10-29). `5c0a90d` 는 부위 `forearm`(아래팔), 관계 `across`(맞은편) · `against`(기대어 맞닿음), 동작의 `support`(몸무게를 받침)를 더했다. 시안은 `forearm` 점을 더했다. `across` · `against` 는 `place` 가 좌표를 내므로 3D 에 할 일이 없다. `support` 는 3D 의 '안기거나 업히기 매달기' 조건으로 쓸 수 있다(지금 시안은 자세와 '@인물' 자리만 본다).

## 규칙

### 마네킹

- 뼈: 골반 → 몸통 → 목 · 머리, 몸통 → 위팔 → 아래팔(+손), 골반 → 넓적다리 → 정강이(+발). 발 상자와 코 표시로 몸 앞을 읽는다. 마디 길이(m): 넓적다리 0.44, 정강이 0.46, 몸통 0.5, 위팔 0.3, 아래팔 0.27, 손 0.08, 머리 반지름 0.11. 키 약 1.72m. 인물마다 키를 바꾸지 않는다(인물 신체 프로필 `Character.body` 는 프롬프트 밖 작가 메모이고, 그것으로 3D 비율을 바꾸면 신체 프로필이 그림 규칙이 된다).
- 몸 앞은 +z, 왼쪽은 +x. 방 좌표 (x, y) 는 3D (x, z) 다. 향함 각 a(평면도와 같은 `atan2`)는 yaw `π/2 − a` 다.

### 자세 → 관절 각도

자세마다 숫자 몇 개만 둔다: 골반 높이, 몸 전체 기울기(pitch · roll), 허리, 어깨 [왼, 오른], 팔 벌림, 팔꿈치, 엉덩관절, 무릎. 각도는 도이고 굽힘이 양수다. 두 칸은 필요한 자세만 적고 나머지는 0 이다: 다리 벌림(`labd`, 바닥에 앉기 25° · 안기거나 업힘 38°), 향한 쪽으로 옮김(`shift`, 의자에 앉기 −0.13m: 엉덩이를 등받이 쪽에 둬야 넓적다리가 앉는 면 위에 놓인다). 시안의 표가 첫 값이다(시안 오른쪽 '자세 → 관절 각도 표').

2026-10-29 에 자세 12개를 하나씩 앞 · 옆에서 보고 고쳤다. 고친 것: 기대 서기(팔짱이 기도하는 손처럼 보여 팔을 내리고 한 발을 벽에 대게: 무릎 75°), 의자에 앉기(`shift`), 바닥에 앉기(`labd` 로 책상다리). 나머지 아홉은 첫 값 그대로 읽혔다.

- 눕기 · 엎드리기는 몸 전체 pitch ∓90°, 옆으로 눕기는 roll 90° 로 만든다. 따로 뼈대를 두지 않는다.
- 앉기 · 눕기는 자리 기준점이 앉을 수 있는 종류이고 관계가 `on` 이면 그 윗면 높이에서 시작한다.
- 박자 사이 0.6초 동안 자리 · 방향 · 바닥 높이 · 관절 각도를 모두 섞는다. 서기 → 눕기처럼 pitch 가 크게 바뀌면 몸이 바닥을 스칠 수 있다. 1차 2D 처럼 '자세는 박자에서 바뀐다'로 두려면 각도 섞기만 끄면 된다.
- `prefers-reduced-motion` 이면 섞지 않고 박자 값으로 바로 그린다.

### 손 접촉

- 손이 맡은 접촉(`Hand.contact`)마다 어깨에서 대상 부위 점으로 두 마디 IK 를 푼다. 팔꿈치는 기본으로 아래 · 바깥 · 뒤로 굽히고, 접촉 동작마다 다른 쪽(pole)을 줄 수 있다(안기는 아래). 두 사람이 서로 손을 뻗으면 두 번 푼다.
- IK 는 어깨→목표 방향을 pole 쪽으로 돌려 위팔 방향을 얻는다. 첫 시안은 돌리는 부호가 반대여서 팔꿈치가 pole 반대(위 · 안쪽)로 꺾였다. 2026-10-29 에 바로잡았다. 넣을 때 node 시험으로 '팔꿈치가 pole 쪽 반공간에 있다'를 본다.
- 팔이 모자라면 다 뻗고 손 끝에서 부위 점까지 점선을 남긴다.
- 팔이 모자라고 대상이 몸 앞에 있으면 IK 전에 몸통을 대상 쪽으로 비틀고(최대 35°) 숙인다(최대 15°). 숙이면 어깨가 옮겨 가므로 네 번까지 다시 잰다. 서거나 앉은 자세(pitch · roll 0)만 그런다.
- 숙임 상한 15° 는 시안에서 정했다. 5박자에서 도윤이 하린의 늘어진 왼 손목을 잡으려면 25° 를 숙여야 닿는데, 그러면 하린의 머리와 0.22m 안으로 겹친다(머리 반지름 0.11 둘). 15° 면 머리 사이 0.37m, 손목까지 0.066m 틈이 남는다. 실제로는 잡힌 사람의 팔이 들리지만, 그것은 대상의 팔을 움직이는 두 번째 IK 라 넣지 않았다.
- 빨강은 규칙 판정(`stage.judge`)이 그 박자에 짚은 접촉에만 쓴다. 3D 가 두 번째 판정기가 되면 안 된다. 위 5박자는 평면 0.55m 라 `reach`(1.2m)를 통과하므로 0.066m 틈은 회색 점선으로만 보인다. 4박자(1.3m)는 숙여도 0.64m 모자라고, 판정이 짚었으므로 빨갛다. (`REACH_HAND` 를 1.4m 로 올린 뒤에는 평면이 이 접촉을 통과시키고 3D `reach3d` 가 짚는다.)
- 고개는 향함 대상(인물이면 그 머리, 기준점이면 가구 윗면)을 본다. 좌우 70°, 위아래 35° 안이다. 시안의 시작 상태에서 의자에 앉은 하린은 책상을 21° 내려다본다.
- 손 아닌 부위 접촉(입 맞추다, 머리를 기대다)은 선만 긋고 몸을 움직이지 않는다. 입술 · 이마 · 목 · 목덜미 · 가슴 · 등 · 허리 · 어깨 · 무릎 점은 마네킹에 있다.

### 두 사람이 겹치는 자세

'안기거나 업힘'과 '안다 · 끌어안다 · 업다'는 물리 없이 풀 수 없다. 시안의 '자세 12개와 업기 · 안기 시험 보기'가 이 문제를 보인다.

- 업기 · 안아 들기: 업힌 사람의 골반을 업은 사람의 골반 뼈에 매단다(등 뒤 0.3m, 높이 +0.12m). 업힌 사람은 다리를 38° 벌려 업은 사람 허리를 감는다. 업은 두 손은 업힌 무릎 점으로, 업힌 두 팔은 업은 가슴 점으로 IK 한다. 업힌 팔은 업은 사람의 어깨를 지나고, 넓적다리는 업은 골반 옆을 조금 뚫는다. 받아들인다.
- 마주 안기: 두 사람을 0.34m 떨어뜨려 마주 세운다. 한 팔은 상대 등 위(`back`), 한 팔은 허리(`back_low`)로 보내고, 두 사람의 높낮이를 엇갈려 같은 쪽 팔끼리 부딪히지 않게 한다. 손은 등 가운데에서 제 쪽으로 5cm, 등 겉에서 3cm 뒤를 겨눈다. 팔꿈치 pole 은 바깥 · 앞(`[0.8, -0.2, 1.0]`)이라 팔꿈치가 상대 옆구리 밖(가운데에서 0.26~0.33m, 몸통 반폭 0.16m)에 놓인다. 팔꿈치 안쪽 각은 등 위 팔 97°, 허리 팔 127° 다. 팔 마디마다 10점씩 잰 20점 가운데 상대 몸통 안에 든 점은 0개다(고치기 전 등 가운데를 겨누고 기본 pole 이었을 때 5~7개). 고개는 같은 쪽으로 40° 돌린다(마주 보면 머리가 겹친다). 발끝은 서로 겹친다. 받아들인다.
- '안기거나 업힘' 자세에 업다 · 안다 접촉이 없으면 매달 사람이 없다. 시안의 표 값(골반 1.05m)으로 혼자 떠 있다. 화면은 이 경우 '누가 안거나 업었는지 접촉을 더해 주세요' 를 보인다.
- 겹침을 고치는 충돌 처리 · 물리 엔진은 넣지 않는다. 비용에 비해 작가가 얻는 것이 적다.

### 라이브러리 무게와 CDN

- three.js r170 `three.module.min.js`: 691,648 바이트, gzip 170,881 바이트. 시안이 더 쓰는 `OrbitControls`(gzip 6,789) · `CSS2DRenderer`(gzip 1,513). 지금 `canon/static` 전체가 약 1.7MB 다. (2026-10-29, jsDelivr 에서 받아 잼)
- 지금 앱은 CSS(글꼴, 토스페이스)만 CDN 에서 읽고, CDN 이 막혀도 기본 글꼴로 돈다. 스크립트를 CDN 에서 읽으면 막힐 때 그 화면이 돌지 않고, 남의 서버 스크립트를 작품 데이터와 같은 페이지에서 돌린다. 그래서 넣을 때는 저장소에 한 판을 넣는다(정할 것 2).
- 3D 를 켜기 전에는 읽지 않는다. 장면 연출 화면을 열어도 2D 만 보면 내려받지 않는다.
- WebGL 이 없거나 라이브러리를 받지 못하면 '3D 를 그리지 못했어요' 와 평면도 링크를 보인다(시안에 있음).

### 접근성

- 캔버스에 `role="img"` 와 박자마다 바뀌는 `aria-label`(인물 · 자세 · 자리)을 단다. 같은 글을 `aria-live` 칸에도 넣는다.
- 3D 옆 '이 박자' 칸에 같은 내용을 글로 둔다(인물, 자세, 자리, 향함, 두 손, 접촉). 3D 없이도 장면을 읽을 수 있다.
- 카메라는 버튼 셋(비스듬히 · 위에서 · 문에서)으로도 바꾼다. 캔버스에 초점이 있으면 방향키로 옮긴다(`OrbitControls.listenToKeyEvents`).
- 색은 앱 CSS 변수(`--pair-a` · `--pair-b` · `--surface` · `--chip` · `--red` …)에서 읽고, 다크 모드로 바뀌면 다시 칠한다. 이름표는 DOM 글자(`CSS2DRenderer`)라 확대해도 흐리지 않다.
- 접촉 선은 몸에 가려도 보이게 깊이 검사를 끈다.

## 추천안

1. 1차(2D)를 그대로 끝낸다.
2. 2차에서 넣는다면 '평면도 | 3D' 전환을 평면도 칸 머리에 둔다. 3D 는 읽기 전용이고 박자 슬라이더 · 재생을 2D 와 함께 쓴다.
3. 위치는 `stageLayout` 한 함수를 2D · 3D 가 함께 쓴다. 3D 만의 계산은 자세 표 · IK · 매달기뿐이다.
4. 스키마는 바꾸지 않는다. `stage.py` 기준점 종류 표에 `seat` · `height` 두 칸만 더한다.
5. 삽화 태그 연결(2차 후보)과 묶지 않는다. 3D 자세 각도는 NovelAI 태그로 바뀌지 않는다.

## 시험

- `tests/test_stage_js.py` 에 더한다: `POSE` 의 자세 id 가 `stage.POSTURES` 와 같다, 앉을 높이 표의 종류가 `stage.py` 의 기준점 종류와 같다.
- IK 는 node 로 맞춰 본다: 팔 길이 안의 점이면 손 끝이 그 점에서 1cm 안, 밖이면 팔이 곧게 뻗는다(three.js 수학만 쓰므로 node 에서 돈다).
- 그림은 시험하지 않는다. 브라우저로 넓은 · 좁은 화면, 다크 모드, 재생을 눈으로 본다.
