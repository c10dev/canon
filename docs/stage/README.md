# 장면 연출 작업 문서

Canon 장면 연출 기능의 설계 자산이다. 장면 연출은 방 하나 안에서 인물이 어디에 서고, 어떤 자세로, 누구의 어디를 어떻게 만지는지를 박자마다 적고 그림으로 재생하는 사이드바 도구다.

**왜 만드나** (2026-10-29 사용자): AI 가 쓴 소설의 장면이 (1) 실제 3D 로 옮겼을 때 말이 되는지, (2) AI 가 쓴 동작 · 위치가 맞는지, (3) 쓰기 전에 스토리보드로 미리 보아 매끄러운지를 본다. 장면 연출은 집필을 동작 묘사로 끌고 가지 않는다. 은연중에, 뒤에서 매끄러움을 재는 도구다.

**두 역할**
- 집필 전(스토리보드 · 지시): 작가가 짠 **계획 장면**(`role = plan`)을 재생해 보고, 박자 설명은 지시로, 배치는 배경 제약으로 쓰기 프롬프트에 들어간다.
- 집필 후(판별): 본문에서 뽑은 **본문 장면**(`role = text`)을 규칙으로 판정하고 계획 장면과 견준다. 결과는 검수 세션의 '사소' 동선 지적이다.
기능이 들어가면 동작 설명은 [DESIGN.md](../../DESIGN.md) 에 쓰고 이 폴더를 가리킨다. 이 폴더는 일을 나누고 이어 가는 데 쓴다.

## 정한 규칙

2026-10-29 에 사용자와 정한 것이다. 바꾸려면 사용자와 다시 정한다.

| 날짜 | 규칙 |
|---|---|
| 2026-10-29 | (두 역할 결정 전) 1차는 사이드바 도구 화면 '장면 연출'만 만든다. 대화로 다듬기 패널(`chat.js`)은 데이터 모양이 굳은 뒤 2차로 붙인다. |
| 2026-10-29 | 목적은 쓰기 전 연출과 쓴 뒤 동선 검수다. 같은 데이터를 쓰기 프롬프트 재료로 다시 쓴다. 삽화 포즈 연결은 2차다. |
| 2026-10-29 | 공간은 방 · 실내 하나다. 마을 규모 이동은 지도(`atlas`, `travel`)가 맡는다. |
| 2026-10-29 | 그림은 2D SVG 다: 위에서 본 평면도, 막대 인형 자세 카드, 몸 부위 도식의 접촉 선. 3D 와 관절 편집은 하지 않는다. |
| 2026-10-29 | 계획 장면은 AI 초안 → 작가 고침 → 적용으로 만든다. 작가가 처음부터 짤 수도 있다. AI 초안은 장면 통째로 비교한 뒤 적용하고 적용 취소를 둔다. 박자 일부만 적용하지 않는다(박자는 앞 박자에서 바뀐 것만 적으므로 일부만 고르면 앞뒤가 깨진다). 본문 장면은 추출 결과 그대로 두고 계획을 덮지 않는다. |
| 2026-10-29 | 가구는 좌표를 가진 기준점이다. 인물 위치는 '기준점 + 관계 말'로 저장하고 그림 좌표는 코드가 계산한다. AI 는 좌표를 읽거나 쓰지 않는다. DESIGN.md 검수 절의 '화마다 좌표나 배치도를 만들지 않는다'(모델이 좌표 추론에 약하다)와 맞춘 결정이다. |
| 2026-10-29 | 장면은 플롯 사건(`EpisodePlot.events`) 하나에 하나 붙는다. 사건은 번호와 사건 글 사본으로 찾는다. 한 사건에 장면이 둘 필요하면 사건을 나눈다. |
| 2026-10-29 | 장면은 박자 목록이다. 박자마다 바뀐 인물 · 칸만 적고 본문 문장 인용으로 본문과 잇는다. 화면은 슬라이더로 재생하고 박자 사이 이동을 보간 애니메이션으로 보인다. |
| 2026-10-29 | 부위 · 자세 · 향함 · 접촉 동작은 고정 목록이다. 목록 밖은 자유 메모로 적는다. |
| 2026-10-29 | 방은 틀에서 골라 끌어서 고친다. 방은 지도 장소에 묶어 여러 장면이 다시 쓴다. 장소가 없으면 장면 전용 방을 두고 나중에 장소에 묶는다. |
| 2026-10-29 | 성인 인물 사이 접촉은 성적 접촉까지 제한 없이 작가 전용 데이터로 다룬다. 미성년 인물(`cast.is_minor_age`)이 낀 성적 부위 · 성적 동작 접촉은 화면 입력, AI 초안 · 추출, 프롬프트 어디에서도 만들지 않는다. |
| 2026-10-29 | (두 역할 결정으로 고침) 쓰기 프롬프트에는 계획 장면만 두 층으로 넣는다: 박자 설명(`note`)은 작가 지시로 그대로, 자리 · 자세 · 접촉은 '이 배치와 어긋나지 않게만 쓰고 동작을 하나하나 묘사하지 않는다'는 배경 제약으로. 화마다 바뀌는 쪽, 예산 `context.BUDGET["stage"]` 안, 뺀 수를 적는다. 장면마다 끌 수 있다. 전연령 작품(`Meta.adult` 거짓)은 성적 접촉 박자를 빼고 뺀 수를 작가에게 보인다. |
| 2026-10-29 | 장면 끝 상태는 같은 화 다음 장면의 시작값으로만 잇는다. 화를 넘는 옷 · 상처 · 물건 변화는 상태 변경안의 `CharacterState.attire` 가 맡고, 장면 연출은 `attire` 를 읽기만 한다. |
| 2026-10-29 | 1차 검수 규칙: 손(한 손 두 곳), 이동 자세(서지 않고 자리를 옮김), 거리(먼 사람과 접촉), 향함(등 뒤에서 몸 앞쪽 접촉), 물건(쥔 물건을 놓지 않고 다른 손으로 다시 쥠). 옷 겹 규칙은 2차다. |
| 2026-10-29 | 규칙 검수 결과는 검수 세션 지적 목록(`Episode.findings`)에 '동선' 지적으로 합치고 출처를 '규칙'으로 표시한다. 장면 연출 화면에도 그 박자에 표시한다. (두 역할 결정으로 더함) 심각도는 '사소'(low)이고, 고침안은 어긋난 낱말만 바꾸며 새 동작 문장을 더하는 고침안은 거른다. |
| 2026-10-29 | (두 역할 결정으로 고침) 본문에서 연출을 뽑는 AI 호출(`check` 단계)은 검수 때 자동으로 돈다. 설정 '검수 때 함께 뽑기'(`Settings.stage_extract`)는 기본으로 켠다. 화면 버튼으로도 돌린다. 비용은 자동 집필 추정에 넣는다. 플롯에서 연출 초안을 만드는 호출은 `plan` 단계다. |
| 2026-10-29 | 연구 화면의 장면 상태표 검수(`check_scene`, `BodyState`)는 새 스키마로 옮긴다. 같은 일을 하는 스키마를 둘 두지 않는다. |
| 2026-10-29 | 장면 데이터는 상태가 아니라 작가 자료다. 스냅샷 · 반영 취소 대상이 아니고, 갈래는 `project.json` 을 복사하므로 함께 따라간다. 장면은 자동으로 지우지 않는다. |
| 2026-10-29 | 화면 이름은 '장면 연출', 주소는 `stage/<화>/<사건 번호>` 다. |
| 2026-10-29 | 1차 판정기는 `canon/stage.py` 에 둔다. 규칙 이름과 `?` 손 규칙은 DESIGN.md 의 shadowcast 계획과 맞춘다. shadowcast 엔진 패키지가 나오면 손 · 물건 규칙을 엔진으로 바꿀지 그때 견준다. |
| 2026-10-29 | 접촉 거리 문턱은 손 1.2m, 그 밖 부위 0.6m 로 시작한다(제안값). 일감 03 시험 장면으로 고친다. |
| 2026-10-29 | 쓰기 프롬프트 블록 예산은 1,500자다. 블록 머리에 배경 제약 규칙, 장면마다 '사건 N: 사건 글 · 방 (기준점)' 머리, '처음 배치' 줄, 박자마다 '1. 지시: 작가 설명 \| 배치: 하린 침대 옆, 왼손 → 도윤 오른 손목(잡기)' 줄이다. 방 기준 8방향 향함과 빈손은 넣지 않는다. 성적 접촉을 뺀 박자는 지시도 뺀다. |
| 2026-10-29 | 3D 보기는 1차 2D 를 바꾸지 않고 따로 탐색한다(사용자 요청, 별도 세션). |
| 2026-10-29 | 두 역할: 장면은 `StageScene.role`(plan · text)로 계획과 본문을 따로 둔다(일감 07). 집필 후 판별은 규칙 판정과 계획 대비 차이를 둘 다 본다. 계획 대비 차이는 계획 장면이 있을 때만, '사소', 작가가 '그대로 둠'으로 닫는다. |
| 2026-10-29 | 계획 대비 차이(일감 07): 박자 번호가 아니라 박자 끝 상태의 차례로 견준다(계획 박자마다 본문 장면에서 처음 이뤄지는 박자를 차례로 찾음). 견주는 칸은 자리(기준점만) · 자세(선 자세인지만) · 접촉(누가 · 누구에게 · 부위 쌍)이고 향함 · 쥔 것은 견주지 않는다. |
| 2026-10-29 | 3D 는 '보기'가 아니라 '판별'이다. 3D 판정(높이를 넣은 닿음, 몸 · 가구 겹침)을 2차 첫 일감으로 올리고 3D 보기는 그 결과 화면이다. 3D 는 자세마다 · 장소(방 틀)마다 모듈로 나눠 명세 · 문서화한 뒤 병렬로 만든다(일감 06). |
| 2026-10-29 | 일감 03 · 04 정할 것(사용자, 모두 추천안): 추출은 화 본문 전체를 넣고 그 사건 부분만 뽑는다(박자 40개). 연구 검수 시험 `scene` 은 `stage` 로 옮긴다. 출처 칸 `ConsistencyIssue.origin`(ai · rule), 규칙 지적의 다시 검수는 LLM 없이 판정만. 인용 없는 박자의 판정은 장면 연출 화면에만. 검수 때 뽑기는 본문이 바뀐 사건만 하고, 작가가 손본 본문 장면은 덮지 않고 비교로 남긴다. |
| 2026-10-29 | 진행을 빠르게 하려고 일감을 모듈로 나눠 병렬 세션으로 한다. 같은 파일을 고치는 일감은 앞 일감 브랜치 위에 쌓는다(AGENTS.md 의 worktree 규칙). |
| 2026-10-29 | 선행 조사 반영(사용자 승인): 기준틀을 문서에 적는다(기준점 좌우는 상대, 인물은 내재). 관계 말에 `across`(맞은편) · `against`(기대어 맞닿음)를 더한다. 접촉 동작에 받침(`support`) 표시를 두고 업힘 이동 규칙이 쓴다. 부위에 아래팔을 더한다. 2차 규칙 후보와 평가 방법을 plan.md · 03 명세서에 적는다. |

## 근거

'기준점 + 관계 말, 좌표는 코드' 결정과 데이터 모양의 근거다(2026-10-29 선행 조사).

- Holodeck (CVPR 2024, arXiv 2312.09067): LLM 이 좌표 대신 물체 사이 관계 제약을 쓰고 최적화가 배치를 푼다.
- WordsEye (SIGGRAPH 2001): 물체마다 공간 태그(윗면 · 앞쪽)를 두고 관계를 배치로 바꾼다. `StageAnchor.sit` · `lie` 와 `rel` 이 같은 생각이다.
- IJCAI 2024 공간 추론 재평가 (doi 10.24963/ijcai.2024/701), StepGame (arXiv 2204.08292): 흩어진 관계를 여러 단계 잇는 일에 모델이 약하다. 관계 잇기는 `place` 가 한다.
- 소설 속 인물 위치 데이터셋 (arXiv 2504.03434): 장소 수준에서도 약 60% 정답(논문 초록 기준). 추출은 작가 확인을 거친다.
- ISO-Space · SpaceEval (SemEval-2015): 기준틀(절대 · 내재 · 상대) 구분. Spatial Role Labeling: trajector · landmark · indicator 가 `who` · `ref` · `rel` 과 같다.
- FlickrCI3D · DECO: 사람-사람 접촉을 부위 쌍으로 적고, 받침 접촉을 따로 나눈다.
- Stage Write · ActThread · FORMI: 박자별 평면도 + 대본 연결 + 보간 재생은 연극 · 무용 블로킹 도구의 관례다.
