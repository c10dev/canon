# 장면 연출 3D 작업 문서

장면 연출 일감 6(3D 판정 · 보기)의 모듈 지도다. 2026-10-29 사용자 결정에 따라 3D 는 '보기'가 아니라 '판별'이다. 평면 판정(`stage.judge`)이 못 보는 어긋남을 높이와 몸 부피로 잡는다. 3D 보기는 그 결과를 보이는 읽기 전용 화면이다.

- 높이를 넣은 닿음: 선 사람이 바닥에 누운 사람의 뺨을 만진다. 평면 거리는 0.5m 라 `reach` 를 통과하지만 허리를 숙여도 손이 닿지 않는다.
- 몸 · 몸 겹침: 두 사람이 같은 자리에 겹쳐 선다.
- 몸 · 가구 겹침: 다리가 책상을 뚫는다. 차 안에서 선다.

이 폴더는 일을 나누고 이어 가는 데 쓴다. 탐색 기록은 [../specs/06-3d.md](../specs/06-3d.md), 동작 시안은 [../mockup-3d.html](../mockup-3d.html) 이다. 시안의 자세 각도 표 · IK · 부위 점이 구현의 첫 값이다.

## 계약 요약

자세한 모양은 [01-body.md](specs/01-body.md) 가 정한다. 01 이 먼저 병합되고, 02 · 03 · 04 · 05 는 그 계약만 믿는다.

- 좌표: 평면도와 같은 x(오른쪽) · y(아래쪽) 에 높이 z(위쪽)를 더한다. 단위 m. three.js 는 렌더러가 (x, z, y) 로 바꾼다.
- 자세 모듈 → `POSTURE = PostureSpec(id, angles, surface, reach, feet_to_floor=False, place_hook=None)`: 자세 id 하나의 관절 각도 표, 앉는 면 요구(`floor` · `seat` · `lie` · `top` · `back_support` · `carrier`), 닿기 여유(허리 숙임 · 비틀기 최대), 특수 배치(기대기 · 매달기).
- 장소 모듈 → `ROOM = RoomSpec(template, ceiling, anchors={기준점 이름: Furniture(...)})`: 틀 하나의 기준점마다 높이 · 모양(상자 여럿) · 앉는 면 높이, 천장 높이. 평면 자리(x · y · w · h · rot)는 `stage.ROOMS` 의 것을 쓰고 다시 적지 않는다.
- `frames(scene, room) -> Frames`: 박자마다 인물의 관절 좌표 · 부위 점 · 캡슐과 가구 상자. 판정과 렌더러가 같은 값을 쓴다.
- 3D 판정 → `judge3d(scene, room, p) -> list[stage.Violation]`. 규칙 이름은 [04-judge.md](specs/04-judge.md). `stage.judge_all` 이 2D 판정에 이것을 더해 `stage.check` · 검수 지적으로 보낸다(07).
- 07 이 더한 계약: `Angles.hip_rot` · `ankle`, `Placement.angles`, `PostureSpec.head`, 특수 배치 두 번, 빈 향함의 몸 방향(`body.default_facing`), `to_dict()` 접촉의 `act` · `by` ([specs/01-body.md](specs/01-body.md) 의 구현 메모).

## 정할 것

06-3d.md 의 정할 것과 이번에 생긴 갈림길을 모았다. 추천안을 먼저 쓴다. 2026-10-29 사용자가 열 개 모두 추천안대로 정했다([../README.md](../README.md) 의 정한 규칙에 한 줄로 더했다).

1. **3D 계산을 파이썬이 할까, JS 가 할까** (정함 2026-10-29, 추천안대로) — 추천: 파이썬(`canon/stage3d/`)이 관절 계산 · 판정을 다 하고, JS 는 서버가 준 관절 좌표를 그리기만 한다. 판정은 검수 · 자동 집필에서 브라우저 없이 돌아야 하므로 파이썬에 있어야 한다. 계산을 두 언어로 두면 시안처럼 맞추는 시험(`stageLayout` 꼴)이 자세마다 늘어난다. 다른 안: 두 언어에 같은 계산을 두고 node 로 맞춰 본다(화면이 서버 없이 즉시 바뀌지만 일이 두 배다). 다른 안: JS 만(검수 연결이 안 돼 '판별' 목적과 맞지 않는다).
2. **three.js 를 어떻게 싣나** (정함 2026-10-29, 추천안대로) — 추천: 한 판(r170)을 `canon/static/vendor/three/` 에 MIT 라이선스와 함께 넣고, 3D 보기를 처음 열 때만 `import()` 로 읽는다. 다른 안: jsDelivr CDN(앱이 지금 스크립트를 CDN 에서 읽지 않는다. 막히면 화면이 안 돈다).
3. **3D 에서 고치기** (정함 2026-10-29, 추천안대로) — 추천: 하지 않는다. 고치기는 2D 평면도 · 인물 카드만. 1차 결정('관절 편집은 하지 않는다')과 저장 단위(기준점 + 관계 말)를 지킨다.
4. **사람 크기** (정함 2026-10-29, 추천안대로) — 추천: 모든 인물이 같은 마네킹(키 약 1.72m)이다. `Character.body` 는 프롬프트 밖 작가 메모라 판정 규칙으로 쓰지 않는다. 다른 안: 신체 프로필에 키가 있으면 마디를 늘이고 줄인다(아이 · 거인 장면에 맞지만 메모가 규칙이 된다).
5. **판정 문턱** (정함 2026-10-29, 추천안대로) — 추천(시험 장면으로 고칠 제안값): 손 닿기는 그 자세의 허리 숙임 · 비틀기 여유 안에서 손끝과 부위 점 사이 5cm 안. 몸 · 몸 겹침은 접촉 · 받침이 없는 두 사람의 캡슐이 3cm 넘게 파고들 때. 몸 · 가구 겹침은 앉거나 기댄 그 기준점을 빼고 5cm 넘게 파고들 때. 천장은 머리 꼭대기가 천장보다 높을 때. 07 이 시험 장면 19개로 고쳤다: 발 · 가구는 10cm, 가구 겹침은 팔을 보지 않고 받침 지적이 난 사람은 내지 않으며, 같은 기준점 위 두 사람의 손 닿기는 보지 않는다(근거는 [specs/07-wire.md](specs/07-wire.md) 의 구현).
6. **2D 와 3D 지적이 겹칠 때** (정함 2026-10-29, 추천안대로) — 추천: 2D `reach` 가 짚은 접촉은 `reach3d` 로 다시 짚지 않는다. 3D 는 2D 가 통과시킨 것만 본다. 심각도는 2D 규칙과 같은 '사소'.
7. **박자 사이를 볼까** (정함 2026-10-29, 추천안대로) — 추천: 박자 끝 상태만 본다. 옮기는 길이 가구를 뚫는 것은 2D 2차 후보 '경로 · 가구 겹침 표시'가 맡는다.
8. **그림에서만 바꾸는 것** (정함 2026-10-29, 추천안대로) — 추천: 판정은 `stage.place` 좌표를 그대로 쓴다. 안기 장면에서 두 사람을 더 붙이는 것은 렌더러만 한다(시안과 같음). 판정이 좌표를 고치면 2D 와 3D 가 다른 장면을 보게 된다.
9. **이름이 바뀐 기준점** (정함 2026-10-29, 추천안대로) — 추천: 장소 모듈은 틀의 기준점 이름으로 모양을 찾고, 작가가 이름을 바꾸거나 더한 기준점은 종류 기본값(`furniture.KINDS`)을 쓴다. `other` 종류 기본 높이는 0.8m. 스키마에 높이 칸을 더하지 않는다. 작가가 불편해하면 그때 `StageAnchor.height` 선택 칸을 정한다.
10. **3D 판정 켜기** (정함 2026-10-29, 추천안대로) — 추천: 등록부에 자세 12개 · 틀 7개가 다 있을 때만 `stage.check` 가 3D 판정을 부른다. 빠진 모듈이 있으면 3D 지적 없이 2D 만 낸다(반쯤 된 판정이 헛지적을 내지 않게). 설정 칸은 두지 않는다.

## 병렬 묶음과 차례

```
단계 A (혼자, 먼저)     01 뼈대 계약 ─────────────┐   06 three.js 들이기 (같이 해도 됨)
                                                  ▼
단계 B (동시에 6 세션)  P1 자세: 서기 · 걷기 · 뛰기 · 기대 서기
                        P2 자세: 의자에 앉기 · 바닥에 앉기 · 쪼그려 앉기 · 무릎 꿇기
                        P3 자세: 눕기 · 옆으로 눕기 · 엎드리기 · 안기거나 업히기
                        R  장소: 7개 (원하면 R1 집 4개 · R2 탈것 · 교실 3개로 나눔)
                        J  3D 판정
                        V  렌더러 · 화면 (06 위에)
                                                  ▼
단계 C (혼자, 마지막)   W  연결 (일감 07 · 1-1 브랜치 위) + 시험 장면으로 문턱 고치기
```

- 01 이 먼저다. 계약(`PostureSpec` · `RoomSpec` · `Furniture` · `frames`)과 등록부, 계약 시험이 병합돼야 나머지가 같은 모양을 믿는다. 01 은 실제 자세 · 장소를 만들지 않고 시험용 가짜 자세 · 장소만 쓴다.
- 단계 B 의 여섯 세션은 고치는 파일이 겹치지 않는다(위 표). 각 세션은 01 이 병합된 `main`(또는 01 브랜치)에서 갈라진다.
- J 는 자세 · 장소 모듈이 없어도 시험용 가짜 등록부로 시험한다. 실제 자세로 문턱을 고치는 일은 W 가 한다.
- V 는 `frames` 만 읽는다. `web.py` 를 고치므로 같은 때 `web.py` 를 고치는 다른 일감(일감 07)과 겹치면 앞 브랜치 위에 쌓는다.
- W 는 `canon/stage.py` 를 고친다. 일감 07 · 1-1 이 같은 파일을 고치므로 그 브랜치 위에 쌓는다.
- 자세 묶음은 비슷한 자세끼리 묶었다. 서기 계열은 닿기 여유가 크고, 앉기 계열은 앉는 면 높이와 발 맞추기, 눕기 계열은 몸축 방향과 매달기가 같은 문제다.
