# 07. 연결 (3D 판정을 검수에)

상태: 명세 · 지도: [../README.md](../README.md) 의 07 · 먼저: [04-judge.md](04-judge.md), 자세 12 · 장소 7, 장면 일감 07(계획 · 본문 장면) · 1-1(PR #163)

## 목표

3D 판정 결과를 2D 규칙 지적과 같은 길로 보낸다: 장면 연출 화면의 박자 표시, 검수 세션의 '동선' 지적(출처 '규칙', 심각도 '사소'). 실제 자세 · 장소로 판정 문턱을 시험 장면으로 고친다.

## 정할 것

[../README.md](../README.md) 의 정할 것 6(2D 우선), 10(등록부가 다 찼을 때만)을 따른다. 이 모듈만의 것:

1. 3D 판정을 어느 장면에 — 추천: 장면 일감 07 의 두 역할 모두. 계획 장면(쓰기 전)은 화면 표시만, 본문 장면(쓴 뒤)은 검수 지적까지. 2D 규칙과 같은 길이다.
2. 비용 — 추천: 따로 재지 않는다. LLM 호출이 없고 한 장면 0.2초 안(04 의 제안값)이다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/stage.py` | `check()` 가 `stage3d.ready()`(등록부가 다 참)일 때 `judge3d` 를 불러 `violations` 에 더한다. `RULES` 화면 이름에 3D 규칙 이름을 합친 표를 `vocab()` 이 내려 준다 |
| 검수 연결부 (장면 일감 04 가 만든 곳) | 규칙 지적을 `Episode.findings` 로 합치는 곳이 3D 규칙도 받게 한다(규칙 이름만 늘어나면 고칠 것이 없을 수 있다. 일감 04 의 구현을 보고 정한다) |
| `canon/stage3d/__init__.py` | `ready()` 하나. 01 파일이지만 이 일감 때는 01 이 끝났으므로 겹치지 않는다 |
| `canon/stage3d/judge.py` | 시험 장면으로 고친 문턱 상수만 |
| `tests/test_stage3d_contract.py` | `test_registry_complete` 를 건너뛰지 않고 엄격하게 |
| `tests/test_stage3d_wire.py` (새) | 아래 '시험' |
| `tests/stage3d_scenes/*.json` (새) | 시험 장면 |

`canon/stage.py` 는 장면 일감 07 · 1-1 도 고친다. 그 브랜치가 병합된 뒤(또는 그 위에 쌓아) 시작한다.

## 계약 (입력 · 출력)

- `stage.check(...)` 의 `violations` 에 3D 규칙이 섞인다. 모양은 같다(`stage.Violation`). 화면은 `vocab()["rules"]` 로 이름을 안다.
- 등록부가 덜 차면 3D 지적은 없다. 화면은 05 의 `missing` 으로 '3D 판정 준비 중: 자세 N개 · 틀 M개 남음' 을 보일 수 있다.

## 규칙

- 시험 장면 10개 이상을 만든다. 절반은 말이 되는 장면(지적 0 이어야), 절반은 일부러 어긋난 장면(규칙마다 하나 이상). 말이 되는 장면에서 지적이 나오면 문턱을 고치거나 자세 · 장소 모듈에 이슈를 남긴다.
- 문턱을 고치면 [../../model.md](../../model.md) 의 검수 규칙 절과 이 폴더 README 정할 것 5 를 고친다.

## 시험

- `tests/test_stage3d_wire.py`: 등록부가 다 차면 `check` 에 3D 규칙이 섞이고, 하나 빼면(monkeypatch) 섞이지 않는다. 2D `reach` 와 같은 접촉의 `reach3d` 가 둘 다 나오지 않는다.
- 시험 장면: 말이 되는 장면 지적 0, 어긋난 장면은 정해 둔 규칙 · 박자.
- 계약 시험이 엄격하게 통과(자세 12 · 틀 7).
- 전체 시험.

## 확인하지 못할 것

실제 작품 장면의 헛지적률. 사용자가 실제 작품 몇 화를 검수하고 3D 지적을 '그대로 둠'으로 닫은 수를 보아 문턱을 다시 정한다.
