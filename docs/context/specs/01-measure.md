# 01. 지금 넣기가 놓치는 것 측정

상태: 설계 · 계획: [plan.md](../plan.md) 의 1번 · 먼저: —

## 목표

동작은 바뀌지 않는다.
지금 쓰기 프롬프트가 본문에 나온 인물 · 이야기 요소 · 복선을 얼마나 놓치고, 나오지 않은 것을 얼마나 넣는지 센다.
같은 자료로 이름을 찾는 범위 세 가지와 새 활성 조건(2차 키 · 제외 키 · 한 단계 되부름 · N화 유지)을 흉내 내어, 2번 일감(`Activation`)의 찾는 범위와 권장 값을 정할 숫자를 낸다.
따르는 정한 규칙: [README.md](../README.md) 의 2026-11-08 결정(활성화 일은 측정으로 시작한다, 찾는 범위는 측정으로 정한다, 측정의 대리 정답과 자료).
LLM 을 부르지 않는다. 비용은 0 이다.

## 정할 것

1. 측정 스크립트를 어디 두나 — 추천: `scripts/context_measure.py` 로 커밋한다.
   - 이유: 2번 일감이 끝난 뒤 같은 자료로 다시 돌려 놓침이 줄었는지 보려면 같은 스크립트가 있어야 한다.
   - 결과 글과 숫자 파일만 `reports/` 에 둔다(커밋하지 않음).
2. 본문으로 무엇을 쓰나 — 추천: `Episode.final_text` 가 있으면 그것, 없으면 `Episode.text`.
   - 이유: 상태 반영이 `final_text` 를 바탕으로 했다.
   - 둘이 다른 화 수와 결과 차이도 함께 적는다.
   - n화 본문(`final_text` 포함)은 원본 `Project` p 에서 읽는다. 되돌린 사본 q 에서 읽지 않는다.
   - 이유: `pipeline.revert(q, n-1)` 는 n-1화 뒤의 확정 화를 'written' 으로 돌리고 `final_text` 를 비운다.
   - 되돌린 사본 q 는 컨텍스트를 다시 만드는 데만 쓴다.
3. 복선이 본문에 나왔는지 무엇으로 보나 — 추천: 그 화의 `ForeshadowClue`(심음 · 회수 근거 문장)가 있거나 `payoff_ep` 가 그 화면 '나왔다'로 본다.
   - 이유: 복선에는 이름과 다른 이름이 없다(`Foreshadow` 는 `description` 만 있다).
   - 후보는 `planted_ep < n` 인 복선(n-1화 끝에 열려 있던 복선)만이다.
   - n화에 심은 복선은 n화 전에 없어 `relevant_foreshadows` 가 고를 수 없다.
   - n화에 심은 복선은 '이번 화에 새로 심음, 세지 않음'으로 따로 적는다.
4. 복선 근거를 어디서 모으나 — 추천: 두 정답 묶음을 함께 센다.
   - 엄격한 정답: 작가가 승인해 반영한 근거(`ForeshadowClue`).
   - 느슨한 정답: 엄격한 정답 + `Project.history[*].dismissed.foreshadow_clues`(작가가 체크를 푼 근거).
   - 두 묶음의 놓침 · 낭비를 나란히 적는다.
5. 스냅샷이 없는 화를 어떻게 다루나 — 추천: 직전 화 스냅샷이 있는 화로 정확한 재구성을 한다(주 결과).
   - 모든 화는 '나중에 생긴 것 걸러내기' 근사로 따로 센다(보조 결과).
   - 겹치는 화에서 두 값을 견줘 근사의 치우침을 적는다.
   - 자세한 것은 '규칙'의 '지금 상태가 최신이라는 위험'.
6. 이전 화 끝부분 길이 N 의 후보 — 추천: 0 · 500 · 1500(지금 `context.NAMED_TAIL`) · 3000자.
7. N화 유지의 N 후보 — 추천: 1 · 2 · 3 · 5화.
8. 찾는 범위를 바꾸는 문턱 — 추천: 지금 범위보다 놓침이 상대 20% 이상 줄고 낭비가 상대 10% 이하로 늘 때 넓은 범위를 고른다.
   - 문턱을 넘는 후보가 여럿이면 놓침이 가장 적은 것을 고른다.
   - 놓침이 같으면 프롬프트 글자 수가 적은 것을 고른다.
9. 새 조건의 권장 값을 README 에 적는 문턱 — 추천: 놓침이 상대 10% 이상 줄고 낭비가 상대 15% 이하로 늘 때 그 값을 '권장'으로 적는다.
   - 넘지 못하면 '측정에서 이득 없음'으로 적는다.
   - 기본값은 어느 경우에도 지금 동작이다(README 의 2026-11-08 결정).
10. 작품마다 결과가 갈리면 — 추천: 네 작품 중 셋 이상에서 문턱을 넘을 때만 고른다. 화 수가 12화뿐인 작품도 한 표로 센다.
11. 단편의 찾는 범위 — 추천: 측정 자료가 모두 장편이라 단편은 이 측정으로 바꾸지 않는다. 단편은 지금처럼 플롯 글만 찾고, 2번 일감에서 작가가 켤 때만 넓힌다.
12. 사람이 읽는 20개 표본을 누가 읽나 — 추천: 사용자가 읽는다. 스크립트가 판정 시트를 만든다(`reports/` 의 열 판정 시트와 같은 꼴).
13. 선택된 id 를 어떻게 얻나 — 추천: (a) 스크립트에 선택 과정을 옮겨 쓰고, 옮긴 id 를 만든 프롬프트의 이름과 맞춰 보는 시험을 둔다.
   - 이유: `build_episode_context` 와 `episode_prompt` 는 글만 돌려준다.
   - 플롯 인물, `fit_cast` 결과, `named_ids` + `fit_named`, `fit_states` 뒤 남은 인물은 함수 안의 지역 변수다.
   - 옮겨 쓴 선택은 진짜 코드와 어긋날 수 있다. 맞춰 보는 시험이 어긋남을 잡는다.
   - (b) 다른 길: `canon/` 에 선택을 돌려주는 작은 읽기 전용 변경을 하고 '바꿀 곳'에 적는다.
   - (a) 를 고르면 `canon/` 의 코드는 고치지 않는다.
14. 커밋한 스크립트를 모듈 문서에 적나 — 추천: `docs/modules/labs.md` 에 `scripts/context_measure.py` 한 줄을 관련 줄 바로 뒤에 더한다.
   - `scripts/` 는 `tests/test_agents_docs.py` 가 보는 `canon/` 밖이라 시험이 요구하지는 않는다.

### 대리 정답

- '본문에 나옴'은 그 화의 최종 본문(정할 것 2)에 이름이 나온 항목이다(README 의 2026-11-08 결정).
- 인물: `context.name_pattern` 으로 찾는다. 전체 이름, 세 글자 한글 이름의 성 뗀 이름(`metrics.name_forms`), 띄어 쓴 이름의 첫 낱말, 한 글자 이름의 호칭 · 조사 꼬리를 쓴다.
- 인물에는 다른 이름 필드가 없다(`Character` 에 `aliases` 가 없다). 별명 · 호칭으로만 부른 화는 놓친다. 이 한계는 사람 판정에서 센다.
- 이야기 요소: 이름과 다른 이름(`StoryElement.aliases`) 가운데 두 글자 이상인 낱말이 본문에 있으면 나온 것이다(`elements.terms` 와 같은 규칙).
- 이야기 요소 이름 매칭은 지금처럼 부분 문자열이다. 인물처럼 조사를 보는 매칭을 따로 흉내 내어 차이를 적는다.
- 복선: 정할 것 3.

### 다시 만든 컨텍스트

- '선택됨'은 선택 함수가 그 항목을 골랐는지다. 글을 해석하지 않고 id 로 센다.
  - 인물: `static_characters`(고정 설정 블록), 플롯 등장 인물, `named_ids` + `fit_named` 로 더한 인물, 인물 현재 상태 블록에 남은 인물(`fit_states` 뒤).
  - 이야기 요소: `elements.for_episode` 가 고른 것. 이유(`always`, `episodes`, 관련 인물, 이름 매칭)를 나눠 적는다.
  - 복선: `relevant_foreshadows` 뒤 `rank_foreshadows` 가 남긴 것.
- '글자로 있음'은 조립한 프롬프트 어디에든(사실 줄, 줄거리, 직전 화 본문 포함) 이름이 나오는지다.
- 쓰기 프롬프트는 `episode_prompt(p, n)` 로 만든다. 실제 쓰기 호출과 같다(`write=True`, 스토리보드 · 큐 시트 포함).

## 규칙

### 지표

- 놓침: 본문에 나왔는데 선택되지 않은 항목. 엄격한 놓침은 글자로도 없는 항목이다.
- 낭비: 선택됐는데 본문에 나오지 않은 항목.
- 낭비는 글자 수로도 센다(그 항목 줄의 길이). 예산(`context.BUDGET`)을 얼마나 먹는지 보려는 것이다.
- 블록별로 센다: 인물 설정, 이번 화 등장 인물(플롯 · 이름으로 더한 인물), 인물 현재 상태, 이야기 요소, 열린 복선.
- 항목 종류별로 센다: 인물은 `tier`(main · support · minor), 이야기 요소는 `kind`(세계 규칙 · 장소 · 물건 · 세력 · 인물 특징 · 과거 사건 · 예정 사건 · 기타), 복선은 `kind`.
- 비율은 화 단위로 낸다: 놓침률 = 놓침 / 본문에 나온 항목, 낭비율 = 낭비 / 선택된 항목.
- 신뢰 구간은 화를 묶음으로 한 부트스트랩(`labstats.cluster_boot`)이다. 작품마다 따로, 그리고 네 작품을 합쳐 낸다.
- 항상 넣는 항목(`context = "always"`, 주역)은 낭비에 따로 적는다. 2번 일감에서 이 항목은 활성 이유 '늘 넣기'이라 빼지 않는다.

### 찾는 범위 흉내 (README 의 2026-11-08 결정: 찾는 범위는 측정으로 정한다)

- 지금(기준): 인물은 플롯 글 + 직전 화 끝 1500자, 이야기 요소는 플롯 글만 찾는다(`prompts.build_episode_context`, `elements.relevant`).
- 범위 A: 플롯 글만(`elements.plot_text`).
- 범위 B: 플롯 글 + 그 화의 스토리보드 글.
- 스토리보드 글은 `prompts.board_block(p, n)` 이 돌려주는 글이다(쓰는 AI 가 실제로 보는 글).
- 고정점만 쓰는 작품(`board.fixed_only`)은 `board_block` 이 장면 목록을 빼고 고정점만 돌려준다. 범위 B 도 그 글만 찾는다.
- 고정점만 쓰는 작품인지 작품마다 적는다.
- 범위 C: 범위 B + 직전 화 끝 N자(정할 것 6).
- 세 범위를 인물과 이야기 요소에 똑같이 쓴다.
- 스토리보드가 없는 화는 범위 B 가 A 와 같다. 스토리보드가 있는 화 수를 따로 적고, 있는 화만으로도 결과를 낸다.
- 범위를 넓혀 더한 인물도 지금처럼 `fit_named` 예산(`BUDGET['cast']`)을 거친다. 예산으로 잘린 수를 적는다.
- 프롬프트 전체 글자 수가 어떻게 바뀌는지 함께 적는다.

### 새 조건 흉내 (README 의 2026-11-08 결정: 쓰기로 한 조건)

- N화 유지: k화에 이름 매칭으로 활성화된 항목을 k+1~k+N화에도 넣는다. 이름 매칭은 고른 찾는 범위로 한다.
- 한 단계 되부름: 활성화된 이야기 요소의 `description` 과 활성화된 인물의 고정 설정 글에서 다른 항목의 이름을 한 번만 더 찾는다. 되부름으로 찾은 항목의 글은 다시 찾지 않는다.
- 2차 키(AND) · 제외 키: 지금 작품에 키 자료가 없어 그대로는 흉내 내지 못한다.
- 대신 두 조건이 줄일 수 있는 최대치를 센다: 이름 매칭으로 활성화됐는데 본문에 나오지 않은 낭비 가운데, 매칭 낱말이 다른 뜻으로 쓰인 것(예: '하늘'이 이름이 아닌 하늘)의 수.
- 다른 뜻인지는 사람 판정(아래)으로 보고, 스크립트는 매칭 위치의 앞뒤 30자를 시트에 싣는다.
- 예산을 넘길 때 남기는 차례는 README 의 결정대로 흉내 낸다: 항상 > 키 직접 매칭 > 되부름 > N화 유지, 같으면 최근에 나온 것.
- 이야기 요소 블록(`elements.episode_block`)에는 지금 예산이 없다. 흉내에서는 늘어난 글자 수만 적고 자르지 않는다. 예산은 2번 · 3번 일감에서 정한다.

### 지금 상태가 최신이라는 위험

- `build_episode_context(p, n)` 은 지금 `Project` 만 읽는다. 상태 블록 제목은 'n-1화 종료 시점'이지만 값은 마지막 화까지 반영한 `p.states` 다.
- 그대로 돌리면 n화 뒤에 생긴 인물 · 사실 · 복선 · 비밀 · 아는 정보가 들어가 매칭이 부풀고 놓침이 작게 나온다.
- 정확한 재구성: `stattrial.before(p, n)` 꼴로 깊은 사본을 만들고 `pipeline.revert(q, n-1)` 로 n-1화 반영 직후로 되돌린다.
- n화 본문은 원본 p 에서 읽는다(정할 것 2). q 는 n화의 `final_text` 를 비운 상태다.
- `revert` 는 `p.snapshot(n-1)` 이 있어야 돈다.
- n화는 `p.snapshot(n-1)` 이 있을 때만 정확한 재구성으로 센다. 이 확인 없이 `before()` 를 부르지 않는다.
- 이유: `stattrial.before(p, 1)` 은 0화 스냅샷이 없으면 `revert` 를 건너뛰고 최신 상태 사본을 오류 없이 돌려준다.
- 0화 스냅샷이 없는 1화는 근사로 센다.
- 장편은 `pipeline.prune_snapshots` 가 0화 · 아크가 끝난 화 · 최근 `SNAPSHOT_KEEP`(20)개만 남긴다. `Settings.keep_snapshots` 가 켜진 작품만 모두 남는다.
- 그래서 오래된 화 대부분은 정확한 재구성을 하지 못할 수 있다. 화마다 스냅샷 유무를 적는다.
- 근사(스냅샷이 없는 화): 지금 상태에서 n화 뒤에 생긴 것을 걸러낸다.
  - 인물: 플롯 · 반영 기록(`Project.history` 의 `new_characters`)에서 처음 나온 화가 n 이상이면 뺀다. `Character.first_ep` 도 본다.
  - 이야기 요소: `since_ep > n-1` 이거나 `added_after >= n` 이면 뺀다.
  - 복선: `planted_ep >= n` 이면 빼고, `payoff_ep >= n` 인 회수된 복선은 열린 것으로 본다.
  - 사실 · 비밀: `Project.history` 에서 n화 이후에 더한 것을 뺀다(`new_facts`, `secrets_added`).
  - 인물 상태 · 아는 정보 · 관계 수치은 근사로 되돌릴 수 없다. 근사 결과는 인물 상태 블록을 세지 않는다.
- 두 방법이 모두 되는 화(스냅샷이 있는 화)에서 놓침 · 낭비를 견줘 근사의 치우침을 적는다.
- `revert` 는 n화 뒤 반영 기록이 한 일만 되돌리고, n화 뒤 작가가 더하거나 고친 것은 둔다(`pipeline._undo_later` 설명).
- 그래서 정확한 재구성에도 이야기 요소 걸러내기(`since_ep > n-1` 이거나 `added_after >= n` 이면 뺀다)를 늘 덧씌운다.
- 작가가 나중에 고친 다른 이름과 인물 설정은 기록이 없어 되돌릴 수 없다. 이 한계를 결과에 적는다.

### 사람 판정 20개 (README 의 2026-11-08 결정)

- 대리 정답의 사각지대를 센다: 이름 없이 나온 항목(그, 그녀, 형, 선배, 직함, 별명), 이름이 매칭됐지만 다른 뜻인 낱말.
- 표본: 20화. 작품마다 5화씩, 놓침이 많은 화 2개 · 낭비가 많은 화 2개 · 무작위 1개. 무작위는 고정 씨앗을 쓴다.
- 시트 한 장: 본문, 대리 정답이 '나옴'으로 본 항목, 선택된 항목, 이름 매칭 위치의 앞뒤 30자.
- 사람이 적는 것: 이름 없이 나온 항목, 대리 정답이 잘못 '나옴'으로 본 항목, 그 화를 쓰는 데 빠지면 안 됐던 항목.
- 결과로 대리 정답의 놓침 쪽 과소 계산과 낭비 쪽 과대 계산을 비율로 적는다(`labstats.wilson`).
