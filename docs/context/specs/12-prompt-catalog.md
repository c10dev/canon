# 12. 프롬프트 관리 페이지

상태: 진행 (12a 읽기 페이지 끝 #472, 12b 실험 판) · 계획: [plan.md](../plan.md) 의 12번 · 먼저: 3번 (끝)

## 목표

작가가 Canon 이 AI 에게 보내는 프롬프트를 한 페이지에서 찾고, 읽고, 견준다.
보는 축은 둘이다: 호출 갈래(본문 쓰기, 검수, 서술 다듬기 …)와 주제(문체, 분량, 시점 …).
조각마다 어느 자리(시스템 · 요청 앞 · 요청 뒤 · 지시문 꼬리 · 두 번째 호출)에 들어가는지와 코드 출처를 보인다.
조각을 고친 실험 판을 만들어 프롬프트 놀이터와 블라인드 비교로 돌릴 수 있다(정할 것 1, 2026-11-09 정함).
실제 집필 요청은 바뀌지 않는다: 블록 차례와 문구는 `prompts.py` 가 정한다(2026-11-08, Q10).

### 왜 필요한가

2026-11-09 에 '문체 지시가 어디 있나'를 찾으려면 `prompts.py` 6,290줄에서 다섯 자리를 따로 찾아야 했다.

| 자리 | 조각 | 코드 |
|---|---|---|
| 시스템 프롬프트 | 문체 기본 규칙 13줄(문체 원문이 있으면 11줄) | `_PROSE_RULES` · `prose_rules` · `writer_system` |
| 요청 앞(캐시 앞부분) | 문체 예시 문단 · 스타일 프로필 · 표지 | `style_block` · `style_rules_view` · `style_passages` |
| 요청 뒤(화마다 바뀜) | 가끔 쓰는 장치 · 되풀이한 구절 | `device_block` · `echo_block` |
| 지시문 꼬리 | 프로필 따르기 · banned_phrases · 감정 이름 금지 · 문장 끝 섞기 | `episode_prompt` 의 쓰기 지시 · `ending_rule` · `ending_line` |
| 두 번째 호출 | 서술 다듬기 규칙 | `POLISH_RULES` · `POLISH_ENDING` |

- `prompts.py` 에는 `*_prompt` 요청 함수가 72개 있다(`grep -cE "^def [a-z_]+_prompt\(" canon/prompts.py`).
- 시스템 프롬프트 이름(`SYSTEM_*` 상수와 `*system*` 함수)은 약 30개다(`grep -ohE "prompts\.(SYSTEM_[A-Z_]+|[a-z_]*system[a-z_]*)\b|\bSYSTEM_[A-Z_]+\b" canon/*.py canon/*/*.py | sort -u`).
- 갈래를 한 곳에 적은 표는 `BRIEF_KINDS`(14갈래) 하나뿐이다. 서술 다듬기 · 동선 검수 · 검수 넓히기 · 두 걸음 검수 · 삽화 · 지도 · 장면 연출 · 플레이 · 전환 · 재구성은 표에 없다.
- 요청 글 일부는 `prompts.py` 밖 모듈이 만든다: `statwin.write_rule` · `coord.NOTE` · `timeline` 의 마감 줄 · `maps/prompt.py` · `llm.POLICY_NOTE` · `llm.ADULT_NOTE`(보내기 직전 `with_note`).
- 쓰기 요청 블록 표 `BLOCKS`(spec 03)는 쓰기 가족의 요청만 다룬다. 시스템 프롬프트와 두 번째 호출은 다루지 않는다.

## 이미 있는 셋과의 경계

새 페이지는 넷째 화면을 하나 더 두는 것이 아니라 셋을 잇는 목차다.

| 화면 | 지금 하는 일 | 바뀌는 것 |
|---|---|---|
| 프롬프트 보기 (spec 03, 작품 안 쓰기 화면) | 이 작품 · 이 화의 실제 쓰기 요청, 블록마다 토큰 · 예산, 블록 끄기(장편) | 그대로. 블록 이름 옆에 '관리 페이지에서 보기' 링크만 더한다 |
| 프롬프트 놀이터 (`promptlab`, 작품 밖) | 갈래를 불러와 칸을 고쳐 돌리고 시도를 남긴다 | 관리 페이지의 실험 판을 불러오는 길을 더한다 |
| 작업지시서 (`brief`) | 구독형 채팅 앱에 붙일 글을 만든다 | 그대로. 같은 레지스트리의 갈래를 쓴다 |
| 프롬프트 관리 (새로, 작품 밖) | — | 갈래 · 주제로 찾기, 조각 출처, 조립된 견본 요청, 실험 판 |

## 정할 것

2026-11-09: 사용자가 정할 것 1 은 (나)를, 2~8 은 모두 추천안을 골랐다.

1. 페이지에서 프롬프트 글을 바꿀 수 있는가 — 정함(2026-11-09): (나) 실험 판만.
   - (가) 읽기만. 고치는 일은 지금처럼 에이전트가 `prompts.py` 를 고치는 PR 로 한다. Q10 을 그대로 지킨다.
   - (나) 실험 판만. 조각 글을 고친 판을 작품 밖 저장소에 둔다. 판은 놀이터와 블라인드 비교에서만 쓰고 실제 집필 · 자동 집필 요청에는 들어가지 않는다. 이긴 판은 에이전트가 `prompts.py` 로 옮기는 PR 을 만든다. Q10 을 지킨다.
   - (다) 실제 집필에 쓰는 덮어쓰기. 문체 라이브러리처럼 전역 묶음을 두고 작품마다 켤 묶음을 고른다. Q10 을 다시 정해야 한다.
   - 고르지 않은 (다)를 나중에 다시 꺼내면 덮어쓸 조각을 캐시 경계 뒤와 시스템 규칙 줄로 한정하는 일부터 정한다. `static_context` 안을 바꾸면 Claude 캐시와 Gemini 암묵적 캐시가 처음부터 다시 쌓인다.
2. 레지스트리의 모양 — 정함(2026-11-09, 추천안): `prompts.py` 에 갈래 표 `KINDS` 와 조각 표 `PIECES` 를 둔다.
   - `KINDS` 는 `BRIEF_KINDS` 를 넓힌다: id, 화면 이름, 단계(`settings.STAGES`), 시스템 프롬프트 함수, 요청 조립 함수, 응답 형식(글 · 스키마 이름), 조각 id 목록.
   - `BRIEF_KINDS` 는 `KINDS` 가운데 작업지시서에 나오는 것을 고른 보기로 남긴다. 작업지시서 · 놀이터의 갈래 열쇠는 바꾸지 않는다.
   - `PIECES` 한 줄: id, 화면 이름, 주제 꼬리표, 자리, 글을 담은 상수 또는 함수 이름, 들어가는 조건 한 줄.
   - 쓰기 요청의 블록은 `BLOCKS` 의 id 를 조각 id 로 그대로 쓴다.
   - 조각 글은 이름 붙은 상수에서 읽는다. 함수 안에 박힌 긴 글은 이 일감에서 상수로 꺼낸다. 꺼낸 뒤 요청이 한 글자도 바뀌지 않음을 스냅샷 시험으로 본다.
3. 주제 꼬리표 — 정함(2026-11-09, 추천안): 여덟 개로 시작한다.
   - 문체, 분량 · 형식, 인물 · 말투, 시점, 연속성(사실 · 복선 · 시간), 검수 기준, 출력 형식(JSON · 마크다운 금지), 머리말 · 정책.
   - 조각 하나에 꼬리표 여럿을 달 수 있다.
4. 견본 요청의 재료 — 정함(2026-11-09, 추천안): 놀이터의 예시 작품(mock 으로 만든, 저장하지 않는 작품)이 기본이다.
   - 작가가 작품을 고르면 그 작품을 읽기만 해서 조립한다. 놀이터의 '불러오기'와 같은 함수를 쓴다.
   - 장편에만 있는 갈래는 예시 장편으로 조립한다.
5. 1단계에서 조립 보기를 줄 갈래 — 정함(2026-11-09, 추천안): 집필 흐름 갈래만.
   - 조립 보기: `BRIEF_KINDS` 14갈래 + 서술 다듬기 + 동선 검수 + 다시 생성.
   - 나머지 갈래는 표에 이름 · 단계 · 출처만 보인다. 조립 보기는 다음 단계에서 더한다.
6. 페이지 자리 — 정함(2026-11-09, 추천안): 작품 밖 도구 줄의 놀이터 옆, 주소 `#/prompts[/<갈래>|/topic/<꼬리표>|/piece/<조각>]`.
   - 작품 사이드바 ⋯ 메뉴에도 링크를 둔다(놀이터와 같다).
7. 판 기록 — 정함(2026-11-09, 추천안): 1단계에는 두지 않는다.
   - 조각의 지난 판은 git 기록에 있다. 페이지에서 커밋 목록을 보이는 일은 실험 판을 써 본 뒤 정한다.
8. 대화 에이전트 — 정함(2026-11-09, 추천안): 대화 에이전트(`agent.py`)는 이 페이지의 데이터를 읽지도 고치지도 않는다.
   - 실험 판을 에이전트가 제안하는 일은 쓰임을 본 뒤 정한다.

- 왼쪽 목록은 집필 흐름 차례로 갈래를 묶는다. 조립 보기가 없는 갈래는 '표에만' 아래에 모은다.
- 조각 줄은 화면 이름, 주제 꼬리표, 코드 이름, 글자 수를 보인다. 펼치면 견본으로 조립한 글과 들어가는 조건 한 줄을 보인다.
- 글자 수와 토큰은 spec 03 처럼 추정값(`context.est_tokens`)이고 '추정'이라고 쓴다.
- 자리 머리마다 캐시 앞부분인지 적는다.

### 주제별 보기

- 꼬리표 하나를 고르면 그 꼬리표를 단 조각을 모든 갈래에서 모은다.
- 조각마다 어느 갈래의 어느 자리에 들어가는지 보인다.
- 같은 뜻의 지시가 여러 자리에 있으면 한 화면에 나란히 보인다(예: '문체'는 위 '왜 필요한가' 표의 다섯 자리).
- 횟수 처방(예: '열에 셋쯤', '화에 셋까지')을 담은 조각은 표시를 단다. 판정은 조각 글의 숫자 패턴으로 하고 표시만 한다.

### 실험 판

- 조각 하나 또는 여럿의 글을 고친 판을 만든다. 판은 원래 글과 줄 단위 차이로 보인다.
- 판을 고른 갈래의 견본 요청에 끼워 조립한 글을 보인다.
- '놀이터에서 열기'는 판을 끼운 시스템 · 요청을 놀이터 세션으로 만든다.
- 블라인드 비교로 보내는 길은 이미 있는 블라인드 비교(`revlab.py` · `soelab.py`)의 형식을 따른다. 한 회차 안에 원래 판과 실험 판을 함께 넣는다.
- 구현(2026-11-10): '놀이터에서 원래 판과 견주기'가 만든 놀이터 세션은 돌릴 때마다 원래 판과 실험 판을 같은 백엔드로 함께 돌린다. 백엔드마다 두 결과를 역설계 실험의 가려 읽기(`RevBlind`) 꼴로 보이고 고르게 한다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/prompts.py` | `KINDS` · `PIECES` 표, 함수 안의 긴 글을 상수로 꺼냄, 조각을 견본으로 조립하는 `piece_text` |
| `canon/promptlab.py` | 실험 판을 끼운 세션 만들기 |
| `canon/promptset.py` (새) | 실험 판 저장소. 작품 밖 `<CANON_HOME>/.promptsets/<id>.json`, 환경 변수 `CANON_PROMPTSETS` |
| `canon/routes/prompts.py` (새) | `GET /api/prompts/kinds` · `GET /api/prompts/kinds/{id}?project=` · `GET /api/prompts/topics/{tag}` |
| `canon/static/prompts.js` (새) | 갈래별 · 주제별 보기, 실험 판 편집 |
| `canon/static/app.js` | 라우팅 `#/prompts`, 작품 밖 도구 줄 · 작품 ⋯ 메뉴 링크 |
| `canon/static/write.js` | 프롬프트 보기의 블록 이름 옆 링크 |

- 함수는 이름으로 가리킨다. 줄 번호는 쓰지 않는다.
- 이 일감은 spec 06(정규식 규칙)과 `prompts.py` 를 함께 고칠 수 있다. 시작 전에 고칠 함수를 서로 견준다.
- LLM 호출은 새로 생기지 않는다. 놀이터 · 블라인드 비교가 이미 `usage.record` 를 거친다.

## 데이터 · 스키마

- 1단계(읽기)는 저장하는 데이터가 없다. 레지스트리는 코드 안 표다.
- 실험 판 `PromptSet`: id, 이름, 만든 때, 조각마다 바꾼 글 목록 `[{piece, text}]`, 메모.
- 조각마다 바꾼 글은 dict 가 아니라 목록으로 둔다. LLM 이 채우는 스키마는 아니지만 다른 저장 형식과 맞춘다.
- 판이 가리키는 조각 id 가 코드에서 사라지면 그 줄을 '없는 조각'으로 보이고 끼우지 않는다.

## 규칙

- 견본 조립은 작품을 바꾸지 않는다. 작가가 고른 작품은 읽기만 한다.
- 단편 경로의 요청은 바뀌지 않는다.
- 실제 집필, 자동 집필, 작업지시서 요청은 실험 판을 쓰지 않는다. 그래서 이 요청들은 바뀌지 않는다(정할 것 1).
- 실험 판을 실제 요청으로 옮기는 길은 에이전트가 `prompts.py` 를 고치는 PR 하나뿐이다.
- 레지스트리에 없는 시스템 프롬프트나 요청 함수가 생기면 시험이 실패한다(아래 시험).

- 같은 시험이 `PIECES` 의 상수 · 함수 이름이 실제로 있는지 본다.

- 실험 판을 만들면 `CANON_PROMPTSETS` 를 `tests/conftest.py` 가 지우는 목록에 더한다.
