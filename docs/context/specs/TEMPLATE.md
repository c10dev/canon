# NN. 일감 이름

상태: 설계 · 계획: [plan.md](../plan.md) 의 NN번 · 먼저: N번 (없으면 —)

상태 칸은 `설계`, `진행 (브랜치, PR)`, `끝 (PR)` 가운데 하나다.
'먼저:' 칸은 [plan.md](../plan.md) 표의 '먼저 끝날 것'과 같게 쓴다.

## 목표

작가에게 무엇이 달라지는지 한두 문장으로 쓴다.
동작이 바뀌지 않는 일감(측정, 정리)이면 그렇다고 쓴다.
이 일감이 따르는 정한 규칙을 [README.md](../README.md) 의 날짜로 가리킨다.

## 정할 것

시작 전에 사용자와 정할 것이다.
추천안을 먼저 쓴다.
정하면 결과를 여기 적고 [README.md](../README.md) 의 정한 규칙에도 더한다.
README.md 의 정한 규칙과 어긋나는 질문은 쓰지 않는다.
정한 규칙을 바꾸려면 사용자와 다시 정한다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|

- 함수는 이름으로 가리킨다(예: `canon/prompts.py` 의 `build_episode_context`).
- 줄 번호는 바뀌므로 쓰지 않아도 된다.
- 먼저 머지되어야 하는 일감은 [plan.md](../plan.md) 표의 '먼저 끝날 것'과 같게 머리 줄의 '먼저:' 에 적는다.
- 같은 파일을 고치는 일감(예: 3 과 8 의 `context.BUDGET`)은 [plan.md](../plan.md) 표 아래 문단처럼 적고, 시작 전에 고칠 파일을 서로 견준다.
- 판정(활성화 조건을 보고 넣을지 정하는 일)은 `canon/context.py` 에만 둔다.
- 조건 어휘(Q27)의 값 읽기와 비교는 한 곳에 두고 활성화 판정과 선언형 규칙이 함께 쓴다.
- 상태 변경 제안(효과 y)을 다시 계산할 때(Q28)도 같은 함수를 쓴다.
- 그 한 곳이 아직 정해지지 않았으면 그 일감 명세서의 '정할 것'에 질문으로 둔다.
- LLM 호출이 생기면 `LLM` 인터페이스 뒤에 두고 `get_llm(단계)` 로 단계를 밝힌다.
- 새 단계 이름은 `settings.STAGES` 에 더하고 이름을 적는다.
- LLM 호출 경로가 새로 생기면 `usage.record` 로 사용량 화면에 잡히게 한다.
- LLM 을 부르는 스레드를 새로 띄우면 `contextvars.copy_context()` 로 작품 · 화 정보를 넘긴다.

## 데이터 · 스키마

- 새 필드와 바꾸는 필드: 모델, 필드 이름, 타입, 기본값.
- 기본값은 지금 동작을 그대로 지킨다. 옛 `project.json` 이 고치지 않고 읽혀야 한다.
- LLM 이 채우는 스키마(`.json(…)` 응답 형식과 그 안의 모델)에는 dict 타입 필드를 쓰지 않는다(`tests/test_schema_nodict.py`).
- 프로그램만 채우는 필드는 `SkipJsonSchema` 로 응답 형식에서 뺀다.
- 작품 밖에 두는 전역 저장소(규칙 묶음 같은 것)는 경로, 환경 변수, 파일 하나의 형식을 적는다.
- RisuAI · CCv3 · CBS 와 이름이나 뜻이 다른 필드 · 매크로는 [compat.md](../compat.md) 에 한 줄을 더한다.
- Canon 필드 이름은 바꾸지 않는다.
- 정규식 규칙은 RisuAI 정규식 스크립트의 in · out · type · flag 에 Canon 의 action 하나를 더한 꼴을 지킨다(Q26).

## 규칙

- 계산 규칙과 경계 사례를 쓴다.
- 숫자에는 근거(측정 결과, 기존 상수, 사용자 결정)를 단다.
- 승인 흐름: AI 가 만든 것은 어디서 작가가 고르는지, 자동 집필과 `-y` 는 어떻게 다루는지 쓴다.
- AI · 규칙이 만든 상태 변경 제안이 어떤 표시로 오는지, 기본 체크인지 적는다(규칙 제안은 '규칙' 표시 · 기본 체크, Q22).
- 인물 설정 바꾸기 제안은 기본 체크하지 않고, 자동 집필과 `-y` 는 남겨 둔다(`charlog.hold`).
- 되돌리기: 프로그램이 본문이나 데이터를 바꾸면 무엇을 기록해 되돌리는지 쓴다.
- 대화 에이전트(`canon/agent.py`)가 이 기능을 쓸 수 있는지, 어느 권한 모드에서 쓰는지 쓴다.
- 단편(`form = "short"`)과 장편(`form = "serial"`)에서 동작이 다르면 둘을 나눠 쓴다.

## 화면 · 명령줄 · 프롬프트

- 화면 문구는 해요체로 쓴다. 문구 규칙은 `docs/design/README.md` 를 따른다.
- 화면 모양을 바꾸면 고칠 `docs/design/` 문서를 적는다.
- 프롬프트는 `canon/prompts.py` 한 곳만 고친다. API 경로와 작업지시서(`brief`) 경로가 같은 프롬프트를 쓴다.
- 프롬프트에 블록을 넣으면 예산(`context.BUDGET` 의 키와 글자 수)을 적는다.
- `context.BUDGET` 은 장편 블록 예산이다.
- 단편에도 쓰는 키(예: `deadlines`)를 고치면 그렇다고 적는다.
- 새 블록은 화수에 따라 끝없이 커지지 않게 한다(장편).
- 블록 자리를 적는다. 바뀌지 않는 블록(`static_context`)이 앞, 화마다 바뀌는 블록이 뒤다.
- 예산을 넘겨 뺀 항목이 있으면 몇 개 뺐는지 프롬프트와 프롬프트 보기에 적는다.
- 프롬프트 보기에는 뺀 항목의 이름도 적는다(Q17).
- 남길 차례는 README 의 Q17 규칙을 따른다: 늘 넣기 > 키워드 직접 발견 > 재귀 > 유지, 같으면 가장 최근에 나온 것.
- 단편(`form = "short"`) 경로의 프롬프트는 기본값에서 바뀌지 않는다.
- 블록 차례와 블록 문구는 `prompts.py` 가 정한다. 작품 설정으로 바꾸지 않는다.
- 고친 뒤 `brief` 출력(작업지시서)도 함께 본다.
- 명령줄 명령이나 옵션을 더하면 이름과 안내 문구를 적는다.
- 웹 엔드포인트(`canon/web.py`)를 더하면 경로와 요청 · 응답 모양을 적는다.
- Swift 앱 개발은 멈췄다(AGENTS.md).
- `swift/` 를 고치지 않고 `scripts/make_openapi.py` 를 돌리지 않는다.
- RisuAI 코드(GPL-3.0)와 기본 프롬프트 글은 옮기지 않는다(Q4).
- RisuAI 와 맞추는 곳은 공개 데이터 형식의 필드 이름만 쓴다(Q4).

## 시험

- 새 시험: 파일 이름과 무엇을 보는지 쓴다.
- 시험은 `CANON_HOME` 을 임시 폴더로 두고 돌린다. 저장 위치는 `monkeypatch.setattr(store, "ROOT", tmp_path)` 로 바꾼다.
- 새 전역 저장소의 환경 변수는 `tests/conftest.py` 가 지우는 목록에 더한다.
- 새 모듈 캐시는 `tests/conftest.py` 의 `_fresh_caches` 목록에 더한다.
- 스키마나 파이프라인을 바꾸면 `canon/mock.py`(새 기능은 `mock_<기능>.py`)의 가짜 응답을 맞춘다.
- 기본값으로 옛 동작이 그대로인지 보는 시험을 둔다(옛 `project.json` 읽기, 프롬프트가 바뀌지 않음).
- 스냅샷: 프롬프트 스냅샷이 바뀌면 이유를 쓴다.
- 고친 기능의 시험만 빠르게: `CANON_HOME=$(mktemp -d) python -m pytest -q tests/test_<기능>.py`.
- 전체 시험: `CANON_HOME=$(mktemp -d) python -m pytest -q -n auto tests`.
- 정적 검사: `ruff check canon tests scripts`.

## 문서

- README.md 와 DESIGN.md 의 고칠 부분을 적는다.
- `docs/modules/*.md` 에서 고칠 절(`### 경로`)과 줄을 적는다. 새 파일은 갈래 파일에 새 절을 더한다(`tests/test_agents_docs.py`).
- `docs/modules/` 는 AGENTS.md 의 '문서 줄 규칙'을 지킨다.
- 이 폴더의 [plan.md](../plan.md) 상태 칸을 고친다.
- 정한 것이 생기면 이 폴더의 [README.md](../README.md) 정한 규칙에 날짜와 함께 더한다.
- 측정 일감이면 결과 글은 `reports/` 에 둔다(커밋하지 않음).
- 설계를 바꾸는 실측값은 DESIGN.md 에 날짜와 함께 옮긴다.

## 확인하지 못할 것

- 이 일감에서 돌릴 수 없는 확인과 그 이유를 쓴다.
- 예: 실제 Gemini 호출(키가 있을 때만), 작가의 취향 판단.
- 서버 vocado-dev 의 작품은 읽기 전용으로만 쓴다(측정 일감).
- 작품을 바꾸는 확인은 하지 않는다.
- 사용자가 할 단계를 번호 목록으로 쓴다.

## 비용

- LLM 을 부르는 확인이 있으면 호출 수 × 프롬프트 크기로 비용을 어림한다(`python -m canon usage --prices`).
- 모델별 호출 수와 쓴 비용을 적는다.
- LLM 을 부르지 않으면 "LLM 비용 없음"이라고 쓴다.
