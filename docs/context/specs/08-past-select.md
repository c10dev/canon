# 08. 접은 줄거리 고르기

상태: 설계 · 계획: [plan.md](../plan.md) 의 8번 · 먼저: —

## 목표

장편의 접은 줄거리가 예산을 넘을 때 오래된 묶음부터 빼지 않고, 남길 묶음을 고른다.
고르는 차례는 중요한 것 > 이번 화와 관련된 것 > 최근 것이다. 무작위는 쓰지 않는다(2026-11-08 사용자 결정 Q14 의 b, Q23).
중요도는 데이터로 계산하고, 작가가 묶음마다 '늘 남기기' · '중요하지 않음'으로 덮을 수 있다(Q23).
뺀 묶음은 몇 개인지와 이름을 프롬프트와 프롬프트 보기에 적는다(Q17 의 원칙을 줄거리에도 쓴다).
단편(`form = "short"`)의 줄거리 블록은 바뀌지 않는다(Q18).
예산 안에 드는 장편도 바뀌지 않는다. 고르기는 예산을 넘을 때만 일한다.
따르는 정한 규칙: [README.md](../README.md) 의 2026-11-08 Q14 · Q18 · Q23.

## 정할 것

1. 관련도를 어디에 매기나 — 추천: 묶음에 든 화들의 본문 단락을 `context.passage_index` 로 찾고, 묶음 안 단락 점수 가운데 위 3개의 합을 그 묶음의 관련도로 쓴다.
   - 질의는 `elements.plot_text(ep)`(이번 화 플롯)이다.
   - 검수 `check_recall` 과 같은 점수 식을 쓰고, 질의 재료는 다르다. `check_recall` 의 질의는 이번 화 본문과 플롯이고, 가산 낱말에 조연 이름(`names_of`)이 든다.
   - 가산 낱말은 본문을 보지 않는 함수로 따로 만든다(예: `query_terms(p, n, text=False)` 로 장소를 플롯에서만 찾음). 지금 `query_terms` 는 장소를 플롯과 본문에서 찾아, 본문이 생긴 뒤의 검수 · 상태 프롬프트에서 낱말이 달라진다.
   - 가산 낱말에 이번 화 플롯 인물의 이름(`names_of`)을 넣을지 정한다. 추천은 넣는 것이다(플롯만 보므로 쓰기와 검수가 같다).
   - 색인은 `arc_start` 앞 화만으로 만든다(`passage_index(p, arc_start)`). 아크 안에서 색인 열쇠가 같아진다.
   - `passage_index` 캐시는 최근 2개만 든다(`INDEX_KEEP = 2`). 검수(`skip=recent` 열쇠)와 검수 넓히기가 겹치면 300화에서 한 번에 0.15~0.25초 걸리는 색인을 서로 밀어내 다시 만든다.
   - 그래서 `INDEX_KEEP` 을 3 으로 올리거나, 묶음별 관련도를 (n, 본문 지문) 열쇠로 따로 캐시한다. 둘 가운데 하나를 고른다.
   - 새 캐시를 두면 `tests/conftest.py` 의 `_fresh_caches` 목록에 더한다.
   - 점수 식은 `PassageIndex.find` 의 것을 그대로 쓴다(희소한 한글 3글자 조각의 idf 합을 단락 길이로 누르고, 낱말이 나오면 4.0 을 더함).
   - `find` 는 지금 단락만 돌려주고 점수는 돌려주지 않는다. 점수를 돌려주는 함수(`PassageIndex.scores` 꼴)를 `context.py` 에 더한다.
   - 다른 안: 같은 점수 식을 묶음의 요약 글(실제로 넣는 글)에 매긴다. 요약은 짧아 겹치는 조각이 적다. 본문 쪽이 이름 · 장소가 더 많이 나온다.
   - 두 안을 mock 300화와 측정 데이터로 견준 뒤 고른다. 임베딩은 쓰지 않는다(Q23, 2026-11-03 실측에서 이득 없음).
   - 정할 것 1 · 2 를 고르기 전에 일감 1 의 측정 스크립트로 같은 네 작품을 잰다. 일감 1 머지를 기다리지 않는다.
2. 세 기준을 어떻게 합치나 — 추천: 칸 차례로 채운다.
   - 먼저 '늘 남기기' 묶음, 다음 중요도가 0 보다 큰 묶음(중요도 높은 차례), 다음 관련도가 0 보다 큰 묶음(관련도 높은 차례), 마지막으로 나머지(최근 차례)다.
   - 같은 칸 안에서 값이 같으면 최근 묶음이 앞선다.
   - RisuAI HypaV3 처럼 칸마다 예산 비율(중요 · 최근 · 유사)을 미리 떼어 두는 안도 있다. 비율은 맞출 숫자가 늘어 처음에는 두지 않는다.
   - 비율이 필요한지는 측정에서 '관련 묶음이 중요 묶음에 밀려 다 빠지는 화'가 얼마나 되는지 보고 정한다.
3. 접는 차례도 고르기 차례를 따르나 — 추천: 따른다.
   - 지금은 오래된 묶음부터 한 단계씩 접고(자세히 → 줄임 → 한 줄), 그래도 넘치면 오래된 묶음부터 뺀다(`prompts.story_parts`).
   - 접기만 오래된 차례로 두면 중요한 옛 묶음이 한 줄로 줄어든 채 남는다.
   - 그래서 낮은 차례 묶음부터 접고, 그래도 넘치면 낮은 차례 묶음부터 뺀다.
   - 이 경우 예산을 넘겨 접기만 하던 작품(빼는 묶음이 없던 작품)도 접히는 묶음이 바뀐다. 그 작품들의 프롬프트 스냅샷이 바뀐다.
4. 화마다 바뀌는 관련도와 캐시 경계 — 추천: (나).
   - 접은 줄거리는 `static_context` 와 부 · 아크 구조 바로 뒤에 있어 지금은 아크 동안 바뀌지 않는다(DESIGN.md 7장 '블록 순서').
   - 관련도로 고른 묶음을 지금 자리에 두면 화마다 그 뒤 프롬프트가 캐시에서 빠질 수 있다(`claude.cache_blocks`). 이것은 AGENTS.md 의 '바뀌지 않는 블록이 앞, 화마다 바뀌는 블록이 뒤' 원칙을 어긴다.
   - [plan.md](../plan.md) 는 8 이 캐시 경계를 지킨다고 정했다. 그래서 아래 두 안 가운데 하나를 고른다.
   - (가) 아크 첫 화에서 한 번 고르고 아크 동안 고정한다. 질의는 이번 아크 기획(목표 · 갈등 · 보상)과 아크의 화 플롯이다.
   - (가) 는 Q23 의 '이번 화와 관련'을 바꾸는 일이라 사용자와 정한다.
   - (나) '늘 남기기' · 중요 · 최근 묶음은 지금 자리에 둔다. 관련도로 고른 묶음만 '이번 아크 화별 요약' 앞의 화마다 바뀌는 블록으로 옮긴다.
   - (나) 는 Q23 과 '바뀌지 않는 블록이 앞' 원칙을 함께 지킨다. 그래서 추천한다.
   - (나) 에서 앞자리 묶음은 화마다 바뀌지 않아야 한다. 관련도 칸에 든 묶음은 앞자리에서 빼고 뒤 블록에만 둔다.
   - 문턱값: `jev_trial` 29→30화의 공통 앞부분 6,241토큰(DESIGN.md 7장 '블록 순서')이 고친 뒤 아크 안 화 사이에서 5% 넘게 줄면 그 안을 버리고 다시 정한다.
   - 잴 것: 고치기 전과 뒤의 캐시 적중. mock 300화와 측정 데이터에서 아크 안 이웃 화 두 프롬프트의 공통 앞부분 길이(토큰)를 잰다.
   - 실제 캐시 적중은 [plan.md](../plan.md) 대로 고치기 전과 뒤에 Claude API 로 같은 화 몇 개를 보내 `cache_read_input_tokens` 를 견준다. AGENTS.md 의 '비용 드는 모델 실험' 규칙 안에서 한다.
5. 중요도의 셈 — 추천: 묶음 범위(시작 화 ~ 끝 화)에서 생긴 항목을 같은 무게로 센다.
   - 센다: 그 범위에 심었고 지금도 열린 복선(`Foreshadow.planted_ep`, `status = "open"`)
   - 센다: 그 범위에 반영되어 지금도 `Project.facts` 에 있는 확정 사실
   - 센다: 그 범위에 생겨 지금도 숨긴 상대가 있는 비밀(`Secret.hidden_from` 이 비지 않음)
   - 사실과 비밀은 화 번호 필드가 없다. 화 번호는 `Project.history` 의 `StateDelta.episode` 와 `added`(`AddedItems.facts` · `secrets`)로 찾는다. `added` 가 없는 옛 기록은 `new_facts` · `secrets_added` 로 찾는다.
   - 기록에서 화를 찾지 못한 사실은 세지 않는다. `Project.facts` 는 `list[str]` 이라 글자가 같아야 찾는다. 승인 뒤 작가가 고친 사실, 작가 직접 입력, 결말 다시 열기의 `facts`, 검수 처리의 `new_facts` 는 찾지 못할 수 있다.
   - 측정에서 이런 사실이 얼마나 되는지 센다. 많으면 사실에 화 번호를 두는 일(일감 2 의 `Activation` 시작 화와 같은 질문)과 함께 정한다.
   - 무게를 달리 줄지(예: 복선 2, 사실 · 비밀 1)는 측정 결과를 보고 정한다. 처음에는 같은 무게다.
   - 결정적 사건(`StoryEvent.intensity = 3`)과 비밀을 드러낸 사건(`reveals_secret`)도 후보지만, Q23 이 정한 셋이 아니라 넣지 않는다. 넣으려면 사용자와 정한다.
6. 작가의 덮어쓰기 값과 자리 — 추천: `StoryArc` 와 `Part` 에 `keep: SkipJsonSchema[Literal["auto", "pin", "unpin"]] = "auto"` 를 더한다.
   - `pin` 은 늘 남기기(첫 칸), `unpin` 은 계산한 중요도를 0 으로 본다(관련도 · 최근 차례는 그대로).
   - 화면 이름은 '줄거리에 늘 남기기' 와 '중요하지 않음' 이다.
   - 요약이 있는 부 안의 아크는 부 묶음 하나로 들어가므로 그 아크의 `keep` 은 쓰지 않는다. 화면에서도 부의 값만 보인다.
7. 대화 에이전트 — 추천: `agent.py` 는 `keep` 을 고치지 않는다.
   - 블록 설정처럼 작가가 직접 고르는 값으로 둔다(Q29 의 블록 설정 규칙과 같은 결).
   - 지금 에이전트 도구에는 아크 필드를 고치는 쓰기가 있으므로(`arc` 종류) `keep` 이 그 길로 바뀌지 않는지 시험으로 본다.
   - 부 구성을 바꾸는 길은 모두 `pipeline.apply_series` 를 거친다(`series/apply` 엔드포인트, 플롯 대화 · 대화 에이전트의 `parts` 종류).
   - `apply_series` 는 범위가 같은 옛 부에서 `summary` 만 옮기고 나머지 칸은 LLM 이 낸 `Part` 로 바꾼다. 고치지 않으면 작가가 고른 `Part.keep` 이 AI 제안으로 `auto` 가 된다.
   - 그래서 범위(`start_ep`, `end_ep`)가 같은 옛 부의 `keep` 을 `summary` 와 같이 옮긴다.
   - 범위가 바뀐 부의 `keep` 을 어떻게 할지 정한다. 추천: `auto` 로 돌리고 화면에 '부 범위가 바뀌어 줄거리 고르기를 자동으로 돌렸어요.' 를 보인다.
   - 아크도 `keep` 이 남는지 본다: `ArcEdit` 경로(`ARC_EDIT_FIELDS` 에 `keep` 이 없으므로 옛 아크 값을 지켜야 함), `remove_last_arc`, 저장 · 읽기(직렬화) 경로.
8. 뺀 줄의 문구 — 추천: `PAST_DROPPED` 를 '(줄거리 묶음 {수}개는 분량 때문에 뺐습니다: {이름들})' 로 바꾼다.
   - 이름은 묶음 머리(`[아크 3 제목 (21~30화)]`, `[2부 제목 (101~200화)]`)에서 대괄호를 뺀 것이다.
   - 이름이 많으면 5개까지 적고 '외 N개'를 붙인다. 이름 줄이 예산을 끝없이 먹지 않게 하려는 것이다.
   - 이 줄은 LLM 에게 주는 프롬프트라 해요체 규칙 밖이다. 지금 문구의 말투('뺐습니다')를 따른다.
   - 문구를 만드는 함수 `past_dropped_line(names)` 와 읽는 함수 `parse_past_dropped(line) -> (수, 이름들)` 를 `prompts.py` 에 두고, `story_parts` 와 `play_story` 가 같이 쓴다.
   - 읽는 정규식은 앞쪽의 수만 잡는다(`^\(줄거리 묶음 (\d+)개는`). 묶음 이름에 '(21~30화)' 같은 괄호가 들고 제목에 ')' 가 들 수 있어, 이름은 정규식으로 다시 나누지 않는다.
   - `play_story` 는 `story_parts` 가 뺀 이름과 자기가 뺀 묶음 머리(']' 앞)를 합쳐 같은 문구로 쓴다. 플레이의 빼기 규칙(오래된 것부터)은 그대로 둔다.
   - 지금 `play_story` 는 `PAST_DROPPED.format(dropped)` 로 수 하나만 넘긴다. 새 문구는 이름도 받으므로 이 호출을 `past_dropped_line` 으로 바꾼다.
9. 늘 남기기만으로 예산을 넘을 때 — 추천: 그 묶음들도 오래된 것부터 한 줄로 접고, 그래도 넘치면 오래된 것부터 뺀다.
   - 예산을 끝없이 넘기지 않으려는 것이다. Q17 의 '같은 순위 안에서는 최근 것을 남긴다'와 같은 방향이다.
   - 이 경우 프롬프트 보기와 아크 화면에 '늘 남기기로 고른 묶음이 많아 일부를 뺐어요.' 를 보인다.
10. 뒤 아크 기획(`plans=True`)의 관련도 — 추천: 관련도를 0 으로 두고 중요 → 최근 차례로 고른다.
   - 이번 화 플롯이 없어 Q23 의 '이번 화와 관련'을 매길 재료가 없다. 이 안은 Q23 을 건드리지 않는다.
   - 다른 안: 그 프롬프트가 기획하는 아크의 목표 · 갈등을 질의로 쓴다. 이것은 Q23 과 다른 질의라 사용자와 정한다.
   - 시작 전에 확인할 것: `serial_plot_prompt` 의 `start`, `next_arc_prompt` 의 `start`, 플롯 대화가 `story_parts` 에 넘기는 `n`.

| `canon/schema.py` | `StoryArc.keep` · `Part.keep` 을 더한다(정할 것 6). `StoryArc._prompt_view` 가 빼는 칸에 `keep` 을 더하고, `Part` 에 같은 꼴의 `_prompt_view` 를 새로 둔다 |
| `canon/web.py` 또는 `canon/routes/` | 아크 · 부의 `keep` 을 바꾸는 길. 시작 전에 아크 · 부를 고치는 기존 엔드포인트가 있는지 확인하고, 있으면 그 길에 필드를 더한다 |
| `canon/static/plot.js` | 끝난 아크 · 부 카드에 '줄거리에 늘 남기기' · '중요하지 않음' 고르기를 둔다. 계산한 중요도와 그 까닭(열린 복선 N개 · 사실 N개 · 비밀 N개)을 보인다 |

- 일감 3([03-prompt-view.md](03-prompt-view.md))도 `context.py` 의 `BUDGET` 과 `story_parts` 의 뺀 항목 보고(`trace`)를 고친다. 둘은 각자 worktree 를 쓰고, 시작 전에 고칠 줄을 견준다([plan.md](../plan.md)).
- 일감 3 이 먼저 머지되면 뺀 묶음 이름을 그 `trace` 에 넣는다. 이 일감이 먼저면 `story_parts` 가 뺀 묶음 목록을 돌려주는 내부 함수를 두고, 일감 3 이 그것을 쓴다.
- 그 내부 함수는 남은 묶음마다 `rank_past` 의 까닭도 싣는다. 일감 3 이 까닭을 다시 계산하지 않고, 판정이 `context.py` 밖으로 새지 않게 하려는 것이다.
- `story_parts` 의 반환 모양 `(past, cur)` 은 바꾸지 않는다. 부르는 곳이 많다(본문 · 검수 · 기획 · 다음 아크 · 플레이).
- LLM 호출은 생기지 않는다.

## 데이터 · 스키마

- `StoryArc.keep: SkipJsonSchema[Literal["auto", "pin", "unpin"]] = "auto"`
- `Part.keep: SkipJsonSchema[Literal["auto", "pin", "unpin"]] = "auto"`
- `StoryArc` · `Part` 는 아크 · 부 제안의 LLM 응답 형식 안에 든다. 그래서 `SkipJsonSchema` 로 응답 형식에서 뺀다. dict 타입은 쓰지 않는다.
- 기본값 `auto` 는 계산한 중요도를 그대로 쓴다. 옛 `project.json` 은 고치지 않고 읽힌다.
- 프롬프트에서 `keep` 을 뺀다. 아크는 두 길로 프롬프트에 들어가므로 두 곳을 다 고친다.
- 한 길: `llm.dump` 의 프롬프트용 직렬화. `StoryArc._prompt_view` 가 열 계획을 빼는 자리에 `keep` 을 더한다.
- 다른 길: `a.model_dump(exclude={"summary", *ARC_HEAT})`(`structure_text` 와 기획 · 다음 아크 · 플롯 초안 프롬프트). `ARC_HEAT` 에 `"keep"` 을 더한다.
- `Part` 는 `_prompt_view` 가 없고 `dump(p.parts)` 로 들어간다. `Part` 에 같은 꼴의 `_prompt_view` 를 새로 두어 `keep` 을 뺀다.
- 고치지 않으면 예산 안 작품의 장편 프롬프트에도 `"keep": "auto"` 가 들어가 스냅샷이 바뀐다.
- 중요도와 관련도는 저장하지 않는다. 프롬프트를 만들 때마다 계산한다(`context.py` 모듈 설명의 '저장된 데이터는 그대로').
- 새 전역 저장소와 환경 변수는 없다.
- RisuAI HypaV3 의 `isImportant` 와 Canon 의 `keep = "pin"` 은 뜻이 비슷하다. 가져오기 · 내보내기를 하지 않으므로 [compat.md](../compat.md) 에 대응 줄을 더하지 않는다.

## 규칙

### 고르기 차례

1. 접은 줄거리 묶음은 지금처럼 끝난 부(요약 있음) 하나, 또는 아크 하나다(`story_parts` 의 `entries`).
2. 모든 묶음을 자세히 단계로 둔 크기가 `BUDGET["story_past"]`(6,000자) 안이면 지금과 똑같이 낸다.
3. 넘으면 `rank_past` 로 차례를 매긴다: '늘 남기기' > 중요도 > 관련도 > 최근(정할 것 2).
4. 가장 최근 묶음(이번 아크 바로 앞 묶음)은 지금처럼 늘 남긴다. 이번 아크와 이어지는 자리라서다. 차례 맨 앞에 둔다.
5. 차례가 낮은 묶음부터 한 단계씩 접는다(자세히 → 줄임 → 한 줄). 그래도 넘치면 차례가 낮은 묶음부터 뺀다(정할 것 3).
6. 남은 묶음은 차례와 상관없이 화 차례로 늘어놓는다. 줄거리를 읽는 차례가 시간 차례여야 해서다.
   - 정할 것 4 에서 (나) 를 고르면, 관련도 칸으로 남은 묶음은 뒤 블록에서 따로 화 차례로 늘어놓는다.
7. 뺀 묶음이 있으면 맨 앞 줄에 수와 이름을 적는다(정할 것 8).

### 경계 사례

- 묶음이 하나뿐이면 지금처럼 빼지 않는다.
- '늘 남기기' 묶음만으로 예산을 넘을 때는 정할 것 9 를 따른다.
- 관련도는 이번 화 플롯이 비면(아직 플롯 없음) 0 이다. 그러면 중요도 다음은 최근 차례다.
- 묶음 범위의 화 본문이 없으면(본문 없이 요약만 반영한 경우) 그 묶음의 관련도는 0 이다(정할 것 1 의 추천안일 때).
- `plans=True`(뒤 아크 기획)일 때의 관련도는 정할 것 10 을 따른다.
- 같은 `story_parts` 를 쓰는 검수 · 상태 프롬프트도 같은 고르기를 쓴다.
- 관련도의 질의와 가산 낱말은 본문을 보지 않는다(정할 것 1). 그래서 본문이 생긴 뒤에도 쓰기와 검수가 같은 줄거리를 본다.

### 결정성

- 같은 데이터와 같은 화에는 같은 줄거리가 나온다. 무작위를 쓰지 않는다(Q23).
- 값이 같으면 최근 묶음, 그다음 묶음 번호로 가른다.

### 승인과 되돌리기

- 고르기는 저장된 데이터를 바꾸지 않는다. 무엇을 넣을지만 고른다.
- `keep` 은 작가가 넣는 값이다. AI 출력이 아니므로 승인 흐름을 거치지 않는다.
- 자동 집필은 같은 고르기를 쓴다. 따로 정책이 없다.
- 대화 에이전트는 `keep` 을 고치지 않는다(정할 것 7).
- 단편은 `story_parts` 가 고르기 앞에서 돌아가므로(`not p.serial` 갈래) 바뀌지 않는다.

### 빌려 온 생각

- RisuAI HypaV3 는 넘친 대화를 요약 묶음으로 만들고, 중요 표시 묶음 → 최근 → 유사(임베딩) → 무작위 차례로 기억 예산을 채운다.
- Canon 은 그 생각 가운데 '한 기준만 쓰지 않고 중요 · 관련 · 최근을 섞는다'만 빌린다. 비율로 예산을 떼는 생각은 정할 것 2 의 다른 안으로만 둔다.
- 무작위와 임베딩은 빌리지 않는다(Q23). 2026-11-03 검수 실험에서 임베딩(gemini-embedding-001)은 3글자 조각 점수보다 더 찾지 못했다(DESIGN.md 7장 '검수').
- RisuAI 코드는 옮기지 않는다(Q4).

## 화면 · 명령줄 · 프롬프트

- 프롬프트 자리는 그대로다: '# 지금까지의 줄거리 (끝난 부와 아크)' 블록(`serial_episode_context`)이다. 블록 차례와 블록 문구의 머리는 바꾸지 않는다.

  - 문구: '열린 복선 2개 · 확정 사실 5개 · 비밀 1개가 이 아크에서 생겼어요.'
  - 문구: '이 아크는 지금 줄거리에서 빠졌어요.' (예산 때문에 빠진 묶음일 때)
  - 바꾸면 '저장했어요.' 를 보인다.
- 프롬프트 보기(일감 3): 뺀 묶음 이름과 남은 묶음마다 남은 까닭('늘 남기기', '중요', '이번 화와 관련', '최근')을 보인다.

## 확인하지 못할 것

- 실제 작품에서 접은 줄거리가 예산을 넘는지 모른다. 측정 데이터 넷(nsfw_saintess 87화, nsfw_saintess-claude 83화, subway-1-수정본 72화, 불타는-세상에서-내-캠핑카만-진화한다 12화)이 6,000자를 넘는지는 시작 전에 확인할 것이다.
- 넷 모두 예산 안이면 이 일감은 지금 작품에서 동작이 바뀌지 않는다. 그때 효과는 mock 300화로만 본다.
- 고른 줄거리가 본문을 더 낫게 하는지는 대리값으로만 본다: 뺀 묶음에서 생긴 인물 · 이야기 요소 · 복선이 이번 화 최종 본문에 다시 나오는 경우를, 오래된 것부터 빼기와 고르기로 견준다(일감 1 의 대리값과 같은 셈).
- 이 대리값 비교에는 LLM 비용을 쓰지 않는다.
- 캐시 손실(정할 것 4)은 mock 으로 공통 앞부분 길이를 잰다. 실제 Claude API 캐시 적중은 고치기 전과 뒤의 작은 실측으로만 본다(정할 것 4).
- 작가의 취향 판단은 사용자만 할 수 있다.

사용자가 할 단계:

1. 정할 것 1~10 을 고른다.
2. 정할 것 4 의 캐시 실측이 문턱값을 넘으면 (가) · (나) 를 다시 정한다.
3. 머지 뒤 긴 장편 하나에서 플롯 단계의 끝난 아크 카드를 열고, 계산한 중요도와 그 까닭이 맞는지 본다.
4. 그 작품의 쓰기 화면 프롬프트 보기에서 뺀 묶음 이름이 납득되는지 본다.
