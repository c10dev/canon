# 09. 옛 장면 불러오기 (집필용)

상태: 미룸 (2026-11-08, 8번을 기다림) · 계획: [plan.md](../plan.md) 의 9번 · 먼저: 8번 (9b 는 9a 도)

## 목표

장편 본문 쓰기 프롬프트의 화마다 바뀌는 쪽에, 이번 화 플롯과 겹치는 옛 화 본문 단락을 예산 안에서 짧게 넣는다.
작가에게는 접은 줄거리에서 빠진 옛 장면의 세부(물건, 말, 장소의 모양)를 AI 가 이어받는 쪽으로 달라진다.
이 일감은 측정(9a)과 구현(9b) 두 걸음이다.
9a 의 결과가 '정할 것'의 문턱을 넘지 못하면 9b 는 하지 않고, 결과를 README 에 '측정에서 이득 없음'으로 적고 끝낸다.
9a 는 동작을 바꾸지 않는다. LLM 을 부르지 않는다.
단편(`form = "short"`)은 바꾸지 않는다.
따르는 정한 규칙: [README.md](../README.md) 의 2026-11-08 결정 Q14(a) · Q15 · Q23 · Q30.

### 이 명세서의 낱말

README 의 용어에 더해 이 명세서에서만 아래 뜻으로 쓴다. 9b 를 하면 README 의 용어 표에 옮긴다.

| 낱말 | 뜻 |
|---|---|
| 옛 장면 불러오기 | 쓰기 프롬프트에 옛 화 본문 단락을 찾아 넣는 일 |
| 발췌 블록 | 옛 장면 불러오기가 넣는 블록 하나 |

| 찾는 글 | `context.recall` 에 넘기는 질의 글(`query`) |

## 정할 것

1. 9a 측정 스크립트를 어디 두나 — 추천: 일감 1의 `scripts/context_measure.py` 에 `--recall` 갈래로 더한다. 직전 화 상태로 다시 짓기(`stattrial.before` 꼴)와 자료 복사를 함께 쓴다.
2. 9a 를 언제 돌리나 — 추천: 일감 8(접은 줄거리 고르기)을 머지한 뒤 그 코드로 돌린다. 접은 줄거리가 남기는 묶음이 바뀌면 '컨텍스트 밖' 세부도 바뀌기 때문이다(plan.md 의 '먼저 끝날 것').
3. 9b 로 넘어가는 문턱 — 추천: 네 작품 중 셋 이상에서 아래 세 가지를 모두 넘을 때 9b 를 한다.
   - 옛 장면 참조가 하나 이상 있는 화가 확정 화의 10% 이상
   - 흉내 낸 발췌 블록(추천 예산)이 옛 장면 참조의 30% 이상을 덮음
   - 발췌 블록 단락 가운데 본문의 옛 장면 참조와 이어지는 단락이 20% 이상(나머지는 군더더기)
4. 측정 B(작가가 인정한 옛 화 모순)를 문턱에 넣나 — 추천: 넣지 않고 함께 적는다. 저장된 지적이 작품마다 적고 검수를 켠 화만 있어서다. 측정 B 가 0 이 아니면 그 지적을 사람 판정 표본에 먼저 넣는다.
5. 단락 단위 — 추천: 두 가지를 측정으로 견준다.
   - 지금 단락: 빈 줄로 나누고 `PARA_MAX` 700자까지
   - 줄 묶음: 앞뒤 2줄을 붙인 창, 300자까지
   - 2026-11-03 검수 실험에서는 줄 묶음이 낫지 않았다.
   - 집필용은 근거 한 줄이 아니라 장면 맥락이 목적이라 따로 잰다.
6. 찾는 글 — 추천: 후보 둘을 견준다: 이번 화 플롯 글(`elements.plot_text`)만, 그리고 플롯 글 + 스토리보드. 쓰기 때는 본문이 없으므로 본문은 찾는 글에 넣지 않는다.
7. 덧붙이는 낱말(`terms`) — 추천: 검수와 같게 `context.query_terms` + 이번 화 조연 이름을 쓴다(`prompts.check_recall` 과 같은 규칙).
8. 빼는 화(`skip`) — 추천: 직전 화만 뺀다. 직전 화는 이미 원문 끝부분이나 전체로 들어간다(`prompts.prev_block`).
9. 예산 — 추천: `context.BUDGET["write_recall"]` 를 새로 둔다.
   - 후보 1,000 · 2,000 · 4,000자를 9a 로 견준다.
   - 문턱을 넘는 값 가운데 가장 작은 것을 고른다.
   - 검수 발췌 8,000자(`check_recall`)보다 작게 시작한다.
   - 까닭은 쓰기 프롬프트가 넣은 글의 문체를 따라 하기 때문이다(`prompts.prev_block` 설명의 쇠맛 연구 2026-10-30).
10. 점수 하한 — 추천: 단락 점수가 하한보다 낮으면 넣지 않는다.
   - 하한은 9a 에서 군더더기와 덮음을 함께 보고 정한다.
   - 하한이 필요한 까닭: `PassageIndex.find` 는 점수가 0 보다 큰 단락을 모두 후보로 둔다.

   - 하한 없이 예산이 얼마나 차는지는 9a 에서 잰다.
11. 어느 호출에 넣나 — 추천: 본문 쓰기(`episode_prompt`)에만 넣는다.
   - `build_episode_context` 의 `write=True` 는 다듬기(`rework_prompt`)도 넘기므로 그 인자로 가르지 않는다. 새 인자 `recall` 로 가른다(바꿀 곳 9b).

12. 블록 설정(일감 3)과의 관계 — 추천: 발췌 블록은 끌 수 있는 블록이다.
   - README 의 Q19 의 끌 수 없는 세 블록에 들지 않는다.
   - 일감 3 이 머지되어 있으면 블록 켜고 끄기와 블록 예산에 '옛 장면 발췌'로 더한다.
   - 기본값은 9a 가 문턱을 넘었으면 장편에서 켬이다.
13. 9a 뒤 유료 확인 — 추천: 9a 가 문턱을 넘으면 작은 블라인드 비교를 한다. 문턱을 넘지 못하면 하지 않는다.

### 측정 A: 옛 장면 참조

- 확정 화 n 마다 옛 화(n-2 화까지)의 단락 색인을 만든다(`PassageIndex(p, n, skip={n-1})`, p 는 복사한 작품).
- 드문 글 조각은 색인의 문서 빈도가 `COMMON`(0.3) 비율 이하인 한글 3글자 조각이다(`PassageIndex.find` 와 같은 규칙).
- 최종 본문을 문장으로 나눈다.
- 문장 하나와 옛 화 단락 하나가 드문 글 조각을 K 개 이상 함께 쓰면 짝 후보다. K 후보는 3 · 5 다.
- 함께 쓴 조각 가운데 다시 지은 쓰기 프롬프트(`episode_prompt`)에도 있는 조각은 뺀다. 남은 조각이 K 개 이상이면 그 문장은 옛 장면 참조다.
- 덮음: 흉내 낸 발췌 블록에 그 짝의 옛 단락(줄 묶음이면 그 줄을 품은 창)이 들어 있으면 덮은 것이다.
- 군더더기: 발췌 블록 단락 가운데 어느 옛 장면 참조와도 짝이 아닌 단락이다. 글자 수로도 센다.
- 출력 JSON 한 행: 작품, 화, 문장 번호, 짝 옛 화, 짝 단락 번호, 함께 쓴 조각 수, 컨텍스트 밖 조각 수, 흉내 조건(단위 · 찾는 글 · 예산 · 하한), 덮음 여부.

### 측정 B: 작가가 인정한 옛 화 모순

- 확정 화의 지적(`Episode.findings`) 가운데 `source_episode` 가 1 이상 n-2 이하인 것만 본다.
- '작가가 고침'은 상태가 `fixed` 이고 `closed_by` 가 `author` 또는 `one` 인 지적이다(`canon/schema.py` 의 `Finding.status` · `Finding.closed_by`).
- `closed_by` 가 `recheck` 인 `fixed` 는 다시 검수에서 문장이 사라진 것이라 작가의 판단이 아니다. 세지 않는다.
- '작가가 그대로 둠'은 상태가 `kept` 인 지적이다. 따로 센다(`canon/findings.py` 의 `DECIDED`).
- 그 지적의 `source_quote` 가 다시 지은 쓰기 프롬프트에 없으면 '컨텍스트 밖 모순'이다.
- 흉내 낸 발췌 블록이 `source_quote` 를 품은 단락을 넣었는지 센다.
- 시작 전에 확인할 것: 네 작품에 이런 지적이 몇 개 있는지.

## 규칙

### 대리 정답의 한계

- 본문은 발췌 블록 없이 쓰였다. 측정 A 는 AI 가 접은 줄거리 · 사실 · 상태만으로도 옛 장면을 되살린 곳만 본다. 되살리지 못해 빠진 세부는 보이지 않는다.
- 그래서 측정 A 는 '필요했던 옛 장면'을 적게 센다. 측정 B 가 빠진 세부가 모순으로 드러난 곳을 일부 보탠다.
- 측정 A 의 정답과 `context.recall` 이 같은 글 조각 점수를 쓴다. 덮음이 부풀 수 있다. 찾는 글은 플롯(정답은 본문)이라 같지는 않다. 사람 판정으로 이 치우침을 센다.
- 흔한 표현(예: 고개를 끄덕이는 말)이 짝으로 잡히면 군더더기가 줄어 보인다. 드문 조각 규칙과 K 로 거르고, 사람 판정에서 '우연한 겹침' 수를 센다.

### 2026-11-03 실험에서 아는 약점

- 웹소설은 한 줄이 한 단락이다(평균 28자). 단락 하나에 맥락이 거의 없다(DESIGN.md 7장 '컨텍스트 (장편)' 의 검수 항목).
- 검수 실험에서 근거 줄이 발췌에 든 것은 2.4만 자에서도 58쌍 가운데 19쌍뿐이었다.
- 같은 실험에서 문장마다 찾기 · 줄 묶기 · 임베딩(`gemini-embedding-001`)도 더 많이 넣지 못했다.
- 짧은 단락은 점수의 길이 누름(`sqrt(1 + 조각 수/120)`, 조각 수는 단락의 서로 다른 3글자 조각 수)이 거의 없어 드문 낱말 하나로 위에 오른다. 9a 는 단락 단위와 점수 하한을 이 약점에 맞춰 견준다(정할 것 5 · 10).
- 임베딩은 쓰지 않는다(README 의 Q23 · 넣지 않는 것). 다시 넣으려면 사용자와 정한다.

### 사람 판정

- 표본 20개: 측정 A 의 옛 장면 참조 12개, 군더더기로 센 발췌 단락 4개, 측정 B 의 지적 4개(없으면 측정 A 로 채운다).
- 판정 칸: '정말 옛 장면을 가리킴' · '우연한 겹침' · '컨텍스트 다른 곳에 이미 있음' · '모르겠음'.
- 사용자가 읽는다(일감 1 의 정할 것 12 와 같다).

### 9b 동작

- 장편에서만 쓴다. 단편 경로는 한 글자도 바뀌지 않는다.
- `build_episode_context(recall=True)` 일 때만 넣는다. 그 인자는 `episode_prompt` 만 넘긴다. 다듬기(`rework_prompt`)는 바뀌지 않는다.
- 화면의 컨텍스트 목록(`write=False`)에는 일감 3 의 프롬프트 보기가 실제 요청 본문을 보일 때 함께 보인다.
- 옛 화가 없거나(n ≤ 2) 하한을 넘는 단락이 없으면 블록을 넣지 않는다.
- 단락은 화 차례, 화 안에서는 원래 차례로 엮는다(`PassageIndex.find` 의 출력 차례).
- 하한을 넘었지만 예산 때문에 넣지 못한 단락 수를 블록 머리에 적는다.
- 블록 끄기(일감 3)나 예산 0 이면 블록이 없고 프롬프트는 9b 전과 같다.
- 승인 흐름: 발췌 블록은 읽기 전용 자료라 승인할 것이 없다. 자동 집필과 `-y` 도 같은 프롬프트를 쓴다.
- 되돌리기: 저장하는 것이 없어 되돌릴 것이 없다.
- 대화 에이전트(`canon/agent.py`)는 바뀌지 않는다. `find_text` 도구는 지금처럼 `context.recall` 을 쓴다. 에이전트는 블록 끄고 켜기와 블록 예산을 고치지 않는다(README 의 Q29).

## 화면 · 명령줄 · 프롬프트

### 프롬프트

- 프롬프트는 `canon/prompts.py` 한 곳만 고친다. API 경로와 작업지시서(`brief`) 경로가 같은 `episode_prompt` 를 쓰므로 `brief` 출력에도 블록이 보인다.
- 자리: 장편 `prev_rest` 의 첫 블록이다. 직전 화 본문 바로 뒤에 온다.
- 스토리보드가 없으면 차례는 발췌 블록 → 시간 → 이동 → 장면 연출 → `pre` → `between` → '# 이번 화 플롯' 이다(`prompts.py` 의 `prev_rest = tl + tr + stg + pre + between` 앞에 붙임).
- 스토리보드가 있으면 차례는 발췌 블록 → 스토리보드 → 장면 연출 → `between` → '# 이번 화 플롯' 이다.
- 이 자리라 `write_head`(직전 화 본문까지의 앞부분)가 바뀌지 않는다. 스토리보드 만들기 · 큐 시트 · 쓰기가 함께 쓰는 캐시가 그대로 맞는다(AGENTS.md 의 '바뀌지 않는 블록이 앞').
- 예산: `context.BUDGET["write_recall"]`(정할 것 9).
- 머리글 꼴은 검수 발췌(`prompts._check_budget` 의 '옛 화에서 찾은 관련 단락')를 따른다. 화마다 '### {화}화 {제목} (발췌)' 아래 단락을 '…' 로 잇는다.
- 머리글에는 내용 연결용이라는 것과 문장을 옮겨 쓰지 말라는 것을 적는다. 정확한 문구는 9b 에서 `prompts.py` 에 정하고 `brief` 로 확인한다.
- RisuAI 의 기억 · 로어북 프롬프트 글은 옮기지 않는다(README 의 Q4).

### 화면

- 새 화면은 없다.
- 일감 3 이 머지되어 있으면 프롬프트 보기의 블록 목록에 '옛 장면 발췌' 줄이 생기고, 블록 설정에 켜고 끄기와 예산 칸이 생긴다.
- 뺀 단락 수는 프롬프트 보기에 '관련 단락 N개 중 M개를 넣었어요' 꼴로 보인다. 문구 규칙은 `docs/design/README.md` 를 따른다.
- 화면 모양을 바꾸지 않으면 `docs/design/` 은 고치지 않는다.
