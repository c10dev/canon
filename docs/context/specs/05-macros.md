# 05. CBS 읽기 매크로

상태: 설계 · 계획: [plan.md](../plan.md) 의 5번 · 먼저: 2번

## 목표

작가가 이야기 요소 설명과 작가 메모에 `{{user}}`, `{{char}}`, `{{getvar::인물.스탯}}` 같은 매크로를 적으면, 프롬프트를 조립할 때 그 화의 값으로 바뀌어 AI 에게 간다.
예: 이야기 요소 '각인' 설명에 "{{char}}의 각인은 레벨 {{getvar::도현.레벨}}부터 빛난다"라고 적으면, 프롬프트에는 그 화 시점의 인물 이름과 상태창 값이 들어간다.
저장한 글은 바뀌지 않는다.
매크로는 값을 읽기만 한다. 조건 블록과 값 쓰기(`setvar` 무리)는 하지 않는다.
매크로 이름은 RisuAI CBS(Curly Braced Syntax) 이름을 따른다. 나중에 CBS 를 쓴 자료를 옮겨 올 길을 열어 두려는 것이다.

이 일감이 따르는 정한 규칙(모두 [README.md](../README.md) 의 2026-11-08):

- Q2: Canon 원칙이 이긴다. RisuAI 생각은 Canon 데이터 모델과 승인 흐름으로 옮겨서만 들인다.
- Q4: RisuAI 코드(GPL-3.0)와 기본 프롬프트 글을 베끼지 않는다. 생각과 공개 데이터 형식만 쓴다.
- Q11: 매크로는 값만 읽는다. 조건 블록과 `setvar` 는 없다.
- Q20: 매크로는 RisuAI CBS 이름을 쓴다.
- Q25: `{{user}}` 는 주인공이다.
- Q25: `{{char}}` 는 항목에 이어진 인물이고, 없으면 이번 화 시점 인물이다.
- Q25: `{{getvar::인물.스탯}}` 은 상태창 값이다.
- Q25: `chatindex` 대신 화 번호 함수를 둔다.
- Q25: 모르는 함수와 `#when` 블록은 그대로 두고 경고한다.
- Q25: `setvar` 무리는 경고만 한다.
- Q26: Canon 필드 이름은 그대로 두고, CBS 와의 1:1 대응표를 [compat.md](../compat.md) 에 쓴다.
- Q30: 5번은 2번(`Activation` 모델과 판정)이 머지된 뒤 시작한다.

작업 요청에서 온 것:

- 문법, 쓸 수 있는 곳, 값의 시점, 펼치는 차례, 원문과 펼친 글을 함께 보이는 것은 작업 요청에서 왔다.
- 이 다섯은 사용자 결정(Q1~Q30)에 없다. 그래서 정할 것 18~22 에 추천으로 둔다.
- 이 명세서의 나머지는 그 추천대로 정한다고 보고 썼다. 추천과 다르게 정하면 그 부분을 고친다.

## 정할 것

1. 작가 메모는 어느 칸인가 — 추천: `Meta.notes`. 설정 단계 화면(`canon/static/setup.js`)에서 '메모'라고 적힌 작가의 자유 글 칸이다.
   - `meta_text`(`canon/prompts.py`)는 `Meta` 를 통째로 넣어서 `Meta.theme` · `Meta.tone` · `Meta.logline` 도 자유 글로 들어간다.
   - `static_context` 는 `p.world` 의 자유 글도 넣는다.
   - 이 칸들은 이번 일감에서 펼치지 않는다(정할 것 22).
2. 화 번호 함수의 이름 — 추천: `{{episode}}`. 인자 없이 이번 화 번호를 숫자로 낸다.
3. `{{chatindex}}` 를 `{{episode}}` 의 다른 이름으로 받을까 — 추천: 받지 않는다. RisuAI 의 `chatindex` 는 메시지 번호라 뜻이 다르다(0 에서 시작한다는 것은 확인하지 못했다. '확인하지 못할 것'). 모르는 함수처럼 그대로 두고 경고에 "`{{episode}}`를 쓰세요"를 덧붙인다.
4. `setvar` 무리의 글은 프롬프트에 남길까 지울까 — 추천: 모르는 함수처럼 그대로 남기고 경고한다. 값을 바꾸지 않는다는 것만 다르게 알린다.
5. `#when` 같은 블록 안에 든 매크로를 펼칠까 — 추천: 펼치지 않는다. 여는 표시(`{{#...}}`)부터 닫는 표시(`{{/...}}`)까지 통째로 그대로 둔다. 반만 바뀐 블록이 생기지 않게 하려는 것이다.
6. 겹친 매크로(`{{getvar::{{char}}.체력}}`)를 받을까 — 추천: 받는다. 안쪽부터 펼치고 최대 3번 돈다. 펼쳐 넣은 값은 다시 훑지 않는다.
7. `getvar` 의 인물을 무엇으로 찾을까 — 추천: 인물 id 또는 이름이 똑같을 때만 맞춘다. 알려진 인물 id · 이름 가운데 인자 앞부분과 맞는 가장 긴 것을 고르고, 그 뒤 `.` 다음을 스탯 이름으로 본다.
8. `getvar` 의 인물이나 스탯이 없으면 — 추천: 그대로 두고 경고한다. 빈칸으로 바꾸면 작가가 틀린 이름을 알아채기 어렵다.
9. 시점 인물이 없을 때(전지 시점, 시점을 적지 않음) `{{char}}` 는 — 추천: 주인공(`{{user}}` 와 같은 인물)으로 펼치고 프롬프트 보기에 "시점 인물이 없어 주인공으로 넣었어요"를 보인다.
10. 이야기 요소에 이어진 인물이 여럿이면 `{{char}}` 는 — 추천: `StoryElement.characters` 의 첫 인물. 작가가 차례를 바꿔 고를 수 있다.
11. 앞쪽 블록에 있는 작가 메모의 화마다 바뀌는 값 — 추천: `Meta.notes` 에서는 화가 바뀌어도 값이 같은 매크로(`{{user}}`)만 펼친다. `{{char}}`, `{{episode}}`, `{{getvar}}` 는 그대로 두고 경고한다. `meta_text` 는 `static_context` 안에 있어 화마다 바뀌면 캐시가 깨진다(AGENTS.md 설계 원칙).
12. 쓸 차례가 아닌 화(n화가 `finalized` 이거나 n화 뒤에 반영한 화가 있음. 예: 지난 화 프롬프트 보기, 옛 화 검수 · 다시 생성)의 '쓰기 바로 전 상태' — 추천: `p.snapshot(n-1)` 이 있으면 그 스냅샷의 상태창 값을 쓴다.
   - 스냅샷이 없으면 지금 상태를 쓰고 프롬프트 보기에 경고를 보인다.
   - 스냅샷은 장편에서 `prune_snapshots` 가 지운다(`canon/pipeline.py`, `keep_snapshots` 를 켜면 남긴다). 단편은 지우지 않는다.
13. 한 화에 매이지 않는 기획 프롬프트(`plan_block` 을 쓰는 아크 · 플롯 기획)의 화 번호와 시점 인물 — 추천: 그 기획이 다루는 첫 화로 정한다. 기획 범위가 없는 프롬프트는 쓰지 않은 첫 화로 정한다.
14. 설정을 다루는 프롬프트(이야기 요소 영향 분석 `canon/prompts.py` 의 `elements.describe(p, el)` 를 부르는 두 곳, 명령줄 요소 목록)도 펼칠까 — 추천: 펼치지 않는다. 설정 그 자체를 보고 판단하는 곳이라 원문이 맞다.
   - 인물 탄생 프롬프트(`birth_prompt`)는 세력 이야기 요소의 설명을 잘라 넣는다. 추천: 펼치지 않는다.
   - 되풀이 검사(`canon/echoes.py` 의 `_canon_text`)는 이야기 요소 설명 원문을 어간으로 쪼갠다. 추천: `{{...}}` 를 떼고 쪼갠다.
15. 활성화의 재귀 훑기(2번)는 원문과 펼친 글 가운데 무엇을 훑나 — 추천: 펼친 글. AI 가 받는 글과 같은 글로 판정한다.
16. 함수 이름의 대소문자 — 추천: 가리지 않는다. 작가가 `{{User}}` 처럼 적어도 맞게 하려는 것이다. CCv3 명세가 CBS 를 대소문자 무시로 적었다는 것은 확인하지 못했다('확인하지 못할 것').
17. CCv3 의 `{{// 주석}}` 을 지울까 — 추천: 이번에는 하지 않는다. 정한 네 매크로 밖이라 모르는 함수처럼 다룬다. 쓰임이 보이면 따로 정한다.
18. 문법 — 추천: `{{이름}}` 과 `{{이름::인자}}`. RisuAI 가 인자를 `::` 로 나눈다([compat.md](../compat.md) 3절).
19. 매크로를 쓸 수 있는 곳 — 추천: 이야기 요소 설명과 작가 메모(정할 것 1)만.
20. 값의 시점 — 추천: 이번 화를 쓰기 바로 전 상태.
21. 펼치는 차례와 보이는 법 — 추천: 저장한 글은 그대로 두고 조립할 때 항목마다 펼친다. 예산은 펼친 글로 센다. 프롬프트 보기에는 원문과 펼친 글을 둘 다 보인다.
22. 복선 · 사실 글, 인물의 불변 설정, `Meta.theme` · `Meta.tone` · `Meta.logline` · `p.world` 에서도 펼칠까 — 추천: 이번 일감에서는 하지 않는다.
   - Q7 의 `Activation` 은 인물 · 복선 · 사실도 덮지만, 매크로는 쓰임을 본 뒤 넓힌다.
23. `{{bot}}` 을 `{{char}}` 의 다른 이름으로 받을까 — 추천: 받는다. RisuAI 가 두 이름을 같은 뜻으로 쓴다([compat.md](../compat.md) 3절).

## 데이터 · 스키마

- 저장하는 필드는 새로 만들지도 바꾸지도 않는다. `StoryElement.description` 과 `Meta.notes` 는 원문 그대로 저장한다.
- 옛 `project.json` 은 고치지 않고 읽힌다.
- LLM 응답 형식은 바뀌지 않는다. 가짜 응답(`canon/mock.py`)도 바꾸지 않는다.
- `MacroEnv`(`canon/macros.py`, 저장하지 않는 값 묶음) 필드는 아래와 같다.
  - `user: str` 주인공 이름. 없으면 빈칸.
  - `pov: str` 이번 화 시점 인물 이름. 시점 인물이 없으면 정할 것 9 에 따라 주인공 이름.
  - `pov_fallback: bool` `pov` 에 주인공을 넣었는지. 참이면 정할 것 9 의 경고를 낸다.
  - `names: list[tuple[str, str]]` 모든 인물의 (인물 id, 이름) 목록. `StoryElement.characters` 의 id 를 이름으로 바꾸는 데 쓴다.
  - `episode: int` 이번 화 번호.
  - `stats: list[tuple[str, str, str, str]]` (인물 id, 인물 이름, 스탯 이름, 값) 목록.
  - `dynamic: bool` 화마다 바뀌는 매크로를 펼쳐도 되는 곳인지. `Meta.notes` 는 거짓(정할 것 11).
- `MacroUse`(웹 응답 모델) 필드: `where`(어느 칸, 예: '이야기 요소 각인 설명'), `raw`(원문 조각), `value`(펼친 값, 펼치지 않았으면 빈칸), `note`(경고 문구, 없으면 빈칸).
- `canon/macros.py` 의 `expand(text, env) -> tuple[str, list[MacroUse]]` 가 펼친 글과 쓰임 목록을 함께 낸다.
- CBS 이름과 Canon 값의 대응은 [compat.md](../compat.md) 의 CBS 표에 한 줄씩 더한다.

| CBS | Canon 값 | 비고 |
|---|---|---|
| `{{user}}` | 주인공 이름 | `opening.hero_name` 의 규칙: 역할에 '주인공'이 든 인물, 없으면 첫 주역(`tier == "main"`) |
| `{{char}}` | 항목에 이어진 인물 이름, 없으면 이번 화 시점 인물 이름 | 시점 인물은 `prompts.pov_character(p, n)` |
| `{{getvar::인물.스탯}}` | 그 인물의 상태창 값(`CharacterState.stats` 의 `StatValue.value`) | RisuAI 는 대화 변수를 읽는다. Canon 은 승인한 상태창만 읽는다 |
| `{{chatindex}}` 대신 `{{episode}}` (정할 것 2) | 이번 화 번호 | 이름은 정할 것 |
| `setvar` · `addvar` · `setdefaultvar` 무리 | 없음 | 경고만 한다 |
| `{{#when ...}}` 블록 | 없음 | 그대로 두고 경고한다 |

## 규칙

찾기:

- 매크로는 `{{` 와 `}}` 사이의 글이다. 안에 `{` 나 `}` 가 없는 가장 안쪽 쌍부터 찾는다.
- 인자는 `::` 로 나눈다. 첫 조각이 함수 이름이다.
- 함수 이름은 앞뒤 빈칸을 떼고 대소문자를 가리지 않는다(정할 것 16).
- `{{` 로 열고 닫지 않은 글은 매크로가 아니다. 그대로 두고 경고하지 않는다.
- `{{#` 로 시작하는 매크로는 블록을 연다. 맞는 `{{/` 까지 통째로 그대로 두고 경고를 하나 낸다(정할 것 5).
- 펼쳐 넣은 값은 다시 훑지 않는다. 상태창 값에 `{{` 가 들어 있어도 매크로로 보지 않는다.
- 겹친 매크로는 안쪽부터 펼치고 최대 3번 돈다(정할 것 6). 3번 뒤에도 남은 매크로는 그대로 둔다.

펼치기:

- `{{user}}`: 주인공 이름. 주인공이 없으면 그대로 두고 경고한다.
- `{{char}}`: `elements.describe` 가 항목마다 직접 정한다. `el.characters` 의 첫 인물 이름(정할 것 10, `env.names` 로 찾음)이고, 없으면 `env.pov` 다.
- `env.pov_fallback` 이 참인데 `env.pov` 를 썼으면 정할 것 9 의 경고를 낸다.
- `{{bot}}` 은 정할 것 23 에 따라 `{{char}}` 와 같다.
- `{{char}}` 를 `Meta.notes` 에서 쓰면 이어진 인물이 없다. 정할 것 11 에 따라 그대로 두고 경고한다.
- `{{getvar::인물.스탯}}`: 인물 id 또는 이름이 똑같이 맞고, 그 인물의 상태창에 같은 이름의 스탯이 있으면 그 값(정할 것 7).
- `{{getvar}}` 의 값은 저장된 글 그대로다(예: '80/100', '3,200 골드'). 단위를 바꾸거나 계산하지 않는다.
- `{{episode}}`: 이번 화 번호를 숫자로 낸다.
- 모르는 함수: 그대로 두고 경고한다.
- `setvar` 무리: 상태를 바꾸지 않는다. 글은 정할 것 4 에 따라 다루고 경고한다.
- 상태를 바꾸는 매크로는 어느 경우에도 없다. 상태는 상태 승인 화면에서만 바뀐다(AGENTS.md 설계 원칙).

값의 시점:

- 값은 이번 화를 쓰기 바로 전 상태로 정한다.
- n화가 `finalized` 가 아니고 앞 화가 모두 `finalized` 이면 지금 `p.states` 가 그 상태다. `# 인물 현재 상태` 블록과 같은 값이다.
- 쓰고 아직 반영하지 않은 마지막 화의 검수 · 다시 생성도 이 경우다.
- n화가 `finalized` 이거나 n화 뒤에 반영한 화가 있으면 정할 것 12 를 따른다.
- 상태 변경안을 만드는 프롬프트는 이번 화를 반영하기 전에 만든다. 그래서 같은 '쓰기 바로 전 상태'를 쓴다.

예산과의 차례:

- 펼치기는 예산을 세기 전에 한다.
- `context.BUDGET` 에 맞춰 자르는 일, 프롬프트 보기의 블록별 글자 수, 자동 집필의 크기 어림(`autorun.estimate`)은 모두 펼친 글로 센다.
- 2번의 재귀 훑기는 정할 것 15 를 따른다.
- 활성 키워드(이름 · 다른 이름 · 보조 키 · 제외 키)에는 매크로를 쓰지 않는다. 키워드 안의 `{{` 는 글자 그대로 본다.

저장과 되돌리기:

- 저장한 글은 바뀌지 않는다. 펼친 글은 프롬프트에만 있다.
- 되돌릴 것이 생기지 않는다.
- 시험은 컨텍스트를 만든 뒤 `project.json` 이 그대로인지 본다.

단편과 장편:

- 단편(`form = "short"`)과 장편(`form = "serial"`)에서 똑같이 펼친다.
- 매크로가 없는 글은 펼친 뒤에도 똑같다. 그래서 매크로를 쓰지 않은 작품의 프롬프트는 바뀌지 않는다.

캐시:

- `Meta.notes` 는 `static_context` 의 `meta_text` 안에 있다. 이 칸은 화가 바뀌어도 같은 값만 펼친다(정할 것 11).
- 이야기 요소 블록은 화마다 바뀌는 쪽에 있다. 여기서 펼친 값이 화마다 달라져도 캐시 원칙을 깨지 않는다.

승인 흐름과 대화 에이전트:

- 매크로는 AI 출력이 아니라 작가가 적은 글이다. 승인 흐름에 새로 더할 것이 없다.
- AI 가 이야기 요소 설명을 제안할 때(설정 제안, 상태 변경안의 새 장소) 매크로를 쓰라고 시키지 않는다.
- 대화 에이전트(`canon/agent.py`)는 이야기 요소 설명을 고치는 도구가 없다. 이 일감에서 더하지 않는다.
- 대화 에이전트의 읽기 도구(`read_cast` 등)는 원문을 보인다.

## 화면 · 명령줄 · 프롬프트

프롬프트:

- 프롬프트 문구는 바꾸지 않는다. 블록 차례도 바꾸지 않는다.
- 새 블록이 없어 새 예산 키가 없다.
- 펼치기는 `canon/prompts.py` 가 부르는 한 길로만 한다. API 경로와 작업지시서(`brief`) 경로가 같은 펼친 글을 받는다.
- 작업지시서와 프롬프트 놀이터(`promptlab` 의 불러오기)에도 펼친 글이 들어간다. 경고는 넣지 않는다.
- 고친 뒤 `brief` 출력에 매크로가 펼쳐졌는지 본다.

프롬프트 보기(3번이 만든 화면에 더함):

- 매크로가 있는 블록에 '매크로 N개' 줄을 보인다.
- 펼치면 한 줄에 하나씩 '어느 칸 · 원문 → 값'을 보인다. 예: "이야기 요소 '각인' 설명 · {{getvar::도현.레벨}} → 7".
- 블록 본문은 펼친 글이다. '원문 보기'를 켜면 그 블록을 저장된 원문으로 보인다.
- 경고 문구(해요체, 영문 뒤 조사는 붙인다):
  - 모르는 함수: "'{{roll::6}}'은 Canon이 모르는 매크로라 그대로 보냈어요."
  - `chatindex`: "'{{chatindex}}' 대신 '{{episode}}'를 쓰세요. 그대로 보냈어요." (정할 것 2 · 3)
  - 블록: "'{{#when}}' 조건 블록은 쓰지 않아요. 블록을 그대로 보냈어요."
  - `setvar` 무리: "'{{setvar}}'로는 값을 바꾸지 않아요. Canon 매크로는 값을 읽기만 해요."
  - 없는 스탯: "도현의 상태창에 '레벨'이 없어 그대로 보냈어요."
  - 앞쪽 블록: "메모 칸은 매 화 같은 앞쪽 블록이라 '{{episode}}'를 펼치지 않았어요." (정할 것 11)
  - 시점 인물 없음: "시점 인물이 없어 '{{char}}'에 주인공을 넣었어요." (정할 것 9)
  - 지운 스냅샷: "{n}화 직전 스냅샷이 없어 지금 상태창 값을 넣었어요." (정할 것 12)
- 화면 모양을 바꾸면 프롬프트 보기 대화상자의 `docs/design/` 문서를 함께 고친다. 시작 전에 확인할 것: 3번이 그 대화상자를 어느 컴포넌트 문서에 적었는지.

이야기 요소 화면:

- 설명 칸은 원문을 보이고 고친다. 이 일감은 미리 보기를 더하지 않는다.

명령줄:

- 새 명령이나 옵션은 없다. `brief` 출력이 펼친 글이 된다.

## 시험

- 새 시험 `tests/test_macros.py`:
  - 매크로가 없는 글은 `expand` 뒤에도 똑같다.
  - `{{user}}`: 역할에 '주인공'이 든 인물, 없으면 첫 주역으로 펼친다.
  - `{{char}}`: 이어진 인물이 있으면 그 인물, 없으면 시점 인물, 둘 다 없으면 주인공과 경고.
  - `{{getvar::인물.스탯}}`: id 와 이름 모두로 찾는다. 스탯 이름에 `.` 이 들어가도 맞는다. 없는 인물 · 스탯은 그대로 두고 경고한다.
  - `{{episode}}`: 이번 화 번호.
  - 대소문자를 가리지 않는다(`{{User}}`).
  - 모르는 함수와 `{{chatindex}}` 는 그대로 두고 경고한다.
  - `{{#when::...}}...{{/when}}` 은 안의 매크로까지 그대로 둔다.
  - `setvar` 무리는 상태를 바꾸지 않고 경고한다(`p.states` 가 그대로).
  - 겹친 매크로는 안쪽부터 펼친다. 펼친 값 속 `{{` 는 다시 펼치지 않는다.
  - `Meta.notes` 의 `{{episode}}` 는 펼치지 않고 경고한다. `static_context` 가 1화와 2화에서 같다.
  - 쓸 차례가 아닌 화는 `snapshot(n-1)` 의 값을 쓰고, 스냅샷이 없으면 지금 값과 경고를 낸다.
- 프롬프트 시험(`tests/test_serial.py` 또는 2번이 정한 시험 파일에 더함):
  - 펼친 글로 예산을 센다: 펼치면 길어지는 설명이 예산을 넘기면 펼친 길이로 잘린다.
  - 컨텍스트를 만든 뒤 저장한 `project.json` 이 바뀌지 않는다.
  - `episode_prompt` 와 `brief_parts(p, n, "episode")` 가 같은 펼친 글을 낸다.
  - 단편과 장편 모두에서 펼친다.
- 기본값 시험: 매크로를 쓰지 않은 작품의 집필 · 검수 · 상태 프롬프트가 지금과 글자 하나까지 같다. 프롬프트 스냅샷은 바뀌지 않아야 한다.
- 웹 시험: 프롬프트 보기 응답에 `MacroUse` 목록과 경고가 들어간다.
- 가짜 응답(`canon/mock.py`)은 바꾸지 않는다. LLM 응답 형식이 바뀌지 않는다.
- 고친 기능의 시험만 빠르게: `CANON_HOME=$(mktemp -d) python -m pytest -q tests/test_macros.py`.
- 전체 시험: `CANON_HOME=$(mktemp -d) python -m pytest -q -n auto tests`.
- 정적 검사: `ruff check canon tests scripts`.

## 확인하지 못할 것

- 그대로 남긴 매크로(모르는 함수, 블록)를 실제 Gemini 가 어떻게 읽는지는 키가 있을 때만 볼 수 있다.
- 서버 vocado-dev 의 실제 작품에 이미 `{{` 가 든 설명 · 메모가 있는지는 이 일감 안에서 볼 수 없다. 있으면 이 일감 뒤 그 작품의 프롬프트가 바뀐다.
- 매크로가 작가에게 쓸모 있는지(어떤 설명에 쓰는지)는 작가의 판단이다.
- RisuAI 의 `chatindex` 가 0 에서 시작하는 메시지 번호라는 것은 출처(파일 · 함수)를 확인하지 못했다(정할 것 3).
- CCv3 명세(SPEC_V3.md)가 CBS 이름을 대소문자 무시로 적었다는 것은 출처(절)를 확인하지 못했다(정할 것 16).

사용자가 할 단계:

1. 서버 vocado-dev 에서 `grep -l '{{' projects/*/project.json` 으로 이미 `{{` 를 쓴 작품이 있는지 본다(읽기만).
2. 정할 것 1~23 을 정한다.
3. 머지 뒤 이야기 요소 설명 하나에 `{{char}}` 와 `{{getvar::인물.스탯}}` 을 적고, 쓰기 화면의 프롬프트 보기에서 원문과 펼친 값을 본다.
4. 그 화를 실제 모델로 써 보고 펼친 값이 본문에 맞게 쓰였는지 본다.
