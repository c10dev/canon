# 06. 집필 화면에서 상태 변경안 훑고 고르기

상태: 끝 (#448) · 계획: [plan.md](../plan.md) 의 06번 · 먼저: —

## 목표

본문을 쓰고 검수를 마친 화에서, 집필 화면을 떠나지 않고 상태 변경안의 요지를 보고 고를 수 있다.
상태 승인 화면은 그대로 남는다. 자세히 보거나 고치려면 지금처럼 그 화면으로 간다.
README 관찰 차.

## 원칙

- 작가가 고르기 전에는 데이터에 반영하지 않는다(AGENTS.md '설계 원칙').
- 관계 수치는 AI 가 적지 않는다. 요약 카드도 사건만 보이고 수치는 `dynamics.py` 가 계산한 결과만 보인다.
- 인물 설정 바꾸기 제안은 요약 카드에서도 기본 체크하지 않는다.

## 정할 것

1. 요약 카드에 넣을 것 — 추천: 묶음별 줄 수와 한 줄 요지(요약, 인물 상태, 관계 사건, 복선, 사실, 설정 바꾸기). 묶음을 누르면 상태 승인 화면의 그 묶음으로 간다.
2. 카드에서 할 수 있는 것 — 추천: '추천대로 반영' 하나와 '상태 승인으로'. 추천대로 반영은 상태 승인 화면의 기본 체크를 그대로 반영하는 것과 같다.
   - 설정 바꾸기 제안이 있으면 '추천대로 반영' 옆에 '설정 바꾸기 n개는 반영하지 않아요' 를 적는다.
   - 검수 지적이 남아 있으면 카드를 접고 '검수 지적 n개가 남았어요' 를 먼저 보인다.
3. 카드 자리 — 추천: 집필 화면 단계 띠(집필 · 검수 · 상태 승인) 아래, 본문 위. 변경안이 생긴 화에서만 보인다.
4. 반영 뒤 — 추천: 지금 상태 승인 화면의 반영 뒤 동작(다음 화로, 반영 취소)을 같은 카드 자리에 보인다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/static/write.js` | 요약 카드 자리 |
| `canon/static/review.js` | 변경안 묶음 요약 함수(순수 함수로 빼서 두 화면이 쓴다), 기본 체크 그대로 반영하는 동작 |
| `canon/static/app.css` | 카드 |

- 서버 엔드포인트는 새로 만들지 않는다. 상태 승인 화면이 쓰는 반영 요청을 그대로 쓴다.

## 시험

- 요약 함수 JS 시험: 묶음별 수, 설정 바꾸기 제외 문구.
- '추천대로 반영' 이 상태 승인 화면에서 아무것도 바꾸지 않고 반영한 것과 같은 요청을 보내는지 보는 시험.
- `tests/` 의 상태 승인 화면 시험이 그대로 통과하는지.

## 문서

- `docs/modules/web.md` 의 `canon/static/write.js` · `canon/static/review.js` 절에 줄을 더한다.
- `docs/design/` 에 요약 카드 컴포넌트 문서를 더하거나 기존 카드 문서를 고친다.
- README.md 의 집필 흐름 설명을 고친다.

## 확인하지 못할 것

- 요약 한 줄로 충분히 판단되는지는 작가가 실제 화를 몇 개 반영해 보고 판단한다.
