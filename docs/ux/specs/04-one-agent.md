# 04. 대화 에이전트 하나로 합치기

상태: 04a 끝 (#433, 정할 것 7 고침은 #435) · 04b 끝 (#438) · 04c 끝 (#440) · 04d 끝 (#439) · 옛 대화 정리 남음 · 계획: [plan.md](../plan.md) 의 04a · 04b · 04c · 04d번 · 먼저: 04b · 04c · 04d 는 04a

## 목표

작품 안 어느 화면에서든 같은 대화 패널(대화 에이전트)이 열린다.
화면을 옮기면 패널은 그대로이고, 다듬을 곳(대상)만 그 화면에 맞게 바뀐다.
본문 고치기, 설정 다듬기, 문체 다듬기도 이 에이전트에게 말로 시킨다.
README 관찰 사 · 아. README 의 정한 규칙 2026-11-09(대화를 단기에 하나로 합친다).

## 지금 동작 (2026-11-09 확인)

- 대화 주제는 넷이다: `plot`(대화 에이전트, `canon/agent.py`, 작업으로 돌고 단계 · 승인 카드가 있다), `setup`(`setupchat.py`), `style`, `text:<화>`(부분 고치기).
- `plot` 밖의 셋은 `POST /api/projects/{name}/chat/{topic}` 하나가 동기로 AI 를 부르고 변경안을 대화 기록에 남긴다(`web.py` `chat_send`). 작가가 `apply` 로 고른 것만 반영한다.
  - `text:<화>`: `pipeline.revise_passage` → `record_passage`, 후보 2~3개.
  - `style`: `pipeline.revise_style` → `record_style_chat`.
  - `setup`: `pipeline.revise_setup` → `setupchat.record`.
- 에이전트 세션(`schema.AgentSession`)은 이미 `topic` 칸이 있고 주제마다 세션 목록을 둔다(`agent.sessions(p, topic)`).
- 에이전트 권한 모드는 셋이다: 물어보기, 빈 곳 · 초안만 자동, 모두 자동(`agent.MODE_LABELS`). 쓰기 종류는 `agent.KIND_LABELS` 다.
- 패널을 그리는 화면은 플롯 · 설정 도우미 · 문체 · 집필(검수 · 상태 승인 포함) 넷이다. 그 밖의 화면은 패널을 그리지 않는다.

## 정할 것

1. 새 도구의 권한 — 정함(2026-11-09, 사용자): 04b~04d 의 세 도구는 권한 모드와 상관없이 늘 카드로 묻는다(`RENUMBER_TOOLS` 처럼). 작가가 카드에서 골라야 들어간다.
   - 근거: 지금 세 대화도 작가가 `apply` 로 골라야 반영한다. 합치면서 더 느슨해지지 않는다.
   - '이 세션에서 묻지 않기'(`auto_kinds`)는 이 세 종류에 열지 않는다(2026-11-09 사용자 결정: 늘 카드로 묻기).
2. 화면이 주는 기본 대상 — 정함(2026-11-09, 사용자): 대상 칸(`AgentSession.target`)에 새 값을 더한다: `text:N`(집필 · 검수 · 상태 승인), `setup`(설정 도우미), `style`(문체), 그 밖의 화면은 '' (작품 전체).
   - 화면을 옮기면 패널 아래 상태 줄의 대상이 바뀌고, 한 번 강조한다. 작가가 대상을 고정(핀)하면 화면을 옮겨도 바꾸지 않는다.
   - `pipeline.chat_session_target` · `chat_target` 이 새 값을 받게 한다.
3. 본문 고치기의 고른 부분 — 정함(2026-11-09, 사용자): 집필 화면에서 본문을 드래그하면 고른 부분이 입력 상자 위 '재료' 칩으로 붙는다(`agent.js` 의 '+ 재료'). 지금 빠른 요청(더 길게 · 더 짧게 · 대사 늘리기 · 묘사 살리기)은 `/` 빠른 요청(`AGENT_CMDS`)으로 옮긴다.
4. 짧은 요청의 비용과 시간 — 정함(2026-11-09, 사용자): 빠른 요청과 재료가 붙은 요청은 에이전트 단계를 건너뛰고 바로 그 도구를 부른다(지름길). 지름길은 AI 호출 한 번이라 지금 대화와 비용이 같다.
   - 지름길이 없으면 '더 짧게' 하나에도 에이전트 단계 호출 + 도구 호출로 두 번 이상 부른다.
5. 세션 목록 — 정함(2026-11-09, 사용자): 작품 하나에 세션 목록 하나. 새 세션의 `topic` 은 `"agent"` 로 두고, 옛 `plot` 세션도 같은 목록에 보인다. `topic` 값은 지우지 않는다(옛 `project.json` 읽기).
6. 옛 대화 기록 — 정함(2026-11-09, 사용자): `setup` · `style` · `text:N` 의 옛 기록은 세션 목록 아래 '이전 대화'에서 읽기만 한다(옛 `Project.chats` 를 보이는 지금 방식과 같다). 적용 취소(undo)는 지금 엔드포인트를 남겨 계속 쓸 수 있다.
7. 플롯 화면이 아닌 곳에서 플롯 도구 — 정함(2026-11-09, 사용자): 쓸 수 있다. 다만 플롯 화면이 아닌 곳에서는 대상이 '' (작품 전체)여도 플롯 쓰기를 모두 '다듬을 곳 밖'(`outside`)으로 보고 승인 카드로 묻는다.
   - '빈 곳 · 초안만 자동' · '모두 자동' 에서도 묻는다. '이 세션에서 묻지 않기' 는 지금 `outside` 종류와 같다.
   - 플롯 화면(구간 · 아크 · 화 플롯)은 지금 동작 그대로다. 단편이 '' 를 보내는 경우도 같다.
   - 그래서 턴에 지금 화면을 실어 보낸다. 서버는 알려진 화면 목록으로 확인하고, 값이 없거나 모르면 플롯 화면과 같게 다룬다.
   - 2026-11-09 #433 첫 구현은 '' 일 때 묻지 않았다. 사용자가 묻는 쪽으로 정해 같은 PR 에서 고친다.

## 규칙

- 본문이 있는 화의 플롯 · 상태, 관계 수치, 인물 설정 바꾸기 반영, 지우기는 어느 모드에서도 AI 가 하지 않는다(AGENTS.md). 04c 의 설정 도구는 인물 설정 바꾸기를 제안 카드로만 낸다.
- 사용자가 입력한 설정은 AI 제안이 덮지 않는다. 04c 카드는 지금 `setupchat` 의 칸별 비교를 그대로 쓴다.
- 본문 넣기는 지금처럼 수정 기록에 남아 되돌릴 수 있다(`passage.js` 의 '되돌리기').
- 쓰기마다 전 · 뒤 값을 남겨 되돌릴 수 있게 하는 에이전트 규칙을 새 도구도 따른다.
- 자동 집필 중에도 에이전트 패널은 쓸 수 있다. 자동 집필이 맡은 화(`Job.owned`)를 고치는 도구는 지금처럼 막는다.
