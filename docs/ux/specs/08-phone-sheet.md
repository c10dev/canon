# 08. 휴대폰 대화 시트가 화면을 덮지 않게

상태: 끝 (#432) · 계획: [plan.md](../plan.md) 의 08번 · 먼저: 04a

## 목표

900px 이하에서 화면을 열거나 옮겼을 때 대화 시트가 저절로 크게 뜨지 않는다.
시트는 작가가 열 때만 연다.
README 관찰 타.

## 지금 동작 (2026-11-09 확인)

- 열기 상태 `S.chatOpen` 을 localStorage `canon.chat` 에 기억한다(`chat.js`).
- 390px 에서 상태 승인 화면을 다시 열면 앞서 열어 둔 'AI에게 고치기' 시트가 화면의 약 60%를 덮었다.
- 상태 승인 화면은 본문을 고치는 화면이 아닌데 `write.js` 가 본문 고치기 대화(`text:<화>`)를 붙인다.

## 정할 것

1. 기억 — 추천: 900px 이하에서는 열기 상태를 기억하지 않는다. 화면을 새로 열면 닫힌 채로 시작한다. 901px 이상은 지금처럼 기억한다.
2. 화면을 옮길 때 — 추천: 900px 이하에서 다른 화면으로 옮기면 시트를 닫는다. 뒤로 가기가 시트만 닫는 지금 규칙(`panelOn` · `panelOff`)은 그대로다.
3. 닫힌 시트의 입구 — 추천: 대화가 있는 화면에서는 화면 아래 한 줄 높이의 '대화 열기' 띠를 둔다. 새 답이 있으면 띠에 점을 단다.
4. 상태 승인 화면의 대화 — 추천: 휴대폰에서는 닫힌 띠도 두지 않는다. 작가가 메뉴에서 대화를 열면 일감 04a 의 에이전트 패널이 열리고, 대상은 그 화의 본문이다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/static/chat.js` | 열기 상태 기억 조건, 화면 옮길 때 닫기, 닫힌 띠 |
| `canon/static/write.js` | 휴대폰 상태 승인 화면에서 닫힌 띠를 두지 않음 |
| `canon/static/app.css` | 닫힌 띠 |

## 시험

- `tests/test_chat_js.py`: 900px 이하에서 열기 상태를 읽지 않는지, 화면을 옮기면 닫는지.
- 브라우저 확인: 390px 에서 집필에서 시트를 열고 상태 승인으로 옮긴 뒤 새로 고쳐 시트가 닫혀 있는지.

## 확인하지 못할 것

- 실제 휴대폰(iOS Safari · Android Chrome)의 키보드 · 주소창 높이 변화는 사용자가 실기기에서 본다.
  1. 휴대폰으로 Canon 집필 화면을 연다.
  2. 대화 열기 띠를 눌러 시트를 열고 입력칸을 누른다.
  3. 키보드가 열려도 입력칸과 보내기 버튼이 보이는지 본다.
