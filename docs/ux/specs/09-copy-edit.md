## 목표

화면이 자기 작동법을 설명하는 문장이 줄어든다.
개념 하나에 설명은 한 번, 한 곳에만 남는다.
작가는 내부 용어 대신 자기가 얻는 것을 읽는다.
README 관찰 파 · 하. 동작은 바뀌지 않는다(문구만).

## 지금 (2026-11-09, 데모 작품)

- 집필 화면 한 곳에 "드래그하거나 길게 눌러 고르기" 안내가 네 번 나온다: 본문 칸 위(`write.js`), 삽화(`illust.js`), 대화 패널 소개(`passage.js` 의 `intro`), 입력칸 위.
- '~요.' 로 끝나는 안내 문장: 설정 도우미 29개, 문체 레퍼런스 26개.
- 내부 용어와 규칙이 문장에 나온다: "스타일 프로필에서 바꿀 칸", "기준보다 30% 넘게 길면 경고해요", "정착 문체", "원문 빈도".

## 정할 것

1. 남길 자리 — 추천: 설명은 셋 중 한 곳에만 둔다.
   - 빈 상태(그 칸에 아직 아무것도 없을 때 한 번 보이는 글)
   - 입력칸 안 예시 글(placeholder)
   - 물음표 툴팁(필요할 때 누르면 보이는 글)
   - 늘 보이는 설명 줄(`p.small` · 칸 아래 설명)은 '이걸 모르면 잘못 쓴다' 인 것만 남긴다.
2. 내부 용어 — 추천: 작가에게 보이는 이름 목록을 만들고, 목록에 없는 말은 화면에 쓰지 않는다. 예: '스타일 프로필' → '문체', '정착 문체' → '이 작품이 굳힌 문체'(이름은 사용자와 정한다).
3. 숫자 규칙 — 추천: "30% 넘게" 같은 판정 기준은 툴팁으로 옮긴다. 늘 보이는 글에는 무엇을 알려 주는지만 쓴다("문장이 길게 늘어지면 알려요").
4. 편집 범위 — 추천: 사용 빈도가 높은 다섯 화면부터: 집필, 설정 도우미, 문체 레퍼런스, 기승전결 · 플롯, 작품 홈. 대화 패널 소개 글은 04 가 패널을 합칠 때 함께 쓴다.
5. 세는 방법 — 추천: 화면별 늘 보이는 안내 문장 수를 세는 작은 스크립트(Playwright, mock)를 `scripts/` 에 두고 고치기 전후를 견준다. 목표는 화면마다 절반 이하.

## 바꿀 곳

| 파일 | 바꿀 것 |

| `scripts/` | 안내 문장 세기 스크립트 |

## 규칙

- 해요체, 단계 이름, '반영' · '적용' 구분 같은 지금 문구 규칙은 그대로다.
- 문구를 지우면서 동작을 바꾸지 않는다. 위험한 동작의 확인 문구(반영 취소, 지우기)는 줄이지 않는다.
- 화면 문구를 보는 시험(문구 문자열을 찾는 JS 시험)이 깨지면 시험을 새 문구로 고친다.
