# 04. OSM 빈 블록 채우기

상태: 구현 · 계획: [plan.md](../plan.md) 의 4번

## 목표

OpenStreetMap 에 건물이 덜 그려진 주택가에서 빈 블록을 지은 건물로 채운다. 작가는 텅 빈 동네 대신 집이 들어선 동네를 보고, 장소를 놓을 건물을 얻는다.
2026-10-28 시험에서 망원동은 길은 다 있었지만 빌라촌 건물이 많이 비어 있었다(DESIGN.md '실제 지도' 절).

## 정할 것

다섯 모두 추천대로 구현했다(2026-10-28, 사용자가 추천대로 진행하라고 했다). 다르게 한 곳은 아래 '구현 메모'.

1. 빈 블록 기준 — 추천: 길로 둘러싸인 블록 가운데 건물이 덮은 넓이가 블록 넓이의 10% 아래이고, 물 · 녹지 · 광장 · 밭이 절반을 넘지 않는 블록.
2. 채우는 규칙 — 추천: 현대 동네 생성기의 빌라촌 규칙(필지 쪼개기 → 필지마다 빌라 한 채). 블록이 크면(예: 한 변 150m 넘음) 아파트 단지 규칙.
3. 언제 채우나 — 추천: 기본은 채우지 않는다. 지도 데이터 칸의 '빈 블록 채우기' 버튼으로 미리 보고 적용한다. 다시 누르면 지운다.
4. 지은 건물 표시 — 추천: 화면에서 흐린 색과 점선 테두리, 건물 메뉴에 '지은 건물(OpenStreetMap 에 없음)'. 이름 · 주소 · 입점은 짓지 않는다(실제 지도 규칙). 쓰임 · 층수 · 사람 수만.
5. 출처 글 — 추천: '© OpenStreetMap 기여자 · 빈 블록 건물은 Canon 이 지음'.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/blocks.py` (01) | 길 선으로 블록 다각형 찾기(평면 그래프의 면). 01 에서 옮긴 필지 쪼개기 재사용 |
| `canon/osm.py` 또는 새 `canon/fill.py` | `fill(layout, seed) -> layout`: 빈 블록을 찾아 건물 · `parts` 를 더한다 |
| `canon/bldgs.py` | `parts[i].made` 인 건물은 이름 · 주소 · 입점을 비운다 |
| `canon/atlas.py`, `canon/web.py` | 미리보기 · 적용 · 지우기 (`POST /atlas/layout/fill`). 적용하면 지도 파일을 다시 쓰고 고친 건물 번호를 지킨다(지은 건물은 뒤에 붙인다) |
| `canon/static/atlas.js` (03 뒤면 `atlas-gen.js` 근처) | 버튼, 미리보기, 지은 건물 그리기 |
| `Atlas` (`schema.py`) | 채운 입력 `fill: {seed, rule}` (지울 때와 다시 만들 때) |

## 지도 데이터

- 새 키: `parts[i].made: true`(지은 건물). [layout.md](../layout.md) 에 더한다.
- `buildings` 끝에 붙이므로 OSM 건물 번호(작가가 고친 건물 `Atlas.buildings`)는 바뀌지 않는다.
- 같은 지도 · 같은 시드면 같은 결과.

## 규칙

- 블록 찾기: `roads` 선을 꼭짓점으로 나눈 평면 그래프에서 가장 작은 면들. 지도 테두리에 걸린 면은 테두리로 자른다.
- 길 폭의 절반 + 2m 를 블록 안쪽으로 물려 필지를 둔다.
- 기존 건물과 겹치는 필지는 버린다.

## 화면 · 명령줄 · 프롬프트

화면 문구 예: '빈 블록 12곳에 건물 240채를 지어 채웠어요. OpenStreetMap 에 없는 건물이에요.' 명령줄 `map <작품> fill`. 프롬프트는 바꾸지 않는다(지은 건물에는 이름이 없어 건물 한 줄이 짧다).

## 시험

- 작은 OSM 시험 데이터(`tests/test_osm.py` 의 `_xml` 꼴)에 빈 블록 하나: 채운 뒤 건물 수, `made`, 고친 건물 번호 유지, 같은 시드 같은 결과.
- 지은 건물이 `find_spots`(#140) 후보에 이름으로 걸리지 않는다.
- 실제 망원동 파일로 화면 확인(시험 데이터는 저장소에 넣지 않는다).

## 구현 메모 (2026-10-28)

명세서와 다르게 하거나 명세서에 없던 것을 정한 곳이다.

- 채우는 규칙: OSM 블록은 볼록 다각형이 아니라서 `moderngen` 의 블록 자르기(`_divide` · `_lots`, 볼록 다각형 `blocks.cut`)를 그대로 쓰지 못했다. `fill.py` 가 `moderngen.DIVIDE["villa"]` 의 필지 앞 폭 · 깊이와 같은 단독주택 비율 · 층수를 쓰고, 블록 변마다 필지 직사각형을 늘어놓은 뒤 블록 안 · 길 · 건물 · 물과 녹지를 하나씩 확인한다. `moderngen` 은 고치지 않았다(스냅샷 · `VERSION` 그대로).
- 아파트 단지 규칙은 '블록 한 변'을 블록 가장 긴 변 방향과 그 법선 방향의 폭 가운데 큰 쪽으로 쟀다. 판상 동이 하나도 들어가지 않으면 빌라촌 규칙으로 채운다.
- 쓰임은 빌라 · 단독주택 · 아파트뿐이다. `moderngen` 빌라촌의 모퉁이 가게 · 대로변 상가는 짓지 않는다(실제 지도에 없는 가게가 생긴다).
- 지은 건물은 이름 · 주소 · 입점에 더해 앞길(`street` · `no`)도 두지 않는다. 쓰임 · 층수 · 사람 수만.
- 빈 블록 넓이는 다각형 겹침 대신 블록 안 격자 점(약 400개)으로 잰다. 400m² 보다 작거나 25만m² 보다 큰 블록은 보지 않는다. 강 가운데 선(`rivers`)도 블록 경계로 본다.
- 엔드포인트는 `POST /atlas/layout/fill` 하나에 `mode`(preview · apply · clear)와 `seed` 를 받는다. 미리보기는 채울 블록과 지을 건물 다각형만 돌려주고 저장하지 않는다. 화면의 미리보기 · '다른 모양'은 누를 때마다 새 시드를 뽑는다.
- 큰길 블록 건너뛰기(사용자 결정, 2026-10-28): 둘레 길이 모두 폭 15m(`fill.WIDE`) 이상인 블록은 채우지 않는다. 폭은 필지를 물릴 때 쓰는 값(`_Site.width_at`: 블록 변 가운데에서 1m 안의 가장 넓은 길)이고 지도 테두리 변은 세지 않는다. 강남 파일(시드 1)의 숫자는 바뀌지 않았다(채운 블록 6곳 · 건물 21채). 모퉁이 블록 둘레에 보도(footway 2m)와 연결로(5.3 · 8.6m)가 그려져 있어서다. 둘레 길이의 절반 이상이 15m 넘는 길 가운데 선에서 30m 안인 블록을 건너뛰면 강남 모퉁이 3곳이 빠지고 망원동 63곳은 그대로였다(잰 값, 코드에는 넣지 않음).
