# 13. 화풍을 따라가는 동선 · 핀

상태: 구현 · 계획: [plan.md](../plan.md) 의 13번 · 근거: [research-look.md](../research-look.md) 의 P3 · W4 · W5

## 목표

인물 동선과 핀이 화풍에 맞는 색 · 무늬로 그려지고, 길 색과 섞이지 않으며, 어느 방향 · 어느 화 순서로 옮겼는지 보인다. 지도 데이터는 바뀌지 않는다.

## 정할 것

1. 흑백 인쇄에서 인물 나누기 — 추천: 모두 검정 계열에 인물마다 다른 점선 무늬(`stroke-dasharray` 열 가지).
2. 화 번호 점 — 추천: 장소를 갈아탄 곳마다 작은 원 안에 화 번호. 배율이 낮아 겹치면 처음 · 끝만 남긴다.

## 바꿀 곳

| 파일 | 바꿀 것 |
|---|---|
| `canon/static/atlas.js` | `ATLAS_COLORS`(`atlas.js:61`) · `atlasColor`(`atlas.js:495`)를 화풍별 CSS 변수(`--v-ink0` … `--v-ink9`)로, 동선(`atlas.js:592`)에 바깥 테두리(halo) · 방향 화살표(`<marker>` 를 `defs` 에) · 화 번호 점, `.at-trail`(`atlas.js:1923`)의 `opacity .6` 을 불투명으로 바꾸고 굵기를 키움, 옆 칸 인물 견본(`.at-who i`)도 같은 색 · 무늬 |
| `canon/static/atlas-export.js` | 내보내기가 `marker-*` · `stroke-dasharray` 를 속성으로 옮겨 적는지 확인하고 빠지면 더한다 |

## 지도 데이터

바뀌지 않는다. 동선은 `frames` · `row.route`(서버 응답)를 읽는다.

## 규칙

- 화풍별 잉크: 기본은 지금 열 색, 양피지는 적갈 · 남색 · 먹색 같은 잉크 열 색, 밤은 밝은 색, 흑백 인쇄는 검정 + 무늬.
- 같은 길을 가는 두 인물은 지금처럼 옆으로 조금 비켜 그린다(`off`).
- 화살표 · 화 번호 점은 배율이 낮으면 줄인다(도시 동선이 지저분하지 않게).

## 화면 · 명령줄 · 프롬프트

화면 문구는 바뀌지 않는다.

## 시험

- node 시험: 화 번호 점 고르기(겹치면 처음 · 끝만), 화풍별 잉크 이름 순서.
- 브라우저: 강남 · 마을 지도의 동선을 화풍 4종으로 보고 research-look.md 의 `*-print.png` · `zoom-gangnam.png` 와 견준다.
- SVG · PNG 내보내기에 화살표 · 점선이 나오는지 본다.

## 문서

DESIGN.md 지도 화면 줄, README.md '지도 다루기' 줄, [plan.md](../plan.md) 상태.

## 확인하지 못할 것

잉크 색이 보기 좋은지는 사용자 취향 판단이다. 스크린샷을 보내 확인받는다.

## 구현 메모

2026-10-29 구현.

- 잉크: `ATLAS_COLORS` 를 지우고 색을 화풍 CSS 변수 `--v-ink0`…`--v-ink9` 로 옮겼다. 기본은 옛 열 색 그대로, 양피지는 적갈 · 남색 · 먹색 · 녹청 · 연지 같은 잉크 색, 밤은 밝은 색, 흑백 인쇄는 검정(#000) 다섯 · 짙은 회색(#333) 다섯이다. 인물 차례 → 변수 이름 · 무늬는 `atlasInk(i, 화풍)` 이 고른다. 화풍은 마을 그림에만 걸리므로 배경 그림 · 모눈 지도는 기본 잉크다(`atlasInkStyle`).
- 무늬: 흑백 인쇄만 `ATLAS_DASHES` 열 가지(첫 인물은 실선)를 쓴다. 무늬 길이는 화면 px 이라 1/배율과 선 굵기를 곱해 속성으로 적는다. CSS 변수로 두면 확대할수록 무늬가 길어져서다. 점선은 끝을 둥글리지 않는다(`butt`).
- 동선: 불투명, 굵기 3 → 4(굵게 보기 5 → 6), 흑백 인쇄는 화풍 선 굵기 배율(`lw` 1.8)의 제곱근만큼 더 굵다. 바깥 테두리(`--v-halo`: 기본 `--surface`, 양피지 종이색, 밤 짙은 남색, 흑백 흰색)를 모든 인물 선보다 먼저 한 겹으로 그려, 한 인물의 테두리가 옆 인물의 선을 덮지 않는다. 비켜 그리기(`off`)는 그대로다.
- 화살표: `marker-mid` 를 길 전체에 달면 OSM 길 꺾임마다 화살표가 붙어, 갈아탄 두 장소 사이 길 가운데에 하나씩만 단다. 그 자리에 아주 짧은 선을 긋고 `marker-end` 로 인물 잉크마다 하나인 `<marker>` 를 단다. 화살표 길이의 네 배보다 짧은 길에는 넣지 않는다.
- 화 번호 점: 장소를 갈아탄 곳마다 점을 두되, 장소 핀을 가리지 않게 도착하는 길 위로 핀 바깥까지 물러 놓는다(처음 점은 떠나는 길 위). 시작(0화) 점은 숫자 없이 칠한다. 겹: 장소 핀 위, 이름표 아래. 이름표 놓는 차례(README 2026-10-29)를 바꾸지 않으려고 점 상자는 `taken` 에 넣지 않는다.
- 명세와 다르게 한 곳: 겹친 점 빼기(`atlasTrailDots`)는 '겹치면 처음 · 끝만'을 한 번에 하지 않고, 처음 · 끝은 늘 남기고 가운데 점은 이미 남긴 점(다른 인물 것도)과 겹치지 않을 때만 앞에서부터 남긴다. 다 겹치면 처음 · 끝만 남아 명세와 같다. 한 번에 하면 같은 장소에 같은 길로 두 번 온 인물(집 → 학교 → 집)은 어느 배율에서도 가운데 점이 모두 사라져서다. 처음과 끝이 겹치면 끝만 남긴다.
- 명세에 없던 것: 인물을 굵게 보면 그 인물의 화 번호 점만 그린다. 여러 인물이 같은 길로 같은 장소에 오면 점이 겹쳐 하나만 남기 때문에, 한 사람의 화 순서는 굵게 보기로 본다.
- 크기: 화살표 14 · 점 반지름 7(화면 px)에 `atlasMarkScale` 을 곱한다: 배율 1.5 아래 0.75, 3 아래 0.9, 그 위 1.
- 옆 칸 · 표: 인물 견본 `<i>` 동그라미를 같은 색 · 무늬의 짧은 선(`atlasSwatch`, 작은 SVG)으로 바꿨다. 지도 밖이라 견본에 같은 화풍 class(`at-sw st-*`)를 달아 같은 변수를 읽는다. 인물 표 글자는 `--v-ink-text`(밤만 짙은 색)다.
- 내보내기: 화살표 `marker-end` 는 속성이라 그대로 남고, 점선은 이미 옮겨 적던 `stroke-dasharray` 로 나온다. 고친 곳은 하나다: 요소마다 계산된 값을 읽고 바로 class 를 지우던 탓에 '.at-tok text' 처럼 부모 class 로 고르는 규칙이 자식에서 빠졌다(인물 표 글자가 검정, 테두리 없음). 모두 먼저 읽은 뒤 적게 고쳤다. 내보낼 때 잠깐 만드는 사본의 화살표 id 는 `at-arwx` 라 화면 지도의 `<marker>` 를 집지 않는다.
- 남은 한계: 화 번호 점은 이름표 상자에 들지 않아 장소 이름표 · 인물 표 밑에 가릴 수 있다. 흑백 인쇄의 점선은 굵은 길 테두리 옆에서 철길처럼 보일 수 있다. 잉크 색이 보기 좋은지는 사용자가 판단한다.
- 확인: node 시험(`tests/test_atlas_js.py`: 잉크 차례 · 흑백 무늬 열 가지, 화풍마다 잉크 변수 열 개, 점 고르기(떨어지면 모두 · 겹치면 처음 · 끝 · 다른 인물과 겹친 가운데 점), 화살표 · 점 자리, 배율이 낮으면 작아짐). mock 서버에서 마을 생성기 지도와 OSM 강남(배율 1 · 4)을 화풍 4종으로 고치기 전 · 뒤 찍었고, SVG · PNG 내보내기에 화살표 · 점선 · 테두리 · 화 번호 점 · 인물 표 글자가 나온다.
